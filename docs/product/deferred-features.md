# 삭제 기능과 후속 검토

기준일: 2026-11-01. 현재 기능을 다시 늘리는 작업 목록이 아니라, 삭제 이유와 선택적 후속 검토의 정본이다.
상위 진입점은 [구현 계획](plan.md)이며, 제품 의도는 [intent.md](../../intent.md)를 따른다.

## 관리 규칙

- 식별자 `DF-001`부터 유지한다. 구현을 검토할 때 새 문서를 만들지 말고 해당 항목의 상태와 근거를 갱신한다.
- 상태는 `삭제`, `후속 검토`, `구현 중`, `구현`으로 구분한다. 후속 검토는 구현 승인이나 일정 약속이 아니다.
- 재도입하려면 실제 사용자 문제, 가장 작은 범위, 기존 흐름과의 통합 방법, 검증 결과를 해당 항목에 남긴다.
- 별도 관리 화면·병렬 API·호환 모드를 먼저 만들지 않는다. 현재 사용자에게 완료할 수 없는 선택지를 노출하지 않는다.
- 기존 DB나 비공개 설정을 지우지 않는다. 제품에서 제거한 코드와 기존 자료의 보존은 별개다.

| --- | --- | --- | --- |
| DF-001 | 독립 메모·문서 보관소 | 삭제 | 독립 메모장은 재도입하지 않음 |
| DF-002 | 구형 context 생성과 실제 앱의 stateless API | 삭제 | 병렬 생성·분석·작성 경로는 재도입하지 않음 |
| DF-003 | 사용자 세션 표시와 수동 로그아웃 | 삭제 | 사용자 인증이 실제로 필요해질 때 별도 검토 |
| DF-004 | 프로젝트·수신처 사전 등록과 운영자 카탈로그 설정 | 삭제 | 반복 입력 부담이 확인될 때만 입력 보조 검토 |
| DF-005 | DocAST JSON 직접 편집 | 후속 검토 | 일반 문장·문단 편집이 유용할 때 검토 |
| DF-006 | 화면에서 실행할 수 없는 재현 목표 | 후속 검토 | 실제 재현 job과 파일 검토가 연결된 뒤 검토 |
| DF-007 | 별도 규칙 관리·판본 편집·중복 실행 정보 화면 | 후속 검토 | 핵심 작업 안의 최소 재사용 동작만 검토 |
| DF-008 | 분석·범위 축소·확정·삭제의 중복 확인 UI | 삭제 | 같은 결정을 다시 묻는 체크·입력은 재도입하지 않음 |

## DF-001 독립 메모·문서 보관소

공개 결정이나 확정 파일과 연결되지 않는 메모장이 별도 UI·API·저장·조회 상태를 만들었다.
실제 앱에서 화면, 자동 조회, `/api/documents`와 저장소 초기화를 제거했다.
가상 녹화에 필요한 저장·조회 연출은 fake-app 전용 HTTP 모듈로 분리했다. 기존 DB의 documents 테이블은 삭제하지 않는다.

재도입하지 않는다. 공유 결과 보관이 필요하면 작업의 확정 산출물과 다운로드 경로 안에서 먼저 검토한다.
관련: [실제 HTTP 진입점](../../packages/server/src/app.ts), [가상 시연 HTTP](../../packages/fake-app/src/legacy-app.ts).

## DF-002 병렬 작업 생성·분석·작성 경로

정상 intake와 다른 저장 상태를 만드는 context 생성 경로를 제거했다.
실제 앱의 `/api/analysis`, `/api/sharing`도 제거하고 작업 revision에 연결된 v1 경로만 사용한다.
가상 시연은 fake-app에서 별도 처리한다. 새 별칭이나 호환 API를 제품에 추가하지 않는다.
관련: [작업 HTTP](../../packages/server/src/workflow-http.ts), [작업 라우트](../../packages/server/src/workflow-routes.ts).

## DF-003 사용자 세션 관리

자동 연결인데도 세션 닫힘을 표시하거나 사용하지 않는 로그아웃 API를 유지하던 잔재를 제거했다.
내부 쿠키·CSRF·정확한 Host/Origin 검사는 요청 무결성을 위해 유지한다. 로그인 기능으로 설명하지 않는다.
다중 사용자 식별이나 실제 운영 인증이 필요해질 때 별도로 요구사항을 정의하며, 시작 토큰 절차를 복구하지 않는다.
관련: [연결 상태](../../packages/client/src/ui/hooks/useSession.ts), [요청 경계](../../packages/server/src/workflow-session.ts).

## DF-004 사전 등록 카탈로그

프로젝트·수신처를 운영자 JSON에 미리 등록해야 자료 처리를 시작할 수 있던 의존성을 제거했다.
기존 작업 입력의 목적과 수신처는 유지하고, 별도 프로젝트 관리 UI·목록·등록 설정은 제공하지 않는다.
목적·언어·파일 제한 등 서버가 제공하는 선택 정보는 유지한다. 내부 workspace 범위는 운영상의 실제 프로젝트 등록이 아니다.

후속으로 자주 쓰는 수신처 입력 보조를 검토할 수 있다. 재도입 조건은 실제 반복 입력 부담이며 별도 관리 제품으로 확대하지 않는다.
관련: [입력 검증](../../packages/server/src/workflow-catalog.ts), [작업 화면](../../packages/client/src/ui/TaskSection.tsx).

## DF-005 사람이 읽는 초안 편집

사용자에게 JSON 문법과 fact_ids를 관리하게 하던 편집 UI·상태·HTTP 경로를 제거했다.
현재는 공개 결정을 수정한 뒤 초안을 다시 작성하고 검토한다. 자유 문서 편집은 현재 지원 기능으로 표시하지 않는다.

후속 편집은 문장·문단 단위로 검토한다. 근거 연결, 미승인 내용 거부, 수정 후 재검토, 확정 바이트 무효화를
제품이 책임져야 하며 JSON 입력창이나 검증 우회 기능을 다시 추가하지 않는다.
관련: [초안 화면](../../packages/client/src/ui/DraftSection.tsx), [파일 검토·확정](../../packages/server/src/artifact-store.ts).

## DF-006 재현 목표

실행 job이 없는 화면에서 reproduction_evidence를 고르게 하던 선택지를 제거했다.
Docker 실행기·고정 oracle·합성 입력의 코어 기능과 개발용 CLI는 유지한다.

재도입 조건은 실행 시작·취소·결과 연결·현재 파일 검토까지 한 작업 revision으로 완료되는 흐름이다.
실제 실행 검증과 UI 연출을 구분하고, 연결 전까지 선택지나 성공 표시를 복구하지 않는다.
관련: [재현 기능 설계](../features/08-reproduction.md), [실행기](../../packages/sandbox-runner/src/index.ts).

## DF-007 관리 화면 확장

규칙 별도 관리 화면과 판본·만료 편집, 중복 실행 정보 조회 화면을 제거했다.
결정 재사용의 코어 계약·기존 참조 무결성·기본 저장/적용/철회 경로는 보존한다.
현재 UI에서 규칙 저장을 권유하거나 관리 메뉴를 표시하지 않는다. 모델 연결 상태는 상단 표시로 모은다.

후속 검토는 현재 작업의 공개 결정 저장과 다음 작업에 대한 명시 적용으로 제한한다.
실제 사용이 확인되기 전에는 판본 관리·만료 관리·전용 대시보드를 만들지 않는다.
관련: [결정 재사용 코어](../../packages/server/src/rule-store.ts), [작업 이력](../../packages/client/src/ui/TaskHistory.tsx).

## DF-008 중복 확인 UI

분석 전송 동의, 필수 정보 제외 후 별도 범위 축소 동의, 파일 확정 전 확인 체크,
삭제 시 DELETE 입력과 규칙 보존 확인을 제거했다. 사용자가 선택하고 해당 버튼으로 실행한다.
실제 파일 검토와 공개 범위 결정, 삭제 결과 안내는 유지한다.
서버의 형식적인 삭제·확정 확인 필드도 제거했다. 판본·파일·공개 결정 검증은 유지한다.
관련: [현재 API](../design/api.md), [분석 화면](../../packages/client/src/ui/TaskSection.tsx).
