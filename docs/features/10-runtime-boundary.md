# F10 / 내부 실행과 접근 경계

등급: P0 core / 담당: 기반/운영 담당 / 의존: 없음 / 모든 기능의 선행 계약

기준: [PRD](../prd.md) PRD-03/06/08/12, [spec](../spec.md), [보안 경계](../security.md), [API](../api.md). 회사별 설치형 오픈소스, 한 사용자, 지정 사내 LLM을 전제로 한다. 실제 LLM/회사 정책 확인이 없어도 가상 자료와 fixture 모드로 개발을 시작할 수 있다.

실행 시 앱과 live evaluator가 현재 디렉터리의 `.env`를 자동으로 읽는다. 기존 프로세스 환경 변수가 우선하며 `.env`는 선택 사항이다. config.json에는 환경 변수 이름만 두고 값은 환경 변수 또는 Git에서 제외한 `.env`에서 받는다. endpoint의 스킴/HTTP 허용/모델 ID 등 설정 오류는 값 노출 없이 원인 필드로 구분한다.

## 1. 목적

**회사 원자료를 정리하는 작업을 지정한 내부 환경에서 수행하고, 사용자가 확인한 결과만 복사/저장할 수 있게 한다.** 원문을 읽는 모델이 외부 발송 권한까지 갖지 않도록 실행 경로를 제한한다. 오픈소스라는 배포 형태 자체를 보안 보장으로 쓰지 않는다.

## 2. 쓰는 사람과 권한

| 주체 | 할 수 있는 일 | 할 수 없는 일 |
| --- | --- | --- |
| 로컬 사용자 | 접속/자료/결정/확정/복사/다운로드/작업 삭제 | hard check 우회 |
| 운영/설치 담당자 | endpoint/비밀 환경변수/도구/팩 설치 설정 | 사용자 대신 실제 공개 승인 자동 생성 |
| 모델 역할 | 정해진 데이터로 후보/초안/검토 반환 | 세션 발급, DB 쓰기, 규칙 활성화, endpoint 변경 |
| 오케스트레이터 | 현재 권한/판본 확인 후 등록 작업 실행 | 승인 없는 외부 전송 |
| process 확장 | 주어진 최소 입력과 고정 공개 자원 | 임의 회사 파일/네트워크/인증키 접근 |

단일 사용자 PoC에는 조직 계정/SSO/관리자 콘솔을 추가하지 않는다. 같은 사용자의 다른 작업 간에도 객체 소속/revision/참조를 검사한다. 실사용 조직의 공유권한은 Q-POLICY에서 별도로 확인한다.

## 3. 화면

| 화면 | 정상 | 빈 상태/실패 |
| --- | --- | --- |
| UI-10 `/connect` | 시작 터미널의 일회 토큰 입력 -> 로컬 세션 | 잘못됨/만료/사용됨을 안전한 공통 문구로 안내 |
| UI-09 `/settings` | 실행 모드, 내부 모델 설정 여부, 연결 검사, 팩/runner 상태 | 미설정/연결 실패/환경 없음, 현재 가능한 작업 안내 |
| UI-01/03 | fixture/live 표시, 자료가 내부에서 처리됨을 표시 | 세션 만료 시 작업을 잃지 않고 재접속 안내 |
| UI-07 | 보관 중인 자료 종류, debug trace 상태, 작업 삭제 | 삭제 중/실패/충돌, 재시도 가능 |
| UI-06 | 확인한 파일의 복사/다운로드 | 유효성 만료 시 이유와 돌아갈 단계 표시 |

UI에서 실제 모델 키를 입력/노출하지 않는다. 상세 오류는 접힌 내부 진단으로 분리하고 기본 문구에 원자료/키/endpoint 인증정보를 포함하지 않는다. 작업을 삭제하면 원자료와 결과 이력이 제거되며 이미 받은 파일과 OS 백업은 별개라는 안내를 삭제 화면에 붙인다.

## 4. 데이터

| 저장/설정 | 내용 | 수명 |
| --- | --- | --- |
| 시작 설정 | 기본 loopback 또는 명시한 listen IP, allowed_hosts, 사내 endpoint, 제한, 등록 도구 | 프로세스 설정, 비밀값은 env |
| 메모리 접속 토큰 | 토큰 검증 정보/만료/사용 여부 | 5분 일회 |
| 메모리 세션 | 세션 식별자/만료/CSRF 정보 | 8시간 또는 logout/재시작 |
| `run_traces` 메타데이터 | 역할/판본/시간/상태/usage | 작업 삭제까지 |
| raw debug trace | 실제 요청/응답 | 명시 opt-in, 최대 24시간 또는 작업 삭제 |
| DB 원자료/결과 | source/evidence/decision/artifact/export | 작업 삭제까지 |
| 임시 실행 디렉터리 | 등록 입력/출력 | 실행 종료 후 정리 |

원자료/trace를 공개 artifact로 자동 등록하지 않는다. debug opt-in은 현재 내부 운영자의 명시 설정이며 실자료 처리 전에 UI-09에 표시한다. 보존 기한이 지난 raw trace는 조회/전달하지 않고 정리한다. 기본 trace가 없다는 이유로 검증 보고서에 실제 writer 입력을 봤다고 쓰지 않는다. 입력 경계 시험은 가상 자료의 별도 캡처 환경에서 한다.

## 5. 규칙

적용 불변조건은 INV-01-04/07-09/11/14-16이다.

### 접속

기본 바인딩은 `127.0.0.1`이며 사용자가 명시한 `0.0.0.0`/`[::]` 또는 특정 IP도 허용한다. wildcard 바인딩은 서버 인터페이스 IP/loopback의 Host를 허용하며 별도 도메인/접속 주소는 `server.allowed_hosts`에 호스트:포트로 등록한다. 시작 토큰은 암호학적 난수로 만들고 터미널에 표시한다. UI-10에서 `POST /api/v1/auth/session`으로 교환하고 성공 시 소비한다. 토큰은 URL이나 접근 로그에 넣지 않는다. 5분 만료 토큰은 거절하고 재시작 등 안내된 새 발급 절차를 제공한다.

세션은 8시간 고정 만료이며 `HttpOnly`, `SameSite=Strict`, `Path=/` 쿠키를 사용한다. loopback HTTP에서 Secure 쿠키를 쓰지 않는 설정을 원격 배포에 재사용하지 않는다. 서버 재시작은 세션을 폐기한다. task/job의 영속 상태 복구는 F09가 담당한다.

Host는 허용 목록과, Origin은 실제 요청 Host와 정확히 비교하고 외부 CORS를 허용하지 않는다. 상태 변경 요청에는 세션/CSRF/멱등 키를 요구한다. 토큰 교환은 세션 이전 경로이므로 Host/Origin/토큰/크기 제한을 검사하며 일반 작업 API의 공개 예외로 확대하지 않는다. 비인증 health는 liveness만 반환한다.

### 내부 모델

provider 주소는 시작 설정에서 고정한다. 원자료/모델 출력/확장 문서가 바꾸지 못한다. redirect를 따르지 않고 설정하지 않은 proxy를 쓰지 않는다. 사내 TLS 연결이 기본이며 plain HTTP는 운영자가 정확한 endpoint에 한해 설정한 경우만 허용한다.

모델 호출은 글로벌 동시성 기본 1, 역할별 timeout과 총 호출 예산을 지킨다. 문맥 초과/잘린 JSON/응답 형식 오류를 성공으로 표시하지 않는다. live 장애를 fixture로 대체하지 않는다. 최초 연결 확인에 원자료를 쓰지 않는다.

### 역할 입력

분석/검토 원문 대화, 원본 파일명, 내부 작업명, 자유형 목적, tool stderr는 writer 입력으로 보내지 않는다. writer는 새 메시지에 current fact_pack과 공개 template만 받는다. reviewer는 자유 설명을 내부에 반환하며 writer 수정 피드백은 현재 fact ID/block ID/고정 reason code만 허용한다.

업로드/편집/최종 확인은 서로 다른 권한 동작이다. 업로드했다고 공개되지 않고, 편집했다고 새 사실이 승인되지 않으며, 최종 확인했다고 누락 결정을 무시하지 않는다. API에서 강제하고 UI 비활성화에만 의존하지 않는다.

### 실행과 파일

builtin 도구는 등록 인수만 받는다. process 도구는 고정 파일/이미지/argv와 최소 마운트, 네트워크 없음/자원 상한으로 실행한다. 모델 인증키/원자료 DB/Docker socket을 컨테이너에 넣지 않는다. 환경이 없을 때 임의 호스트 실행으로 바꾸지 않는다.

공개 파일은 허용 목록에서 생성하며 실제 bytes/해시/현재 승인을 검증한다. 확정 이후 다운로드에서 새 렌더링/모델 호출을 하지 않는다. raw HTML/원격 이미지/실행 링크를 출력하지 않고 원자료는 escape해서 표시한다. 내부 자료 응답에 `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, 안전한 Content-Disposition을 적용한다.

### 삭제와 동시성

작업 삭제는 `expected_revision`과 명시 확인을 요구한다. 작업 취소 요청과 삭제를 처리한 뒤 늦은 결과가 사라진 task를 다시 만들지 못하게 한다. 관련 source/evidence/decision/artifact/export/event/trace를 삭제하고 재사용 기준에는 원문 없는 최소 provenance만 남긴다. 기존 공개 파일 회수/OS 백업 삭제/저장매체 완전 소거 기능으로 표시하지 않는다.

사용자 선택이나 규칙 변경이 진행 중 모델/도구보다 우선한다. 네트워크 호출을 기다리며 DB 트랜잭션을 잡지 않고, 결과 적용 시 task revision/current job/cancel/hash를 CAS로 확인한다.

## 6. 다른 조각과 닿는 곳

| 상대 | 공통 함수/경로 | 계약 |
| --- | --- | --- |
| 모든 API | `RequireSession`, `ValidateOrigin`, `ValidateCSRF`, `AuthorizeTaskReference` | 순서가 다른 우회 endpoint 없음 |
| UI-10 | `POST /api/v1/auth/session`, `DELETE /api/v1/auth/session` | 일회 토큰/세션 발급/폐기 |
| UI-09 | `GET /api/v1/runtime`, `POST /api/v1/provider/check`, `GET /api/v1/catalog` | 인증된 실행 환경/설정 여부/등록 목록. 별도 비인증 `GET /api/v1/health`는 liveness만 |
| F04 | `BuildWriterRequest`, `SanitizeReviewerFeedback` | 승인된 입력만 전달 |
| F07/F08 | `RunRegisteredTool` | 권한/digest/sandbox/자원 제한 |
| F05 | `ValidateExport`, 저장 bytes 반환 | current decision/hash 재검사 |
| F09 | `DELETE /api/v1/tasks/{id}`, `PurgeTask` | 취소/삭제/늦은 결과 차단 |

서비스 함수 이름은 공통 API/architecture의 책임 경계다. 별도 구현 이름을 쓰더라도 기능 파일마다 다른 승인 로직을 복제하지 않는다.

## 7. 하지 않을 것

중앙 SaaS, 인터넷 공개 서버, 다중 사용자/SSO/조직 ACL, 자동 외부 전송, 모델 서버 자체의 보존정책 강제, OS 관리자 공격 방어, DB 저장 암호화 상품 기능, 소스 공개만으로 안전성 보장, 임의 명령 실행은 이번 범위에서 제외한다.

## 9. 확인 필요

Q-LLM: 실제 사내 endpoint/인증/지원 응답/보관 정책. Q-DEPLOY: OS/네트워크/sandbox 운영 주체와 실제 차단 상태. Q-POLICY: 실자료 접근/공유 권한/보존 기간. 위 항목 확인 전에는 가상 자료로 구현/테스트하고 실자료 운영이 검증됐다고 보고하지 않는다.

## 10. 구현 순서와 변경 영향

loopback/세션/요청 검사 -> 저장 경로/자료 수명 -> provider transport -> 역할 입력 조립 -> 도구 실행 경계 -> export 재검사 -> 삭제/중단 시험 순서다. 이 기능은 마지막 보안 패치로 미루지 않고 각 API와 도구가 사용하는 공통 기반으로 제공한다. 바인딩 외의 원격 운영/다중 사용자/자동 제출을 추가할 때는 PRD/spec/security/ERD/API를 함께 개정해야 한다.
