# Fxx · 기능 이름

우선순위: P0/P1/P2 · 담당 역할: · 문서 상태: 초안/합의/구현중/검증완료.

## 1. 목적

사용자 문제 한 문장. 연결 PRD ID와 이 기능이 제공할 결과. 제품 범위를 새로 정했다면 PRD부터 같은 PR에 수정한다.

## 2. 쓰는 사람과 권한

누가 시작/읽기/변경/확정하는지, 모델/도구는 어디까지 가능한지. 인증·객체 소속·공개 결정·최종 확인을 구분한다.

## 3. 화면

UI ID, 시작 경로→행동→다음 화면. 초기/빈/진행/부분결과/실패/재시도/권한없음/오래된 결과/취소/복구 상태. 버튼 비활성 이유와 입력 보존 여부.

## 4. 데이터

읽는 표/필드, 만드는 불변 레코드, 수정하는 현재 포인터, 새 필드·migration 필요 여부. 내부용과 외부 공개 데이터를 구분한다.

## 5. 규칙·상태·동시성

정상 순서, 필수 입력·길이·enum·경계값, state/revision/hash 변화, 재시도·멱등·늦은 결과, 삭제·만료·철회. INV ID를 연결한다. 아직 없는 규칙은 spec에도 반영한다.

## 6. 다른 조각과 닿는 곳

제공/호출하는 서버 함수, API method/path, 공통 DTO/schema, 이벤트, 오류, 상대 기능 F ID. 요청/응답 예를 최소 한 개 적고 실패 예도 포함한다. DTO 복제 대신 공통 계약을 사용한다.

## 7. 하지 않을 것

이번 PR/PoC에서 뺀 행동. 다른 기능이 책임지는 항목과 후속 확장을 구분한다.

## 8. 끝났다는 기준

`AC-Fxx-01` 형식으로 정상·경계·오류·권한·동시성의 관찰 가능한 결과를 적고 T ID에 연결한다. ‘동작한다/안전하다/잘 나온다’만 쓰지 않는다. 실제 실행 결과는 별도 보고서에 기록한다.

## 9. 확인 필요

문서에 없어 사람에게 물어야 할 실제 조직/운영 결정 Q ID. 없는 경우 ‘없음’. 새 기본 설계 D를 사용자 확정으로 꾸미지 않는다. 이 확인이 없어도 진행할 수 있는 개발과 막히는 실제 작업을 함께 쓴다.

## 10. 구현 순서와 변경 영향

선행 기능/계약, 첫 작은 구현, 유효한 검증, 영향받는 공통 문서·기능·테스트. 문서 PR→연동 계약 확인→구현 흐름을 따른다.
