# F03 - 공개 범위/표현 수준/직접 조건 결정

상태: P0 구현 기준안 / 기준일: 2026-10-31 / 구현 담당: [plan.md](../product/plan.md)의 F03 담당

## 1. 목적

[PRD-05/06](../product/prd.md)에 따라 사용자가 **필요한 정보는 무엇이고 어느 수준까지 공개할지** 실제 결과를 보며 결정하게 한다. 선택은 내부 원자료에서 공개 작성용 정보로 넘어가는 경계다. 후보를 발견한 것, 원문을 읽은 것, 초안을 편집한 것을 공개 허용으로 처리하지 않는다(INV-03~06).

### 사용자에게 설명할 것과 검토할 선택

이 화면에서는 어떤 내용을 실제로 어떤 표현으로 공유할지 결정한다. 미선택·허용·제외·보류의
차이와 표현 미리보기의 역할은 [UF-03](../design/user-flow.md#uf-03-공개-결정)을 따른다.
허용은 해당 표현의 범위에만 적용한다. 선택지 클릭·조건 입력·모델 추천은 저장된 공개 결정이 아니다.

현재 A~D는 수치 요청량 사례의 표현이다. 정확히 네 종류로 고정하거나 일반 원자료 전부에
같은 선택지를 보여줘야 한다는 사용자 결정 근거는 확인되지 않았다. 특히 필드 선택은 실제값을 남길 수 있으므로
마스킹이라는 명칭으로 숨김을 보장하지 않는다. 조건 직접 입력도 지원 변환 안에서 실제 결과를 확인해야 한다.

## 2. 쓰는 사람과 권한

| 주체 | 허용 | 금지 |
| --- | --- | --- |
| 사용자 | 허용/제외/보류, 미리보기 적용, 정확값/원문 허용, 철회, 재사용 기준 저장 | 미유효 판본을 화면 조작으로 승인, 필수 검사를 확정 버튼으로 우회 |
| 분석/조건 해석 모델 | 근거/필요 이유/지원 조건 제안 | 결정 생성/승인/규칙 활성화 |
| 서버 공개 투영기 | 현재 자료/선택으로 정확한 미리보기와 승인팩 계산 | 선택되지 않은 정보의 자동 포함 |
| 작성기 | 승인팩의 정보 사용 | 후보/원자료 조회, 공개 범위 확대 |

결정의 사용자는 로컬 세션 사용자다. 회사의 공식 승인권자/다단계 결재는 Q-POLICY/P2다. 현재 구현에서 모델 호출을 사용자의 UI 동작으로 위장할 수 없어야 한다.

## 3. 화면

UI-03의 UI-04 공개 질문 패널에서 선택하고, D는 같은 패널의 UI-05로 연다. 카드의 요소는 정보명, 필요한 이유, 근거, 관찰/가설/모름 표시, 선택별 미리보기, 제외되는 정보, 적용 범위, 저장 동작이다.

선택지 클릭은 미리보기 요청이다. `이 방식으로 적용`에서만 결정이 저장된다. 기본 상태는 허용 미선택이다. `나중에 결정`은 defer, `이번 결과에서 제외`는 exclude다. 허용/제외/보류는 서로 다른 결과다.

### 요청량의 고정 선택

| 선택 | 구현 의미 | 820/1160/1740의 출력 |
| --- | --- | --- |
| A. 구체적인 데이터 없이 사실만 | 승인한 fact_summary | 관찰된 구간에서 요청량이 증가했습니다 |
| B. 추이만 보이게 나머지 마스킹 | `series_direction_only.v1`의 derived_table | 첫 번째 기준 / 두 번째 증가 / 세 번째 증가 |
| C. 요청 정보 마스킹 | selected_fields. 남길 실제 필드/값/단위의 미리보기를 이번 자료에서 승인 | 사용자가 허용한 열/실제값으로 구성한 새 표 |
| D. 기타 (직접 입력) | 등록 변환으로 해석하고 계산된 결과 확인 | 예: `series_index_base100.v1`, 소수0자리 HALF_UP -> 100/141/212 |

B는 관찰 개수와 순서까지 드러난다. A는 그 정보도 별도 승인 없이는 포함하지 않는다. C는 실제값을 유지하므로 재사용 저장을 허용하지 않는다. D가 비율을 공개하면 상대 변화량이 드러난다는 설명을 미리보기에 포함한다.

## 5. 규칙

### 허용 종류

| 종류 | 허용 범위 | 자동으로 허용되지 않는 것 |
| --- | --- | --- |
| fact_summary | 사용자가 확인한 의미와 상세 수준 | 원인 단정/새 숫자/새 관계/추가 시점 |
| derived_table | 등록 변환으로 계산한 정확한 결과 | 원래 열/원래 값/숨긴 단위/관측 간격 |
| selected_fields | 선택한 현재 원자료 필드와 실제값의 공개 형태 | 제외한 필드/같은 위치의 새 판본 값 |
| exact_value | 이번 자료에서 확인한 지정 값 | 주변 문장/같은 값이 있는 다른 맥락 |
| approved_excerpt | 지정 판본/바이트 구간/확인한 출력 형태 | 범위 밖 원문/다른 판본/미확인 숨김 변형 |

원문 구간 허용은 source_version_id, source hash, UTF-8 경계에 맞는 반열린 바이트 범위, 실제 공개 형태의 hash, scope, expiry에 결합한다. 구간을 숨기는 예외적 표현을 지원할 경우에도 원문 전체를 모델에 넘겨 알아서 가리게 하지 않고 최종 실제 구간을 사용자에게 보여준다. 인용은 승인된 슬롯을 앱이 삽입한다.

### 공개 미리보기와 저장

1. 현재 후보와 자료/범위를 조회한다.
2. 지원 representation과 매개변수를 검증하고 실제 공개 projection을 앱이 만든다.
3. projection bytes와 hash, scope/source/revision 결합을 서버에 저장한다.
4. 사용자가 확인한 미리보기 참조로 결정 배치를 요청한다.
5. 서버가 미리보기와 현재 scope/source/revision의 일치를 확인하고 모든 allow 항목의 projection을 다시 계산해 저장/요청/재계산 hash가 같은지 검사한다. 클라이언트가 보낸 임의 scope/raw grant를 신뢰하지 않는다.
6. 배치 전체를 검증한 뒤 불변 결정과 current_decisions를 한 번에 저장하고 revision을 한 번 올린다.
7. 기존 결과를 stale로 만들고 F04가 현재 승인 정보로 전체 새 작성하도록 연결한다.

allow 항목은 유효한 `preview_id`와 `projection_sha256`가 필수다. exclude/defer는 projection이나 grant를 만들지 않으며 미리보기 참조를 요구하지 않는다. 재사용 저장은 현재 지원하는 allow 변환에만 가능하고 exact/raw/selected_fields 실제값은 제외한다.

미리보기 이후 값 한 셀이라도 바뀌면 기존 미리보기 승인으로 통과시키지 않는다. 선택별 비공개 정보 설명은 내부 UI에만 사용하며 작성기로 넘기지 않는다.

### 보류/제외/필수성

- optional 후보를 선택하지 않으면 공개 입력에서 제외한다. 무조건 모든 후보에 사용자의 클릭을 요구하지 않는다.
- 사용자가 defer한 후보와 목적상 필요한 미결정 정보는 최종 확정 전에 해소해야 한다.
- 일부 결정만으로 임시 초안을 만들 수 있으나 draft/미완료로 표시하고 최종 확정하지 않는다.
- required는 자동 공개 허용이 아니다. 제외할 권리가 있으며 시스템은 목적 달성에 어떤 제약이 생기는지 설명한다.
- 목적 범위를 조정하면 새 범위의 필수 정보 조건으로 다시 검사한다. 모든 required 표시를 사용자가 해제하는 우회 UI는 없다.
- 공개 정보가 전혀 없는 빈 문서를 성공 결과로 만들지 않는다.

등록 템플릿이 정한 필수 need와 모델의 required 추천은 구분한다. 모델 추천 자체가 변경 불가능한 차단 조건은 아니다. 목표의 필수 조건이 빠지면 `goal_variant` 변경을 요청한다. 예를 들어 ID가 없는 공급사 문의는 `ask_for_diagnostics`, 재현 확인을 못한 제보는 사용자가 `observations_only`를 선택할 수 있다. 변경은 PATCH tasks -> revision +1 -> needs_analysis이며, 새 목표의 후보/공개 결정을 다시 평가한다.

### 수동 후보/메모 추가

`POST /api/v1/tasks/{id}/manual-candidates`는 근거 또는 user_note를 받아 새 revision과 새 불변 candidate_set을 만든다. 기존 후보는 검증 후 새 ID로 복제하고 새 후보를 추가한다. user_note가 있으면 같은 트랜잭션에서 내부 source로 저장한다. 과거 결정은 자동 이전하지 않으며 needs_decisions로 전환한다. 이전 선택은 참고로 제시하고 사용자 재확인 또는 유효한 재사용 변환을 거친다. LLM 재분석 없이 수동 복구할 수 있지만 새 메모가 자동으로 writer 공개 입력이 되지는 않는다.

### 직접 입력

`interpret_disclosure` job은 supported/ambiguous/unsupported를 반환한다. supported여도 등록 transform_id/허용 매개변수만 사용한다. 직접 입력은 해석 결과->실제 계산->미리보기->사용자 적용 단계를 거친다. 자연어/생성 코드/정규식/SQL을 그대로 권한 조건이나 실행 명령으로 저장하지 않는다.

기준값이 0인 상대지수는 `INDEX_BASELINE_ZERO`다. 음수/결측/잘못된 타입은 등록 스키마에 따라 거부하고 누락 행을 숨겨 성공 결과로 만들지 않는다. 방향은 실제 순서대로 다시 계산하며 820/780/1740은 감소/증가다. 실제 날짜/간격/단위/규모/증가율은 별도의 정보다.

### 철회/만료/재사용

현행 wire scope에는 project_id, purpose_id, recipient_id, audience, skill_set_hash가 포함된다. `goal_variant`는 현재 scope 스키마에 없으므로 별도 목표 결합 규격이 확정되기 전까지 UI가 임의로 추가하거나 범위 전체 허용으로 해석하지 않는다.

기본은 이번 작업만 적용한다. expires_at=null은 시간 제한 없음이며 원자료/범위/판본 검사는 계속한다. 정확값/원문/실제값 selected_fields는 reusable=false다. 저장 기준은 F06의 조건 일치 변환만 허용한다.

새 결정은 기존 결정을 덮어쓰지 않고 supersedes_id로 연결한다. 현재 결정이 철회/만료되면 현재 허용 없음으로 처리한다. 옛 allow 레코드로 되돌아가지 않는다. 철회는 현재 결과/export를 무효화하며 이미 받은 외부 파일은 회수하지 못한다.

### 동시성

결정과 철회는 expected_revision과 Idempotency-Key를 검사한다. 배치 중 하나라도 미리보기/근거/범위가 잘못되면 전체 배치 미반영이다. 사용자 변경 즉시 현재 결과가 stale로 바뀌며 늦은 job 결과는 CAS에서 거부된다. 저장한 미리보기만으로 모델이 decision API를 호출할 권한은 생기지 않는다.

| `DisclosureService.CreatePreview` / `POST /api/v1/tasks/{id}/disclosure-previews` | expected_revision, candidate_id, representation | preview 참조, 실제 projection, hash, 공개되는 의미, 재사용 가능 여부 |
| 조건 해석 / `POST /api/v1/tasks/{id}/jobs` | kind=`interpret_disclosure`, expected_revision, arguments의 candidate_id/text | job; 지원 조건 제안. 공개 결정 아님 |
| `DisclosureService.ApplyDecisionBatch` / `POST /api/v1/tasks/{id}/decision-batches` | expected_revision, 후보별 disposition과 현재 미리보기/hash, expiry, 재사용 선택 | 새 결정 ID/revision/phase/무효화 내역 |
| `DisclosureService.RevokeDecision` / `POST /api/v1/tasks/{id}/decisions/{decision_id}/revoke` | expected_revision | 현재 결정 무효, 새 revision |

현재 실제 경로/세션 CSRF/DTO는 [api.md](../design/api.md)를 정본으로 따른다.
`contracts/openapi.json`과 `*.v1.schema.json`은 [참고 계약](../../contracts/README.md)이며
전체 스키마가 현재 서버의 동작 API라는 뜻은 아니다. `select_fields.v1`의 parameters.fields는
기존 core 정의와 HTTP 참고 스키마를 맞췄고, 단일 CSV/JSON 근거의 필드 목록/서버 변환을 구현했다.
화면 로그인/C 필드 선택 등 후속은 [UI 요청 현황](../ops/ui-api-requests.md)을 따른다.
F02의 후보/근거 -> F03의 결정/투영 -> F04의 승인팩으로 연결한다. F05는 현재 결정의 유효성과
보류 여부를 검사한다. F06은 재사용 기준만 만들고 새 자료의 정확값 허용을 만들지 않는다.
F07의 예외 검사 결과가 F03 allow를 대신할 수 없다.

## 7. 하지 않을 것

위험 점수에 따라 자동 공개 승인, 단순 유사도 기반 반복 허가, 원문 전체를 가린 뒤 보내는 기본 모드, 자연어 정책의 무제한 실행, 조직 결재/법적 승인 판정, 실수한 외부 공유의 회수는 범위 밖이다.

## 9. 확인 필요와 구현 순서

실제 회사의 공개 판단 기준/승인권자는 Q-POLICY, 실제 제품의 필요한 정보와 변환은 Q-EXT다. 가상 사례의 A/B/C/D와 기본 변환은 이 문서의 D 기준으로 구현한다.

구현 순서는 결정 타입/projection 함수 -> 미리보기 저장/해시 -> 원자적 배치/철회/만료 -> A/B/C/D UI -> 직접 입력 어댑터 -> F06 재사용 -> F04/F05 연결이다. 공개 결정 규칙을 바꾸면 spec/ERD/API/F04~F08/qa와 함께 검토한다.
