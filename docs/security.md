# 실행 경계와 자료 취급

> 보존한 제품 설계·이전 기록이다. 현재 구현은 TypeScript 서버·클라이언트의 문서 저장·조회만 제공한다. 현재 실행과 API는 [README](../README.md) 및 [api](api.md)를 따른다.

버전: 1.0 · 기준일: 2026-10-31 · 상태: 구현 기준안

이 문서는 [PRD](prd.md)의 PRD-03·06·08·12와 [동작 명세](spec.md)의 INV-01–16을 실제 배치·권한·자료 수명으로 연결한다. SafeHandoff의 목적은 사람이 공유 자료를 준비하는 일을 돕는 것이다. 아래 경계는 그 과정에서 원문과 승인되지 않은 자료가 의도하지 않은 경로로 전달되는 일을 줄이기 위한 설계다. 모델의 의미 판단이 항상 정확하다는 약속은 포함하지 않는다.

## 1. 이번 PoC의 배치

**회사별로 설치·운영하는 단일 사용자 로컬 앱**이다. 사용자 소유 OS 계정에서 실행하고 브라우저는 기본적으로 `127.0.0.1`의 앱에 접속한다. 사용자가 명시한 경우 `server.listen=0.0.0.0:port` 등 사내 네트워크 바인딩을 지원한다. 원자료를 읽는 앱과 지정 사내 LLM이 내부 준비 공간을 이룬다. 모델 서버가 원격 사내 서버여도 연결할 수 있다. 외부 사업자가 모든 회사의 원문을 모으는 중앙 서비스는 설계에 없다.

| 구성 | 허용하는 접근 | 이번에 주지 않는 권한 |
| --- | --- | --- |
| 브라우저 | 인증된 로컬 앱, 사용자 확인 후 복사·다운로드 | 원문 속 URL의 자동 요청, 외부 분석·광고 스크립트 |
| 앱 서버 | 로컬 DB, 등록 자료, 지정 사내 LLM, 등록 실행기 | 임의 URL·임의 폴더·외부 티켓 자동 전송 |
| 분석·검토 호출 | 해당 작업의 선택한 원자료와 현재 조건 | 승인 생성, 외부 제출, 도구 등록 |
| 작성 호출 | 현재 `fact_pack`과 등록 공개 템플릿 | 원자료 조회, 분석 대화 재사용, 임의 파일·네트워크 도구 |
| 확장 프로세스 | 앱이 넘긴 최소 JSON·공개 입력·등록 파일 | 회사 원자료 전체, 모델 인증키, 호스트 Docker socket |
| 외부 수신자 | 사용자가 확인하고 직접 공유한 결과 | 앱 DB·내부 근거·검토 기록 |

최초 설치에 필요한 모듈·도구·이미지 준비와 실제 업무 실행을 분리한다. 업무 실행 중에는 인터넷 연결을 막고 지정 사내 모델 통신만 허용하는 환경을 권장한다. 앱의 URL allowlist만으로 OS 전체의 망 차단이 구현됐다고 표시하지 않는다. 실제 방화벽·사내 모델 접근 정책 확인은 Q-DEPLOY의 대상이다.

## 2. 신뢰하는 것과 시험하는 것

PoC는 사용자 OS 계정, 호스트 관리자, 사내 모델 운영자, 설치한 고정 확장 코드가 승인된 운영 환경이라는 전제에서 동작한다. 악의적 호스트 관리자·커널 침해·장비 탈취 방어는 이번 검증에 포함하지 않는다. 이 전제를 감춘 채 ‘로컬이라 유출 불가’라고 설명하지 않는다.

시험 대상은 원자료 속 악성 지시, 모델이 만든 잘못된 요청, 늦은 작업 결과, 조건과 다른 이전 승인, 미리보기와 다운로드의 불일치, 검토 피드백을 통한 원문 혼입, 예외 검사 실패, 브라우저 요청 위조다. 원자료·모델 출력·사용자 첨부를 지시나 실행 코드가 아닌 데이터로 취급한다.

## 3. 로컬 접속과 권한

다음은 **신규 PoC 기본값**이다. 다중 사용자 로그인 시스템으로 확대하지 않는다.

1. 기본 바인딩은 `127.0.0.1`이다. 명시한 IP 또는 `0.0.0.0`/`[::]` 바인딩을 허용한다. wildcard listen에서는 서버 인터페이스 IP와 loopback의 Host만 자동 허용하고 추가 접속 이름은 `server.allowed_hosts`의 호스트:포트로 등록한다. Host 검사를 생략하거나 임의 도메인을 허용하지 않는다.
2. 시작 시 암호학적 난수로 일회 접속 토큰을 만든다. 토큰은 실행 터미널에 한 번 표시하고 5분 뒤 만료한다. URL·쿼리 문자열·일반 접근 로그에 넣지 않는다.
3. UI-10 `/connect`에서 사용자가 토큰을 입력하면 `POST /api/v1/auth/session`이 검증한다. 성공하면 토큰을 소비하고 8시간 유효한 로컬 세션을 만든다. 실패가 토큰 내용이나 존재 여부를 드러내지 않게 한다.
4. 세션 쿠키는 `HttpOnly`, `SameSite=Strict`, `Path=/`로 설정한다. HTTP에서는 `Secure`를 사용하지 않으며 TLS 접속을 구성한 경우 해당 배치의 쿠키·Origin 계약을 함께 적용한다. 사내 네트워크 바인딩 자체가 TLS나 사용자 인증을 제공하지 않는다.
5. 인증된 변경 요청은 세션·CSRF 토큰·허용 목록에 속한 Host와 그 요청 Host와 일치하는 Origin을 함께 검사한다. 외부 CORS를 허용하지 않는다. 로그인 교환도 Host·Origin과 제한된 요청 크기를 검사한다.
6. `DELETE /api/v1/auth/session`은 해당 세션을 폐기한다. 서버 재시작은 기존 메모리 세션을 폐기하고 새 접속 절차를 요구한다. 진행 중 작업의 내부 상태는 DB에 남는다.

비인증 `GET /api/v1/health`는 프로세스 liveness만 반환한다. 파일 목록·작업 ID·모델 주소·DB 경로·상세 오류는 인증 후 제공한다. ‘로컬 앱이므로 모든 요청 허용’ 분기를 만들지 않는다.

기능별 소속 검사도 필요하다. 인증된 같은 사용자라도 A 작업 API에 B 작업의 candidate·file·evidence ID를 넣는 것은 오류다. 클라이언트가 보낸 참조를 현재 작업·판본과 대조한다.

## 4. 내부 LLM 연결

endpoint·모델 ID·인증 방식은 운영자가 시작 설정으로 제공한다. 모델이나 원자료가 이 설정을 바꾸지 못한다. runtime의 모델 요청은 한 등록 endpoint에만 보내고 HTTP redirect를 따라가지 않는다. 프록시 환경 변수 때문에 지정하지 않은 외부 서버로 전달되지 않게 transport를 명시적으로 구성한다.

사내 원격 연결은 TLS가 기본이다. HTTP만 제공하는 기존 사내 서비스는 운영자가 그 endpoint에 한해 예외 설정할 수 있다. 이는 회사의 실제 연결 정책 확인 사항이며 모델이 자동 권고·적용하는 설정이 아니다. 연결 확인은 비민감한 짧은 입력으로 한다.

`fixture`와 `live`는 실행 설정과 UI에 계속 표시한다. live 실패 시 준비된 응답으로 바꾸지 않는다. 작은 모델의 출력 형식·문맥 한도·기능 미지원은 작업 오류 또는 사용자 보완으로 드러낸다. 사내 모델의 요청 기록·학습 사용·보관 기간은 앱이 통제하지 못하므로 Q-LLM에서 확인한다.

## 5. 원문과 작성 입력 사이의 경계

공개 자료는 현재 결정으로 계산한 `fact_pack`에서 새로 작성한다. 분석과 검토가 읽은 원문 대화는 작성 호출에 재사용하지 않는다. 작성기는 source 조회 도구를 갖지 않는다. 역할별 호출은 같은 모델을 써도 매번 새 메시지 배열로 구성한다.

| 원문이 섞일 수 있는 곳 | 처리 규칙 |
| --- | --- |
| 내부 작업명·원본 파일명·수신자 표시 이름 | 내부 UI에만 사용. 공개 이름은 등록 템플릿에서 생성 |
| 목적 자유 입력 | 내부 분석 입력. 공개 본문에 필요한 내용은 후보·공개 미리보기·결정 경유 |
| 검토기의 자유로운 설명 | 내부 검토 화면에만 표시 |
| 작성 수정 피드백 | 검증한 `block_id`, 현재 승인 `fact_id`, 고정 `reason_code`만 전달 |
| 도구 stderr·모델 오류 원문 | 내부 진단에만 저장. 사용자·작성기에는 고정 코드와 안전한 설명 |
| 직접 편집한 새 주장·값 | 편집만으로 공개 승인 생성 금지. 새 결정 또는 기존 허용과 일치 확인 |
| 제품 지침 | 공개 작성용으로 별도 등록한 문서만 writer에 제공 |
| 원문 인용 | source 판본·바이트 범위·렌더 결과가 묶인 승인 슬롯을 앱이 삽입 |

같은 모델로 작성·검토를 호출하는 것은 독립된 전문가 두 명의 판정과 같지 않다. 분리된 입력 경로와 검토 기록을 구현하고, 의미 정확성은 실제 사례와 사람 평가로 확인한다.

## 6. 검사와 예외

판본·해시·승인·원문 참조·파일 목록·필수 검사 등 결정적으로 확인할 조건은 서버가 집행한다. 사람의 ‘의미 검토 완료’ 체크로 이 조건을 우회할 수 없다. 패턴 검사는 보조 수단이며 모든 숫자·주소를 일괄 지우는 규칙이 아니다. 보안 findings는 severity와 관계없이 해소해야 하며 severity는 화면 표시 우선순위에만 쓴다. 단순 비보안 안내는 event로 기록한다.

문맥 예외 검사기는 **이미 공개가 허용된 결과의 특정 finding**을 해소한다. 새 공개 허가를 만들지 않는다. 정확한 값이 같아도 원래 접속 로그와 새 설명용 설정은 서로 다른 문맥이다. 예외 오류·timeout·해시 불일치는 허용이 아니다. [확장 계약](extensions.md)과 [F07](features/07-domain-extensions.md)에 판정표를 정의한다.

## 7. 자료 보관과 삭제

다음은 **신규 PoC 기본값**이며 실자료 도입 전에 Q-POLICY를 확인한다.

| 자료 | 기본 보관 | 삭제 동작 |
| --- | --- | --- |
| 원자료·근거·선택·결과·작업 이력 | 사용자가 작업을 삭제할 때까지 | 작업 삭제 시 관련 DB 레코드·BLOB 제거 |
| 호출 메타데이터 | 작업 이력과 함께 | 작업 삭제 시 제거 |
| 모델 요청·응답 원문 trace | 기본 저장 안 함. debug 명시 opt-in 때 최대 24시간 | 보존기한 도달 또는 작업 삭제 시 제거 |
| 실행 중 임시 파일 | 해당 실행 동안 | 종료·실패·취소 시 정리; 시작 시 남은 임시 파일 회수 |
| 재사용 기준 | 사용자가 철회·삭제할 때까지 | 원자료를 복제하지 않은 기준만 별도 유지 가능 |

작업 삭제는 입력 목록에서 자료를 제외하는 동작과 다르다. `DELETE /api/v1/tasks/{id}`에서 현재 revision과 삭제 확인 문구를 검사한다. 작업 취소를 요청하고 DB의 작업·source·evidence·decision·artifact·export·event·trace를 삭제한다. 늦게 도착한 작업 결과는 삭제된 task에 다시 저장할 수 없다.

삭제된 작업에서 만든 재사용 기준에는 원문·개별 값·상세 이유를 남기지 않는다. source task 참조는 NULL로 바꾸고 비민감 최소 provenance만 유지한다. 기준 자체의 철회는 별도 기능이다. 이미 받은 파일, 브라우저 외부에 복사한 내용, OS 백업·스냅샷을 회수하거나 물리 저장매체를 완전 소거했다고 표시하지 않는다.

데이터 디렉터리는 소유자만 접근하는 권한을 사용한다. PoC는 저장 암호화 기능을 제공한다고 주장하지 않는다. 원자료와 내부 기록을 공개 파일 경로·정적 자원 경로에 두지 않는다. `.env`, 실행 DB, debug trace는 저장소에 넣지 않는다.

## 8. 화면과 공개 파일

원자료·생성 자료는 HTML escape 후 표시한다. 임의 HTML, 실행 URL scheme, 자동 링크 미리보기, 원격 이미지 로드를 허용하지 않는다. JSON 중복 키·보이지 않는 제어문자·경로 우회·중복 첨부 이름을 검사한다. CSV의 텍스트 셀 표현 규칙은 실제 출력 바이트에 적용하고 같은 내용을 미리보기에 보여준다.

공개 패키지는 허용 파일 목록에서 하나씩 만든다. 내부 작업 폴더 전체를 ZIP으로 만들지 않는다. 내부 원문·도구 진단·사용한 승인 ID·DB 참조·평가 정답표는 공개 manifest에 넣지 않는다. 다운로드는 확정한 저장 바이트만 반환하며 새 모델 호출이나 후처리를 수행하지 않는다.

## 9. 확장 실행

등록된 실행 파일·target·공개 asset의 digest를 실행 직전에 확인한다. process 실행은 네트워크 없음, 읽기 전용 root, 제한된 tmpfs, non-root 사용자, capability 제거, 새 권한 획득 금지, CPU·메모리·PID·시간·출력 상한을 적용한다. Docker의 `none` 네트워크는 컨테이너에 loopback만 생성하는 실행 방식이다.[S-SEC-01]

컨테이너에 회사 DB·모델 인증 환경 변수·호스트 Docker socket을 넘기지 않는다. runtime에 image pull을 하지 않는다. 환경이 없을 때 호스트 shell 실행으로 자동 대체하지 않는다. 필수 checker가 없으면 확정 차단, 선택적 재현 환경이 없으면 `not_run/no_environment`로 작성은 계속할 수 있다.

## 10. 구현에서 확인할 증거

외부 요청 시도 거절 기록, 실제 writer 입력 캡처, 다른 작업 ID 거절, 늦은 결과 무효화, 승인 변경 뒤 다운로드 차단, 원문과 동일 값의 다른 맥락 예외, debug trace 만료·삭제, 삭제 뒤 늦은 결과의 재저장 거절을 검증한다. 검증용 로그 자체도 내부에만 남긴다.

보안 관련 시험 통과와 의미 검토 통과를 별도로 보고한다. 동일 호스트와 내부 모델 운영자가 신뢰 경계 안에 있다는 전제, 실제 망 차단 확인 여부, 미수행 시험은 실행 보고서에 남긴다.
