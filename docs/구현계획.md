# SafeHandoff 구현 계획

단일 Go 프로세스 안에서 도메인·정책·저장·모델·워크플로·HTTP를 분리한다. 모델에 권한 판단을 위임하지 않는다. 작업 자료와 내부 설명은 작성 요청에서 제외하고 서버가 계산한 승인팩만 전달한다.

순서는 M0 계약/예시 → M1 저장/투영 → M2 API/fixture → M3 화면 → M4 live 어댑터 → M5 최종 바이트 → M6 확장 → M7 검증이다. 각 단계는 시험과 함께 커밋한다. 실제 실행하지 않은 Docker·live·사람 평가는 미수행으로 남긴다.

사용자의 추가 지시에 따라 도구 버전은 mise.toml로 관리한다. Go는 단일 실행 파일, 표준 HTTP/템플릿, 결정적 ZIP에 적합하여 유지한다.
