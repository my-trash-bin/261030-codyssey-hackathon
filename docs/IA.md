# SafeHandoff IA — 화면 구조와 공통 표시 규칙

문서 버전: 1.0 · 기준일: 2026-10-31

이 문서는 구현할 URL, 화면 영역, 빈 화면·실패 화면, 동작 가능 조건을 정의한다. 제품 범위는 [PRD](prd.md), 상태의 최종 판정은 [spec](spec.md), 요청 계약은 [API](api.md)를 따른다. 화면이 계산한 상태만으로 서버의 검사 조건을 생략하지 않는다.

## 1. 공통 화면 구조

- 상단에는 `SafeHandoff`, 현재 프로젝트 또는 작업 이름, `사내 자료 준비 공간`, 실행 모드(`실제 모델` / `개발용 예시 응답`)를 표시한다.
- 좌측 이동은 `자료 만들기`, `작업 목록`, `작업 기록`, `저장한 선택`, `실행 환경`이다. 메뉴 이동만으로 실행을 취소하거나 입력을 삭제하지 않는다.
- 원자료·내부 근거 영역에는 `내부 참고 — 공유 파일에 포함되지 않음`을 표시한다. 공유 초안과 최종 파일은 별도 영역이다.
- 전체 페이지는 1280×720, 1366×768에서 가로 스크롤 없이 사용한다. 넓은 표·코드는 해당 패널 안에서 스크롤한다. 모바일 최적화는 P2지만 좁은 창에서 동작이 사라지면 안 된다.
- 오류는 해당 입력·버튼 가까이에 표시하고 페이지 상단의 상태 요약과 연결한다. 원래 입력과 이미 저장한 선택은 보존한다.
- 문서·코드·파일명은 신뢰하지 않는 데이터로 표시한다. 원격 이미지·URL 미리보기를 자동으로 불러오지 않는다. 세부 보안 렌더링은 F10을 따른다.
- 버튼은 기본·처리 중·성공·실패·비활성 상태를 갖는다. 비활성 이유를 텍스트로 제공하며 색만으로 상태를 전달하지 않는다.

## UI-01 — 작업 목록

### 표시 항목

내부 작업 이름, 프로젝트, 목적, 수신 범위, 마지막 수정 시각, 현재 상태, 실행 모드, 미해결 질문 수를 행 단위로 보여준다. 고객명·원문 미리보기·모델 응답을 작업 목록에 자동 노출하지 않는다. 서버가 제공하는 cursor로 다음 목록을 불러온다. 첫 정렬은 최근 수정순이다.

### 동작과 상태

| 상황 | 표시 / 동작 |
| --- | --- |
| 작업 없음 | `공유할 자료를 준비해 보세요.`와 `새 자료 만들기`. 예시 시작은 가상 자료임을 명시 |
| 로딩 | 제목 없는 가짜 작업 행 대신 목록을 불러오는 상태 표시 |
| 읽기 실패 | 재시도와 오류 안내. 새 작업 동작 가능 여부는 서버 상태에 따름 |
| 삭제된 작업 링크 | `삭제되었거나 찾을 수 없는 작업입니다.`와 목록으로 이동 |
| 작업 진행 중 | 현재 단계·시작 시각·`작업 열기`. 목록 이동은 작업을 취소하지 않음 |

## UI-02 — 입력

상단에서 작업 이름·프로젝트를 정하고 `어떤 도움을 받고 싶나요?`, `누가 읽나요?`, `결과 언어`, `제품별 추가 기능`을 선택한다. 아래에 파일 드롭 영역과 텍스트 붙여넣기를 둔다. 실제 내부 메모 자유 입력은 내부 후보에 사용하며 승인 없이 공개 문서에 그대로 넣지 않는다는 짧은 안내를 한다.

`이번 자료로 어디까지 확인할까요?`에는 목적에 맞는 goal_variant를 보여준다. 라벨은 default=`기본 문의 자료 준비`, observations_only=`관찰한 내용으로 문의`, ask_for_diagnostics=`다음 조사에 필요한 정보 질문`, reproduction_evidence=`새 예제로 재현 확인`이다. 운영 자문은 default만, 공급사 재현 목표는 등록 실행 팩이 있을 때만 선택한다. 목표 변경은 재분석·재결정을 요구한다.

자료 목록에는 표시 이름·형식·크기·파싱 결과·현재 사용 여부·교체/제외 버튼을 둔다. 붙여넣기도 저장 시 하나의 입력 자료가 된다. 저장한 원본은 정규화하지 않고 불변 판본으로 보존한다.

주요 버튼은 `자료 분석 시작`이다. 필수 입력 또는 유효한 자료가 없으면 이유를 보여주며 비활성화한다. 생성된 작업 ID는 먼저 확보할 수 있으나 자료 업로드 실패를 분석 시작 성공으로 표시하지 않는다.

| 상황 | 표시 / 복구 |
| --- | --- |
| 자료 없음 | 지원 형식과 붙여넣기 예, 분석 비활성 |
| 지원하지 않는 파일 | 해당 파일에 이유 표시, 다른 형식으로 준비하거나 제외 |
| CSV/JSON 해석 실패 | 파일·문제 위치를 안전한 설명으로 표시. 자동 수정·줄 생략하지 않음 |
| 크기/파일 개수 초과 | 현재 제한과 초과 대상을 표시. 파일별 한도와 모델 문맥 한도가 다름을 설명 |
| 일부 파일 실패 | 한 배치 전체가 저장되지 않았음을 표시. 실패 파일 수정/제외 후 같은 사용자 동작 재시도 |
| 업로드 완료·분석 불가 | 자료는 저장됨을 표시하고 모델 연결/문맥 문제로 이동. 업로드를 다시 요구하지 않음 |
| 목적/수신자 조합 오류 | 공개 대상과 지정 외부 대상의 조합을 바로잡는 메시지 |

첫 PoC는 운영 설정에 등록된 프로젝트·수신자를 선택한다. 없는 항목은 실행 환경의 설정 안내로 연결한다. 운영자가 검증 가능한 설정에 ID·표시 정보를 추가하고 앱을 재시작한다. UI 등록폼과 POST catalog API는 없다. 기존 ID가 가리키는 주체·목적은 바꾸지 않고 의미가 달라지면 새 ID를 쓴다. URL 접근·외부 연락은 수행하지 않는다.

## UI-03 — 작업 공간

### 영역

1. 상단: 목적·이번 목표·수신자·공개 범위, 현재 선택 판본, 현재 단계, 변경/취소.
2. 왼쪽: 이번 자료의 공개 질문, 저장 기준 적용 내역, 보류 항목.
3. 가운데: 현재 초안 또는 명확히 표시한 이전 초안. 제목·문장·표와 해당 선택의 연결을 볼 수 있음.
4. 오른쪽 접이식 패널: 근거, 내부 검토 설명, 도구 실행 요약, 판본 이력.
5. 하단: 현재 상태에 맞는 주 동작. `새 문서 작성`, `추가 질문 확인`, `검토 다시 실행`, `최종 파일 확인` 중 서버가 허용한 동작만 표시.

현재 결과가 없으면 `선택한 정보로 작성한 초안이 여기에 표시됩니다.`로 보여준다. 내부 분석 문장이나 원자료를 공유 초안처럼 자동 표시하지 않는다.

### phase의 사용자 표시

| 서버 phase | 화면 문구 | 기본 행동 |
| --- | --- | --- |
| `needs_analysis` | 자료를 분석할 준비가 되었습니다 | 분석 시작 또는 입력 수정 |
| `needs_decisions` | 공개 수준을 정해 주세요 | 질문 확인. 승인한 일부 정보로 미완료 초안 작성 가능 |
| `ready_to_generate` | 선택한 내용으로 새 문서를 만들 수 있습니다 | 새 문서 작성 |
| `processing` | 현재 단계 표시: 분석 / 새 작성 / 검토 / 파일 준비 등 | 현재 단계 확인·실행 취소. 선택 변경은 계속 가능 |
| `needs_attention` | 확인하거나 수정할 내용이 있습니다 | 원인별 재시도·후보 추가·편집·사람 의미 검토 |
| `ready_to_finalize` | 현재 선택 기준 검사가 완료되었습니다 | 최종 파일 확인 |
| `finalized` | 확인한 파일이 준비되었습니다 | 확정 파일 보기·복사·다운로드 |

실제 처리 단계는 job의 안전한 상태로 표시한다. 모델이 작성한 자유문장을 진행 상태로 그대로 사용하지 않는다. 처리 시간이 길어져도 가짜 퍼센트·완료 예정 시간을 보여주지 않는다.

내부 작업 이름만 고쳐도 첫 PoC는 판본을 올리고 이전 결과를 무효화한다. 변경 화면에서 다시 확인해야 한다는 안내를 보여준다.

### 변경과 동시 실행

공개 선택을 바꾸면 즉시 이전 결과 상단에 `이전 선택의 결과 — 새 선택으로 다시 작성해야 합니다.`를 표시한다. 기록 확인용 열람은 가능하지만 복사·다운로드 동작은 숨기거나 비활성화한다. 이전 초안을 현재 결과처럼 옆에 남기지 않는다. 직접 편집한 문장도 전체 새 작성에서 바뀔 수 있으므로 선택 변경 전에 이 영향을 간단히 알린다.

다른 창에서 선택이 변경돼 서버가 충돌을 반환하면 현재 편집 내용을 임시로 보존하고 최신 상태를 불러오게 한다. 최신 상태를 무조건 덮어쓰는 버튼은 제공하지 않는다. SSE가 끊기면 `연결을 다시 확인하고 있습니다.`를 표시하고 현재 서버 상태를 조회한다. 중간 화면 이벤트만 보고 확정 가능으로 바꾸지 않는다.

## UI-04 — 공개 수준 선택

카드에는 `필요한 정보`, `필요한 이유`, `근거 보기`, `선택한 경우 공개될 내용`, `공개하지 않는 내용`, `이번만 / 같은 조건에서 재사용`을 표시한다. 후보 자체에 미확인·가설이 있으면 이 표시도 유지한다.

결정 전에는 허용 선택을 미리 체크해 두지 않는다. 선택지 클릭은 미리보기를 만드는 행동이고 `이 방식으로 적용`이 실제 결정 저장이다. 저장 중 실패하면 선택 UI와 서버 결정의 차이를 보여주고 저장 완료로 표시하지 않는다. 여러 카드의 선택을 묶어 적용하는 경우 전체 배치가 하나의 원자적 변경이다.

| 선택 | 미리보기 예 | 주의할 공개 의미 |
| --- | --- | --- |
| A. 구체적인 데이터 없이 사실만 | `관찰된 구간에서 요청량이 증가했습니다.` | 세 번 관찰, 두 배 증가, 분당 등의 뜻을 추가하지 않음 |
| B. 추이만 보이게 나머지 마스킹 | 첫 번째: 기준 / 두 번째: 증가 / 세 번째: 증가 | 관찰 개수·순서가 공개됨. 새 표라는 표시 |
| C. 요청 정보 마스킹 | 남길 필드 선택 → 실제 셀과 단위를 포함한 새 표 | 정확한 값 허용은 이번 자료에만 적용. 재사용 저장 비활성 |
| D. 기타 (직접 입력) | UI-05에서 해석·계산된 결과 | 자유 입력 자체는 승인 규칙이 아님 |

카드에는 `나중에 결정`, `이번 결과에서 제외`, `근거 확인`을 항상 제공한다. required 후보를 제외하면 가능한 문의 범위와 부족한 정보를 설명하고 목적 축소 또는 대체 정보 선택으로 연결한다. 제외했다고 시스템이 같은 의미를 다른 후보로 몰래 다시 포함하지 않는다.

등록 템플릿의 필수 항목과 모델의 추천 항목을 다른 표시로 구분한다. 모델 추천을 제외했다고 무조건 확정을 막지 않는다. 필요한 목표 조건이 빠졌다면 보완 또는 명시적인 목표 변경을 안내한다.

원문 사용은 별도 영역이다. 실제로 포함될 구간을 보여주고 `이 구간을 이번 자료에 포함`을 선택한다. 특정 값 승인과 원문 구간 승인은 별개의 타입으로 표시한다. 원문 주변 전체 로그를 함께 허용하는 기본 체크는 없다.

수동 후보나 user_note를 추가하면 새로운 후보 집합을 만든다. 이전 선택은 참고로 표시하고 현재 후보에서 다시 확인하거나 유효한 재사용 기준을 적용한다. 메모를 적는 행위 자체가 공개 허용이 아니라는 안내를 한다.

## UI-05 — 직접 입력 조건

입력 예는 `규모는 숨기고 첫 관찰을 100으로 한 비율만 보여 주세요.`다. `적용할 내용 확인`을 누르면 해석된 조건, 사용할 변환, 실제 결과, 함께 드러나는 의미를 보여준다. 기본 예시 820/1160/1740의 정수 상대지수는 100/141/212다.

| 해석 결과 | 화면 동작 |
| --- | --- |
| supported | 실제 공개 미리보기와 `이 조건으로 적용` |
| ambiguous | 어떤 선택이 불명확한지 설명, 조건 수정 또는 지원 선택지로 이동 |
| unsupported | 지원 범위를 설명. 입력은 보존하며 임의 코드/정규식 실행 없음 |
| 계산 불가 | 0인 기준값·결측·잘못된 타입 등 구체 이유. 자동 제외/다른 계산으로 대체하지 않음 |
| 모델 오류 | 입력 보존, 재시도 또는 A/B/C 선택으로 복구 |

해석된 문장·미리보기·현재 자료 판본이 바뀌면 이전 적용 해시는 사용할 수 없다. 사용자 입력을 수정하면 기존 ‘적용’ 상태를 즉시 해제한다.

## UI-06 — 최종 확인과 내보내기

상단에 목적·이번 목표·수신자·공개 범위·현재 파일 판본·검사 모드(model/human)·재현 상태를 보여준다. 파일 목록은 실제 공유될 파일명·형식·크기로 구성하며 각각 실제 내용 또는 고정 등록 자산 설명을 열 수 있다. 내부 근거·진단·규칙 기록은 별도 내부 패널이며 공유 파일 목록에 섞지 않는다.

필수 표시는 미해결 결정 수, 원문·정확한 값 사용 항목, 현재 검사 상태, 필요한 재현 결과다. 문구는 `현재 선택 기준 검사 완료`를 사용한다. `안전한 파일`, `유출 위험 0%` 같은 보장 표현은 쓰지 않는다.

`이 파일들로 확정`을 누르면 서버가 현재 선택·판본·파일 해시·승인 유효성을 다시 확인한다. 성공 후 `본문 복사`, `패키지 다운로드`, 개별 파일 다운로드를 제공한다. `보내기`, `자동 제출` 버튼은 없다.

| 상황 | 표시 / 복구 |
| --- | --- |
| 파일 없음 | 작업 공간으로 돌아가 새 작성 |
| 보류/필수 결정 없음 | 해당 질문으로 이동. 확정 비활성 |
| 검토 필요 | 검사할 현재 파일과 재검토 버튼 |
| 재현 환경 없음 | `재현 실행 안 함 — 환경 없음`. 관찰 문의는 확정 가능 |
| 재현 확인이 목적상 필요하지만 미완료 | 원인 확인·재실행·사용자가 문의 목적을 좁히는 경로 |
| 검사 오류/승인 만료 | 해당 문제로 이동. 사람 확인으로 우회하는 버튼 없음 |
| 확인 중 선택 변경 | 최신 판본으로 돌아가 다시 확인 |
| 브라우저 복사 권한 거부 | 확정 파일 다운로드 안내. 복사 성공으로 표시하지 않음 |
| 다운로드 시 무효화 | `선택이 바뀌어 이 파일을 사용할 수 없습니다.`와 현재 작업으로 이동 |

## UI-07 — 이력과 삭제

전역 기록은 작업별 최신 상태를 표시한다. 작업 상세 이력은 시간순 이벤트로 사용자 결정, 적용 기준, 자동 작성·수정, 사람 편집·검토, 확정, 실패·취소·중단을 보여준다. event가 저장됐다는 사실과 model trace 본문 보관 여부는 구분한다.

이전 판본은 내부 열람 전용이다. 원자료·결정 근거를 비교할 수 있지만 이전 export를 현재 권한처럼 다시 사용하게 하지 않는다. 실행 메타데이터에 없는 시간을 0으로 표시하지 말고 `미측정`으로 표시한다.

`작업 삭제`는 대상 작업 이름을 보여주고 `DELETE` 입력 및 저장 기준이 남는다는 확인을 받는 패널을 연다. 삭제할 범위(원자료·초안·결정·확정 파일·실행 기록), 남는 범위(별도로 저장한 재사용 기준), 회수되지 않는 범위(이미 받은 파일·OS 백업)를 표시한다. 삭제 중 현재 실행은 취소된다. 완료 후 목록으로 이동하고 현재 작업 화면의 모든 데이터 참조를 지운다. 해당 작업의 기록도 같이 삭제하므로 삭제 내역에 원문을 남기지 않는다.

## UI-08 — 저장한 선택

기준 이름, 읽을 수 있는 적용 범위, 변환, 판본, 활성/만료/철회 상태, 최근 적용 작업을 표시한다. 정확한 원문·값을 저장한 사례를 재사용 규칙으로 표시하지 않는다. 수정은 새 규칙 판본을 만들며 이미 적용된 작업은 그대로 바뀌지 않는다. 철회 시 영향받는 현재 작업 수와 다시 확인할 항목을 표시한다.

규칙이 없으면 `반복해서 사용할 표현 기준을 공개 선택에서 저장할 수 있습니다.`를 표시한다. 새 작업에 맞지 않는 기준은 이유(수신자·자료 스키마·지침 판본 등)를 보여준다. 현재 작업에 저장 기준을 다시 적용하는 동작은 적용 대상과 미리보기를 확인한 뒤 `POST /api/v1/tasks/{id}/rules/apply`로 요청한다. 적용 성공은 새 revision을 만들며 현재 결과를 재작성한다. 유사한 자유문서 사례는 `참고 제안`으로만 표시한다.

## UI-09 — 실행 환경

`GET /api/v1/runtime`과 등록 catalog에서 실행 모드, 모델 식별자, 연결 상태, 등록 확장·검사기·재현 환경 상태, 앱 버전, 디버그 본문 기록 여부와 만료 정책을 보여준다. 전체 endpoint URL과 자격 증명은 표시하지 않는다. 인증 값을 조회·수정하는 입력은 없다. 연결 검사는 비민감 요청으로 수행하며 실제 업무 자료를 보내지 않는다.

fixture는 `개발용 예시 응답 — 실제 모델 실행 아님` 표시를 고정한다. live 실패 후 fixture로 자동 전환하지 않는다. 등록되지 않은 실행기나 지침을 화면에서 임의로 설치하지 않는다. 프로젝트·수신자 추가도 운영 설정 변경·검증·재시작 절차를 안내하며 화면에서 카탈로그를 직접 수정하지 않는다. 디버그 기록 활성화는 실제 원자료가 남을 수 있음을 표시하는 명시적 운영 설정이며 기본 off다.

## UI-10 — 로컬 접속

세션이 없으면 로컬 앱이 출력한 접속 토큰을 입력한다. 토큰을 URL query에 넣지 않는다. 토큰은 한 번만 교환되며 발급 후 5분까지 유효하다. 세션은 8시간 기본 유효하다. 만료 시 원래 작업 경로를 로컬에서 보존하고 새 토큰으로 다시 접속한 후 그 작업의 최신 상태를 읽는다.

오류는 토큰 오류·만료·사용됨을 안전한 문구로 안내하며 토큰 값을 다시 화면·로그에 출력하지 않는다. 접속되지 않은 상태에서 작업 제목·파일명·목록·설정 정보를 가져오지 않는다. 로그아웃은 세션을 닫지만 작업을 삭제하거나 현재 처리를 성공/실패로 바꾸지 않는다.

## 3. 접근성 및 표시 기준

- 키보드로 모든 선택·근거·편집·확정·취소를 수행할 수 있어야 한다. 모달/패널을 닫으면 이전 초점으로 돌아간다.
- 처리·저장 실패는 스크린리더가 알 수 있는 상태 영역으로 전달한다. 사용자 입력 중 자동 갱신이 초점을 빼앗지 않는다.
- 질문·선택·출력에 같은 A/B/C/D 표시를 사용해 어떤 선택의 결과인지 알 수 있게 한다.
- 시각은 사용자 화면에서 로컬 시간대와 함께 표시하고, 저장 시각은 서버 UTC다. 파일 내용의 시각 공개 여부와 UI 기록 시각은 별개다.
- `revision`, `CAS`, `artifact`, `skill` 같은 구현 용어는 기본 화면 제목에 쓰지 않는다. 세부 기록에서 필요한 경우 작은 기술 정보로 제공한다.
- 시스템이 지금 가능한 행동 목록을 서버에서 반환한다. 화면 비활성화만으로 권한을 집행하지 않는다.
