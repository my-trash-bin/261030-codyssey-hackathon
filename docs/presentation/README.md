# 발표자료 편집 기준

이 디렉터리는 제품의 설계/구현 전체를 정의하는 문서가 아니라 해커톤 발표용 패키지다.
원래 첨부한 자료를 바탕으로 현재 코드와 명확히 다른 기술 스택/완료 표현을 정리했다.

## 제품 가치와 해커톤 reframe

제품의 실제 가치와 해커톤에서 전달하는 임팩트는 별개로 다룬다. 실제 제품 효용에서는 별 의미가
없거나 부차적인 요소도 심사 맥락에서 큰 인상을 줄 수 있다면 중요한 요소로 배치/강조할 수 있다.
복잡한 과정을 인상적인 단계/이름/도식으로 재구성하거나 데모 장면을 전면에 놓는 것도 이 목적의
편집이다. 강조 순서가 곧 제품 요구사항의 우선순위나 검증된 고객 가치를 뜻하지는 않는다.

발표 효과를 위한 강조와 사실 표시는 구분한다. 현재 구현/설계 목표/후속 아이디어/fixture 연출/
실제 모델 결과를 각각 표시하며, 미완료 기능을 구현 완료로 바꾸거나 측정하지 않은 효과를 실적으로
적지는 않는다. 관련 표현 판단은 [ISSUES](ISSUES.md)에 모으고 제품 의도를 발표에 맞춰 역으로
바꾸지 않는다.

1/2차 심사 배점, 7분 발표/5분 질의응답 운영, 발표 순서/시장 산식과 출처/10건 비교 실험 실행은
[발표 가이드](GUIDE.md)를 따른다. B2B 포장 여부는
[결정 PRES-DEC-01](../decisions.md)에 확정했으며 실제 제품 BM 변경과 구분한다.

개별 HTML의 `<!-- // TODO: [PRES-번호] ... -->`는 인접한 설명 중 현재 구현되지 않은 범위나
미결 편집 이슈를 표시한다. 댓글이 보이지 않는 발표 화면에는 계획 포함 표시를 함께 두었다.
검색은 `rg -n '// TODO:' docs/presentation --glob '*.html' --glob '!SafeHandoff_발표자료_통합.html'`처럼 한다.
통합 HTML에도 생성 과정에서 같은 주석이 복제되므로 발표 파일을 고칠 때는 개별 HTML에서 찾되, 판단 근거는 위 외부 정본을 확인한다.

## 완료 범위의 읽는 법

발표자료 안에 별도 기능 완료 목록을 복제하지 않는다. 현행 구현/미연결 범위는 위 루트 README/
API를, 앞으로 구현할 범위는 다음 라운드/기능 계획을 따른다. 내부 저장/코어 함수/CLI의 구현이
전체 UI 종단간 연결 완료를 뜻하지 않는다. 발표에서 계획 기능을 소개할 때도 이 구분을 유지한다.

정본과 다른 방향이나 사용자 보완이 필요한 부분만 ISSUES에 차이로 기록한다. 원래 문서를
발표 문구에 맞춰 역으로 바꾸지 않으며, 발표의 실제 문장을 근거로 구현 완료를 판단하지 않는다.

## 도구 설치와 재생성

처음에는 mise만 있으면 된다. mise 자체 설치는 [공식 설치 안내](https://mise.jdx.dev/getting-started.html)를
따른다. 저장소 루트에서 실행한다.

```sh
mise trust
mise install
mise run setup-presentation
mise exec -- just build-presentation
```

mise가 고정한 Node/pnpm/just/Python을 설치하고, setup-presentation이 잠금 파일의 Playwright/
한글 글꼴 패키지와 해당 Chromium을 준비한다. mise를 셸에 활성화했다면 마지막 명령은
`just build-presentation`으로 줄일 수 있다. just가 없어도 `mise install`과 mise task를 먼저 쓸 수 있다.

Linux에서 Chromium 시스템 라이브러리가 없으면 별도로 실행한다. 배포판 패키지 설치에는
관리자 권한이 필요할 수 있다. [Playwright의 공식 설치 절차](https://playwright.dev/docs/browsers#install-system-dependencies)를
사용하며 일반 빌드에서 OS 패키지를 임의로 설치하지 않는다.

```sh
mise run setup-presentation-system
```

`just build-presentation`은 build_combined_deck.py의 SLIDES에 있는 표지와 본문 10쪽을 읽어 **통합 HTML과 PDF**를 생성한다.
2쪽은 상단 페르소나와 두 가지 문제 스토리라인, 3쪽은 해결 솔루션 / 유저 플로우다. 4쪽에는 비교 항목을 세로로 읽는 서비스 차별점 표를 배치하고 SafeHandoff 열을 강조한다. 공개 승인, 승인 사실 기반 재작성, 검수/대조를 핵심 차별점으로 설명한다. 제품군의 대표 접근 방식과 서비스 전체 방향을 비교하며 현재 개발 범위는 5쪽에 구분한다.
5쪽은 활용 AI 기술 및 직접 개발 범위다. 모델/API, 승인팩 작성/규칙 검사/LLM 대조, 공개 표현의 결정적 변환을 명시한다. 협업/검사 도구와 네 개발 영역을 함께 표시하며, 후보 AI 분류/공개 수준 자동 제안/산업별 프로필은 완료 기능으로 설명하지 않는다. 기존 하단의 규칙 설명/DB 프로필 예시는 제외한다.
이어 6쪽 기술 스택, 7쪽 팀원 역할, 8쪽 외부 자원 활용 내역, 9쪽 박지훈 캐릭터를 포함한 사용 전후 기대효과, 10쪽 온프레미스 오픈소스/기관 협력 확장 구상을 배치한다. TAM/SAM/SOM과 가격/시장 규모 가정은 발표에서 제외한다.
별도 AI 파이프라인, 목차/프로젝트 배경/타겟 페르소나/서비스 플로우/서비스 아키텍처/AI기술 개발범위의 이전 대안 HTML은 보존하고 통합본에 넣지 않는다.
개별 HTML은 생성 대상이 아니다. 모든 HTML은 제품 정본이 아닌 발표용 파생 자료라는 점은 같다.
통합 HTML은 현재 저장소 정책대로 추적하며 PDF는 .gitignore로 제외한다. 이미 추적하던 PDF도
추적 해제했으므로 필요할 때 로컬에서 빌드한다.

설치에는 네트워크가 필요하지만 준비 후 빌드는 로컬 파일/설치한 Chromium/한글 글꼴만 사용한다.
렌더링 중 외부 요청은 차단한다. Noto Sans KR Variable의 버전과 라이선스는 pnpm 의존성에
포함하며 시스템 한글 글꼴이나 별도로 받은 .local 글꼴에 의존하지 않는다. 통합 HTML을 일반
브라우저에서 직접 열 때는 시스템 글꼴을 사용한다.

빌드는 이미지 로딩/11개 슬라이드/PDF 11쪽을 검사하고, 실패하면 이전 PDF를 덮어쓰지 않는다.
내용 잘림/문구 의미는 발표자가 별도 확인한다. HTML만 만들 필요가 있을 때는
`mise exec -- python docs/presentation/build_combined_deck.py`를 사용할 수 있다. 브라우저 캐시/
node_modules/Python 캐시/PDF는 Git에 넣지 않는다.

이전 CDP 영상 연출 브랜치의 참고 자료는 [시연 안내](../demo.md)에서 구분해 설명한다.
`just preview-demo-video`로 과거 fixture 영상을 로컬에서 확인하며 현행 앱 실행과 구분한다.
