# 발표자료와 외부 정본의 차이

2026-10-31 대조 기준. 제품 전체 계획은 [spec](../design/spec.md)/[기능 문서](../features)가 정본이고,
현재 구현은 [루트 README](../../README.md)/[API](../design/api.md)가 정본이다. 이 파일은 발표와 그
정본 사이의 차이/사용자 보완 방향만 관리한다. 제품 계약 자체를 여기서 변경하지 않는다.

## PRES-01 / 분석 Engine 구현 / 질문/공개 미리보기/UI는 후속

[F02 근거 추출](../features/02-evidence-analysis.md)의 근거 파서/후보 검증/analyze() 호출은 이후 구현했다.
서버 candidate_set 채택/공개 제안/미리보기/묶음 질문/화면 연결은 여전히 후속이다. 발표의 전체
로그 분석/공개 선택 흐름을 완료로 표시하지 않는다. 승인 facts의 작성/검토와 분석 후보 생성은
별도 호출이며 분석 결과가 자동으로 공개 승인이나 writer 입력이 되지 않는다.

## PRES-02 / 전체 UI/동시 갱신/근거/반출 - 계획에는 있으나 미완료

[화면 구조 기준](../design/ia.md)은 목표이며 현재 동작을 증명하지 않는다. 전체 공개 결정 저장/본문/
표/설명 동시 갱신/문장별 근거/최종화/복사/다운로드는 연결 후 확인할 범위다. 현재 메모 저장/조회,
코어 상태 확인과 구분한다. 팀원 소개의 기능 목록도 기여의 완료 증거가 아니라 담당 범위로 표기한다.
개인별 실제 기여를 확인하지 않고 새로 배정하거나 완료를 추정하지 않는다.

## PRES-03 / Rule과 에이전트 SkillPack 분리 - 용어 정리와 후속 설계

발표는 기존 공개 결정의 재사용 데이터와 실제 에이전트 스킬을 모두 '스킬'로 불렀다. 다음 구분으로
편집한다. [F06](../features/06-decision-reuse.md)/[F07](../features/07-domain-extensions.md)의
각 계약을 복제하거나 합치지 않는다.

- **공개 기준 / Rule**: 목적/수신처/자료 조건에 묶인 승인 결정의 재사용 데이터. 새 입력에서
  등록된 변환을 다시 계산하고 적용 근거를 남긴다. 과거 실제 값/원문/허용 권한을 다른 자료나
  다른 회사에 자동 승계하는 에이전트 스킬이 아니다. Rule 저장/매칭 엔진은 후속이다.
- **에이전트 스킬 / SkillPack**: SKILL.md/역할별 지침/공개 제품 계약/양식/도구 참조를 묶은 팩.
  Agent Skills의 파일 구조 관례를 참고하되 현재 manifest/digest/실행 권한 계약은 SafeHandoff
  자체 계약이다. 팩 로딩이 곧 모델 지침 주입/실행 권한 부여/공개 승인은 아니다.

사용자가 보완한 방향: 특히 오픈소스 프로젝트의 공개 제품 지식/재현 절차 등은 **공개 스킬로
공유할 수 있게 한다**. 기업 A/B가 공개 팩을 검토/설치해 활용하는 그림 자체는 이 방향과 맞는다.
회사 원자료를 한곳에 수집하거나 사내 공개 결정을 타 기업에 자동 적용하는 그림과는 다르다.

6쪽(AI/직접 개발 범위)의 회사별 DB 프로필 표는 발표용 설계 예시이며 해당 기능과 계약은 아직 없다. 화면에
'설계 반영 / 가상 예시'로 표시한다. 질문 답변은 [가이드](GUIDE.md)를 따른다.

현재 [도메인 확장 계약](../design/extensions.md)의 ToyRecord 연결은 설치된 로컬 팩 검증/재현을 구현한 단계다.
공개 배포/탐색/설치 UX는 아직 없다. 공개 스킬의 포함 파일/라이선스/출처/버전/검토/설치 pin/
등록 도구/업데이트 정책은 후속 계약으로 정리해야 한다. 비공개 원문/정확값/자격 증명/사내 Rule을
공개 팩에 자동 포함하지 않는다. 실제 외부 게시나 마켓 구현은 이번 문서 수정 범위가 아니다.

## PRES-04 / 3자 대조/제약 복원 - 목표와 현행 검토 구분

[에이전트 역할 계약](../design/agent-workflow.md)의 검토 grounding 구현이 현재 범위의 정본이다. 원문/선택 기준/
초안을 모두 대조하는 전체 흐름이나 누락된 사내 제약의 자동 추출/복원을 완료했다고 표시하지
않는다. PyTorch 분류기는 현재 구현도 필수 계획도 아니므로 기술 스택에서 제거했다.

## PRES-05 / 인증/격리/배포 - 범위와 보장 분리

현재 고정 toy Docker 실행 격리와 앱 전체 원자료 처리 환경의 인터넷 차단은 다른 범위다.
[보안 설계](../design/security.md)를 완료 사실로 읽지 않는다. 앱 인증/작업 소속 검증의 전체 연결/
원자료 작업 환경 격리/CI/CD/PR Preview는 실제 확인 전 TODO로 둔다. Tenant/RLS는 현재
스택이 아니며 공개 스킬 공유를 위해 중앙 멀티테넌트 원자료 서비스를 도입한다고 추정하지 않는다.
기술 스택은 [현재 아키텍처](../design/architecture.md)/[루트 README](../../README.md)/패키지 설정을 참조하며 발표 HTML은 정본이 아니다.

## PRES-06 / A~D와 AI 생성 선택지 - UX/계약 결정 필요

현행 UI의 A~D는 사실/추이/마스킹/기타 직접 입력이며 비율은 D의 예시다. 발표 일부의
'사실/추이/마스킹/비율 4단계'와 같은 정의가 아니다. 다만 **AI가 상황에 맞는 공개 선택지를
자동 생성/제안할 수 있다는 점**을 반영해야 하므로, A~D를 영구적인 네 개의 공개 수준이나
엄격한 민감도 순서로 확정하지 않는다.

후속 결정은 다음과 같다. AI가 제안하는 내용과 서버가 계산/검증 가능한 표현 계약을 구분하고,
항목별 필요한 정보/목적/미리보기/부족한 단서를 표시한다. 사용자가 확인/적용하기 전에는 공개
허용이 생기지 않는다. AI 제안과 직접 입력 모두 기존 승인/계산/재검토 경계를 통과해야 한다.

선택지 수와 문자 부여 방식, 공통 프리셋과 동적 제안의 관계, D 직접 입력의 고정 위치, 지원하지
않는 제안의 거부/질문 동작은 아직 미정이다. [화면 구조 기준](../design/ia.md)은 구현 기준으로
유지하고 후속 승인에서 spec/계약/UI를 함께 갱신한다. 이번에는 모델이나 앱 동작을 바꾸지 않았다.

## PRES-07 / 보안 보장 문구/비교 기준 - 발표 표현 검토 필요

[의도 INT-02/05/11](../../intent.md)와 [가치 비교 기준](../product/prd.md)이 정본이다.

- '원본 유출 걱정 없이', '원본 숫자 노출을 원천 방지', 'Zero'는 보장으로 읽힐 수 있다.
  '승인한 정보로 새 공유본을 작성하고 사람이 최종 확인', '현재 선택 기준으로 검사'처럼 관찰
  가능한 설명으로 바꾸는 편집안을 검토한다. 승인된 정보도 맥락을 드러낼 수 있다.
- '일반 AI는 외부에 원본부터 전송한다'는 비교는 사내 모델을 사용하는 대조군을 배제한다.
  같은 사내 모델/자료/공개 기준/제품 지침/이전 결정/도구/수정 기회를 제공하는 기준과 맞춰야 한다.
- 차별점 표는 특정 제품명을 빼고 유형별 일반 특징으로 바꿨다. 외부 제품 기능을 조사하지 않았으므로 특정 제품의
  한계로 말하지 않는다.
- 준비 시간/재질문/노출 감소는 기대효과다. 실제 사람 작업량/수신자 효용 측정 전 성과로 발표하지
  않는다. fixture/live 모델/사람 완성/실제 Docker 결과는 분리한다.

이 표현들은 TODO와 계획 포함 표시로 추적한다. 경쟁사 조사나 보장 문구 전체의 최종 카피 확정은
이번의 명확한 기술 스택 수정과 분리해 남긴다.

## PRES-08 / B2B 포장은 결정됨 / 실제 사업 방향 변경은 별도

**월 구독료/매출형 TAM/SAM/SOM/중앙 SaaS 사업**은 [INT-07/12](../../intent.md)와 다르다.
[PRES-DEC-01](../product/decisions.md)에 따라 B2B 솔루션처럼 있어 보이게 감싸는 해커톤 발표 포장은
유지하기로 결정했다. 심사위원의 전문 수준을 알 수 없는 상황에서 기업 문제/기술/시장성을 하나의
그림으로 전달하려는 선택이다. 따라서 B2B 표현 자체를 미결 TODO나 삭제 대상으로 취급하지 않는다.
실제 구독 BM/중앙 SaaS 채택은 별도이며 intent를 수정하지 않았다. 수치 근거 보완은 PRES-09,
발표 동선은 [가이드](GUIDE.md)가 담당한다.

**기업 간 비공개 승인 자동 승계**는 [INT-09](../../intent.md) 및 F06의 현재 범위와 다르다.
공개 SkillPack 공유는 사용자 보완 방향으로 구분했으므로 이 항목과 함께 금지하거나 미승인 사업
모델로 분류하지 않는다. 원자료의 중앙 수집/자동 공개 승인/자동 외부 제출까지 따라오는 것도 아니다.

**가림 위주의 로그 보안 제품**이라는 설명은 [INT-02/05](../../intent.md)의 공유 자료 새 작성
도구라는 가치와 다르다. 마스킹은 승인된 표현 방식 중 하나다. 본문/표/예제/확인할 질문을 준비하는
가치와 혼동하지 않도록 정리할 필요가 있다.

확장 페이지의 시장 수치와 산출 근거는 검증되지 않은 발표 가설로 남긴다. 외부 통계와 인용 이미지의
정확도/시점/사용 조건 역시 이번 코드/계획 대조로 검증했다고 보지 않는다.


## PRES-09 / 시장 규모의 근거 - 단순 산식과 도입률 보완 필요

발표 10쪽은 조직별 온프레미스 적용과 오픈소스/정보보호 생태계 확장으로 바꿨다. 아래 시장 산정 기록은 발표에서 제외한다. [발표 가이드](GUIDE.md)의 재산정을 따른다. 아래는 이전 국내 기업 기준 계산이다. 2026-10-31에 공개 통계로 다시 계산했다. 모집단 39.8만 곳, TAM 연 약 9,550억, SAM 연 약 592억,
SOM 연 약 30억 원이다. 기존 15만 개사/12배/4.32조는 출처가 없어 제거했다. 남은 약점은 월 20만 원과
도입률 5%가 여전히 가정이라는 점, AI 활용률을 소규모 기업까지 넓혀 적용한 점이다. AI 활용률은 보도로만
확인했고 원 보고서 대조는 하지 못했다. 산식과 출처는 [발표 가이드](GUIDE.md)의 시장 규모 절이 담당한다.
시장 규모가 검증됐거나 실제 매출이 있는 것처럼 사용하지 않는다.

## PRES-11 / 외부 자원 표 - 확인 범위

표의 버전/라이선스는 잠금 파일/패키지 정보/각 프로젝트 공개 페이지로 확인했다. 네이토 API, 사전 보유 코드 없음,
페르소나 이미지 Gemini 생성, AI 도구 목록은 2026-10-31 사용자 확인값이다. 네이토 API의 이용 조건과 캡처 이미지의
사용 허가는 검증하지 않았고 1/2쪽에 원 출처를 표기했다. 화면 디자인은 사용자가 CSS와 ChatGPT로 작성했다고 확인해 design-pick을 표에서
뺐다. 루트 README의 design-pick 기반 설명과 달라 작성 경위 확인이 남아 있다. QG(@slop-lab/qg)는 2026-10-25에 npm에
처음 게시됐다. 팀원이 만든 도구라면 표의 사전 보유 코드 행으로 옮겨야 하며 사용자 확인이 필요하다.

## PRES-10 / 기대효과의 근거 - 10건 비교 실험 구분 기록

슬라이드에서 'Zero', '원클릭 갱신', 숫자 없는 막대를 뺐다. 가상 로그 10건/정답지/측정 도구를 만들었고
사람 작업 시간 측정값은 [가이드의 실험](GUIDE.md)을 실행해야 채워진다. 결정적 코드/파이프라인 비교(직접 정규식 가림 vs 미검토 원문 AI vs SafeHandoff 승인팩/grounding/검토)는 해커톤 당시 `tools/value-comparison.mjs`로 실행해 보고서에 기록했으나, 그 도구와 보고서는 2026-10-31에 저장소에서 제거했다([decisions.md](../product/decisions.md)).
참여자 스톱워치 작업 시간 측정과 구분한다는 원칙은 유지한다. 9쪽의 41개->0개와 필수 단서 32/32개는 당시 가상 10건의 고정 응답 코드 검증값이었다. 시간/비용은 10분->5분/건, 월 100건, 인건비 3만원/시간을 가정한 계산 예시(50%, 월 25만원)로 표시하며 실측 성과로 말하지 않는다. 재질문/반복을 묶어 문제는 3개로 정리했다. 9쪽은 세 열의 사용 전후 비교와 박지훈 삽화, 10쪽은 온프레미스 오픈소스와 기관/개발자 협력 구상으로 나눴다. 목업/부분 구현/실제 동작을 섞어 성과를 만들지 않는다.
일부 사례의 노출 잔존 0건도 보안 Zero 보장으로 일반화하지 않는다. 의미 판정은 사람의 기준으로
남기며 결정적 코드 회귀 테스트에 넣지 않는다.

## PRES-12 / 3쪽은 그림 중심의 가상 사용 시나리오

3쪽은 2쪽의 문제 경험 다음에 서비스 시작/AI 단서 제안/공개 사실 승인/새 작성/최종 확인/조사 가능한 문의 전달을 보여 주는 6컷 스토리보드다. 앞 장의 문제를 반복하지 않고 서비스 사용으로 문의 준비가 달라지는 흐름을 설명한다. 장면 전체는 가상 사용 개념도이며 실제 모델 출력/외부 발송/장애 해결 실적이 아니다. 현재 개발 범위는 5쪽에서 별도로 구분한다. 첫 요청 처리 완료/중복 생성 여부는 미확인으로 유지한다. 실제 실행 결과를 소개하려면 별도 실행 근거를 확인하고 시나리오 그림과 구분한다.
