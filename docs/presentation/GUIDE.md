# 해커톤 발표 가이드

제품 의도/요구사항/구현 사실의 정본은 [README의 외부 문서 안내](README.md)를 따른다.
이 문서는 말하는 순서와 근거 준비를 위한 발표용 가이드다. B2B 솔루션 포장은
[결정 PRES-DEC-01](../decisions.md)에 근거한다. 심사위원의 전문 수준을 단정하지 않고, 서로
다른 배경에서도 문제/기술/사업성의 연결을 빠르게 이해할 수 있게 기업 솔루션 언어로 감싼다.

## 심사 배점과 7분 발표 / 5분 질의응답 운영

- **1차 서면 심사 (각 20점, 총 100점)**: (1) 기획의 구체성(문제/목표 사용자/실행 및 확장 계획) (2) 기획의 창의성(단순 가림이 아닌 공개 범위 선택/새 공유본 작성) (3) 기술 완성도(직접 개발한 계약/검증/변환/재현 경계와 외부 모델 호출 구분) (4) 성과 및 실용 가능성(재현 가능한 데모와 10건 3자 비교 실험) (5) 팀 구성 및 협업 체계(5인 역할별 산출물과 저장소 통합).
- **2차 대면 심사 (각 25점, 총 100점)**: (1) 아이디어 전달력 및 문제 해결력 (2) 기술 구현력 및 라이브 시연 완성도(실제 앱/fixture/녹화 재생 구분) (3) 적용 가능성 및 확장성(현재 범위와 확장 가설 분리) (4) 발표 구성 및 팀워크.
- **발표 시간 배분 (발표 7분 = 설명 4분 이내 + 라이브 시연 3분 이상, 질의응답 5분 별도)**:
  - `0:00~0:45` 문제와 목표 사용자 / `0:45~1:35` 해결 방식(AI 제안 -> 범위 확인 -> 새 공유본) / `1:35~2:20` 직접 개발 범위 / `2:20~5:20` 라이브 시연 1과 2(합계 3분 확보, 장애 시 확인된 상태 설명 후 백업 전환) / `5:20~6:15` 적용 가능성 및 비교 실험 / `6:15~7:00` 확장(`Rule`/`SkillPack`)과 마무리.

## 핵심 메시지와 동선

"기업이 외부 도움을 요청할 때, 무엇을 공개할지 정하고 공유 자료를 다시 준비하는 수고를 줄인다"로
시작한다. 공개 범위를 사람이 확인한다는 축을 유지하고, 화면의 모든 버튼이 연결됐다고 설명하지 않는다.

| 구간 | 전달할 메시지 | 발표 근거/주의할 구분 |
| --- | --- | --- |
| 문제/사용자 | 문의하려고 자료를 가리고 다시 쓰는 반복 작업 | 뉴스는 문제의 배경. 제품의 효과 측정 자료와 구분 |
| 흐름 | AI 제안 -> 사람이 범위 확인 -> 새 공유본 작성/검토 | 전체 흐름은 설계 목표. AI 생성 선택지와 A~D는 ISSUES PRES-06 참조 |
| 기술/데모 | 승인 정보의 작성/검토, 결정적 변환, 고정 toy 재현 | 현행은 외부 README/API가 기준. 실제 실행/fixture/녹화 재생을 구분 |
| 재사용/확장 | 공개 기준 데이터와 공개 에이전트 스킬 | 사내 Rule의 승인 권한과 공개 SkillPack 설치를 섞지 않음 |
| 기대효과 | 준비 시간/누락/재질문 감소를 검증할 수 있다 | 측정 전에는 기대/가설. 작은 비교 실험으로 근거 준비 |
| 시장/마무리 | 기업 업무에 적용할 수 있는 솔루션 형태로 확장 가능 | B2B 포장은 의도된 발표 전략. 시장 숫자는 출처/가격/도입률 가정 명시 |

실제 제품 효용에서 비중이 작아도 인상적인 실행 경계/도식/예제를 강조할 수 있다. 실제 가치 평가와
발표 강조 순서는 별개다. 현재 구현/향후 기능/사업성 가설의 구분은 유지한다.

## 확장 가능성 (발표 10쪽)

온프레미스에 설치/운영하는 오픈소스 프로젝트로서 개발자 참여, 정보보호 현장 검증, 공공 확산의 협력 생태계를 지향한다. 기관 로고는 협력 확장 구상에 사용하며 실제 협약/후원으로 설명하지 않는다. BM/시장 규모/가격 가정은 발표에서 제외한다.

### 이전 시장 산정 기록 (발표 제외)

페르소나가 개발자이므로 기업 수가 아니라 사람 수로 계산한다. 환율은 1달러 1,400원이다.

| 구분 | 계산 | 값 | 근거 |
| --- | --- | --- | --- |
| TAM | 전문 개발자 3,650만 명 x 연 $228 | 약 $83억 (11.6조 원) | [SlashData](https://www.slashdata.co/post/global-developer-population-trends-2025-how-many-developers-are-there) 2025 초 |
| SAM | TAM x AI 일일 사용 51% = 약 1,860만 명 | 약 $42억 (5.9조 원) | [Stack Overflow 2025](https://survey.stackoverflow.co/2025/ai) 전문 개발자 |
| SOM | SAM x 0.1% = 약 1.9만 명 | 약 $424만 (59억 원) | 3년 차 도입 가정 |

- 단가 $228은 GitHub Copilot Business 정가 $19/인/월을 12개월로 곱한 참조값이다. 지불 의사는 검증하지 않았다.
- 개발자 수는 추정 방식에 따라 차이가 크다. JetBrains의 1,960만 명으로 계산하면 TAM은 약 $45억이다.
- 기술지원 전담 인력은 세계 통계를 찾지 못해 넣지 않았다.
- "외부 문의가 잦은" 비율은 통계가 없어 SAM에 반영하지 못했다. 실제 시장은 SAM보다 좁을 수 있다.

슬라이드의 숫자는 매출 전망이 아니라 공개 통계와 명시한 가정으로 계산한 시나리오다. 2026-10-31에
아래 산식으로 교체했다. 기존 15만 개사/12배/4.32조는 출처를 찾지 못해 쓰지 않는다.

| 모집단 | 소상공인 제외 중소기업 392,054 + 중견기업 5,868 (둘 다 2023) | 397,922곳 | 통계 |

## 기대효과를 방어할 작은 실험

슬라이드에서 'Zero', '원클릭 갱신', 수치 없는 막대를 뺐다. 값은 아래 실험을 실행해야 채워지며 그 전에는
기대 방향과 지표만 보인다. [가치 비교 정본](../prd.md)의 같은 조건 원칙을 따른다.

실행 방법: 실제 앱과 모델을 띄운 뒤(`just app`) 아래를 실행한다. 두 사람이 A조와 B조를 하나씩 맡아 각자
10건을 처리하면 각 사례가 두 방식으로 한 번씩 측정된다. 한 사람이 같은 로그를 두 번 보지 않는다.

```sh
node tools/effect-measure.mjs serve   # http://127.0.0.1:8090 에서 조별로 진행
node tools/effect-measure.mjs apply   # 슬라이드에 반영 후 just build-presentation
```

시간이 없으면 화면에서 `3건 (예비 측정)`을 고르고 `apply --partial`로 반영한다. 슬라이드에 '예비 측정 3건'으로 표시되며,
일반화하지 않고 표본이 작다고 말한다. 숫자는 실제로 잰 값만 넣는다.

사례와 정답지는 [evaluation/effect-compare/cases.json](../../evaluation/effect-compare/cases.json), 측정표는
evaluation/results/effect-measurements.csv다. apply는 연출 앱 결과가 섞였거나 10건이 모자라면 거부한다.
analyze()가 없어 SafeHandoff 쪽은 미리 준비한 후보 사실에서 고른다. 사실 후보를 찾는 수고가 빠지므로
SafeHandoff에 유리한 조건이며, 슬라이드에 '부분 파이프라인'으로 표기하고 발표에서도 그렇게 말한다.
유출 금지 항목은 문자열로 자동 집계하고, 문자열로 안 잡힌 노출과 필수 단서는 참여자가 판정한다.

실험 원칙은 다음과 같다.

1. 가상 로그 10건과 같은 문의 목적/수신처/공개 조건/필수 단서를 고정한다. 각 로그의 공개 금지
   항목과 반드시 남겨야 할 단서를 사람이 사전에 표시한다. 실제 회사 자료를 새로 수집하지 않는다.
2. 같은 자료를 직접 준비하는 방식과 SafeHandoff로 준비하는 방식으로 처리한다. 실행 순서를
   번갈아 학습 효과를 줄이고 참여자/날짜/코드 판본/지침/모델/모드를 기록한다. 일반 AI 비교를
   추가하면 같은 사내 모델/기준/지침/도구/수정 기회를 제공한다.
3. 건별 사람 작업 시간, 모델/서버 대기 시간, 총 경과 시간을 분리한다. 가리지 못한 금지 항목 수와
   지워서 잃은 필수 단서 수를 따로 세고 수정 횟수/최종 통과 여부도 남긴다. 가림 개수만으로 효용을
   판단하지 않는다. 의미 판정은 사전 기준에 따른 사람 검토이며 LLM 평가/문장 정규식 회귀로 대체하지 않는다.
4. 현행 UI에서 연결되지 않은 단계는 성공 처리하지 않는다. API/CLI와 사람이 조립한 결과라면
   그 개입을 기록하고 '부분 파이프라인 실험'으로 발표한다. 목업의 클릭 수를 사람 작업 시간으로
   대신하지 않는다. 실패/보류도 10건의 분모에 포함하고 미완료 사례의 시간을 임의 보정하지 않는다.
5. 원자료별 측정표를 남기고, 같은 완료 조건을 충족한 사례의 중앙값/범위와 전체 성공/실패 수를
   함께 제시한다. '10건에서 놓친 금지 항목 0개'가 나와도 일반적인 유출 Zero 보장으로 확대하지 않는다.

아직 이 10건 실험을 실행하지 않았으며,
수치나 감소율을 이 가이드에서 만들어 넣지 않는다. 실제 로그는 로컬 평가 결과에, 발표에는 집계와
가상 데이터 범위만 반영한다. 기존 Docker 성공은 시간 절감/사용자 효용의 증거가 아니다.

9쪽에는 시간/비용의 계산 예시를 실측과 구분해 표시한다. 10분에서 5분으로 줄어든다고 가정하면
작업 시간은 50% 감소한다. 월 100건/인건비 3만원/시간 가정의 절감액은
100건 x 5분 / 60분 x 3만원 = 월 25만원이다. 이 가정은 참여자 측정값이나 검증된 효과가 아니다.
공개 금지 항목 41개->0개, 필수 단서 32/32개는 가상 10건의 고정 응답 코드 검증으로 구분한다.

## 시연과 설계의 구분

4쪽은 서비스 차별점 비교표다. 5쪽에서 활용 AI/API/적용 방식과 직접 개발 범위를 구분하고, 별도 AI 파이프라인은 통합본에서 제외한다. 7쪽은 배지 없이 문장으로 구현과 설계를 구분한다. 6쪽 구조도는 실선(앱에서 실행)과 점선(CLI로 실행)으로 나눈다. 시연은 앱/API로 지금 실행되는 것(메모 저장/조회, 승인 사실로 작성/검토),
구현은 라이브러리/CLI로 동작하지만 화면에 없는 것(표현 변환, Docker 재현, 팩 검증/등록)이다. 후보 분류/공개 수준 제안 API는 현재 코어에서 미구현이며, 산업별 민감 기준 자동 적용도 추가 개발이다. 설계 반영은 아직 없는
것(분석/묶음 질문, 동시 갱신, Rule 매칭, 인증, 회사별 DB 프로필)이다. 발표 시연은 첫 단계만 보여 준다.

## 질문 대응과 편집 주석

- "보안 서비스인데 다른 회사와 스킬을 공유하나?": 스킬에는 원문이 아닌 규칙만 담긴다. 오가는 것은 제품 지침/
  질문/양식/검사 규칙이고 원문/실제 값/사내 승인 결정은 회사 안에 남는다. B가 설치해도 A의 공개 허가는
  넘어오지 않으며 B의 담당자가 새로 승인한다.
- "팩에 비공개 값이 섞이지 않게 어떻게 막나?": 지금은 설치 담당자의 검토와 파일 지문 고정이다. 내용 자동
  검사는 설계 단계이므로 자동으로 막는다고 말하지 않는다.
- "회사마다 DB가 다른데 맞출 수 있나?": 규칙은 공통으로 두고 컬럼 연결은 회사별 프로필로 분리하는 설계다.
  슬라이드 표는 가상 예시이고 프로필 기능은 아직 없다. 지금 있는 것은 팩 구조/검증과 가상 제품 팩 2종이다.
- "백엔드 언어가 뭔가?": 프론트/백엔드/AI 엔진 모두 TypeScript(Node 24)다. 모델 추론은 LLM에 OpenAI 호환
  HTTP로 위임하며 Python 서버는 없다. Go는 재현용 toy 이미지에만 쓴다.
- "원본이 밖으로 안 나간다면서 외부 API를 쓰나?": 시연 데이터는 전부 가상이고 네이토 API에는 승인한 사실만
  보낸다. 도입 시 OpenAI 호환 사내 LLM이면 model-adapter의 연결 설정만 바꾼다. 호환되지 않으면 어댑터 구현이
  필요하다. 사내 LLM 연결과 인터넷 차단 환경은 아직 시연하지 않았으므로 구현됐다고 말하지 않는다.
- "왜 B2B 솔루션인가?": 기업의 자료 준비 문제를 설명하는 발표 프레임이다. 현행 제품은 내부
  설치 오픈소스이며 구독료는 시장성 시나리오의 가정이라고 설명한다.
- "다 구현했나?": 정본의 실제 연결 범위를 답하고 목업/계획/실제 실행을 구분한다.
- "기존 AI보다 얼마나 좋은가?": 동일 조건 실험의 측정값만 답한다. 미측정이면 검증 계획을 말한다.
- "정보 유출이 0인가?": 사람의 공개 결정과 현재 기준 검사로 준비를 돕는 것이며 보장하지 않는다고 답한다.

`// DECISION: [PRES-DEC-01]`은 B2B 포장의 의도된 편집 결정을 뜻한다. 구현 누락 TODO가 아니다.
`// TODO: [PRES-번호]`는 실제 미완료/근거 미확인 항목이다. 같은 페이지에 두 종류가 함께 있을 수
있다. HTML에 결정을 다시 길게 적지 않고 외부 decisions 문서를 참조한다.
