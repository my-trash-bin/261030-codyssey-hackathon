# 핵심 사용자 흐름 - 단계의 역할과 선택 근거

기준일: 2026-11-01. 문서 검토·개편 설계이며 구현 완료나 추가 기능 승인을 뜻하지 않는다.
정본 의도는 [intent.md](../../intent.md), 기존 UI·API 구현과의 차이는 아래 관련 문서에서 구분한다.

## 읽는 기준

사용자는 어떤 도움을 받고 싶은지 설명하고, 원자료를 이해한 뒤 공개할 정보와 표현을 고른다.
앱은 승인 정보로 새 공유 자료를 작성·검토하고 사용자가 실제 파일을 확인해 가져가도록 돕는다.
각 화면과 선택은 이 작업을 줄이기 위해 존재해야 한다 (`INT-01`~`INT-06`).

현재의 여섯 단계는 UI 배치다. 여섯 화면을 순서대로 모두 방문하거나 같은 결정을 반복 확인하는 것이
제품 목적은 아니다. 화면 통합·자동 이동·저장 시점은 실제 작업 부담과 사용자 이해를 기준으로 검토한다.
기술 식별자·내부 상태를 이해해야 다음 단계로 갈 수 있게 만들지 않는다.

현재 구현 사실, 의도로 설명되는 필요성, 근거가 부족한 UI 선택을 구분한다.

기존 서버 계약을 바꾸려면 저장·판본·공개 결정·검토·파일의 정합성과 회귀를 함께 검증해야 한다.

| 04 초안 작성 | 정한 정보로 읽기 쉬운 공유 자료 만들기 | 승인 정보로 새로 작성한 초안과 파일 | [F04](../features/04-compose-review.md) |

| 06 파일 확인 | 실제로 무엇을 가져갈지 확인하기 | 확인한 동일 파일의 복사·다운로드 | [F05](../features/05-export.md) |

## UF-02. 자료 분석

화면 안내: `자료에서 확인한 내용과 확인이 필요한 내용을 살펴보세요.`

설명과 원자료를 읽어 관찰·추정·불확실·제약을 제안하는 단계다.
사용자가 긴 원문을 다시 읽고 분류하는 부담을 줄이기 위해 근거 원문, 필요한 이유, 불확실성을 함께 보여준다.
분석 모델이 제안했다고 사실이나 공개 허가로 확정하지 않는다 (`INT-04`, `INT-06`).

| 현재 동작·구분 | 왜 있는가 | 한계와 설명할 것 |
| --- | --- | --- |
| 분석 시작·진행·취소·재시도 | 비용과 대기를 인지하고 실행을 제어 | 자료 등록만으로 실행하지 않으며 새 분석이 예전 공개 허가를 확대하지 않음 |
| 관찰·가설·미확인·제약 등 후보 종류 | 무엇이 근거이고 무엇이 해석인지 구분 | 현재 enum은 구현 분류다. 사용자가 모든 종류를 선택·암기할 필요는 없음 |
| 원본 파일 보기·근거 대조 | 제안의 근거와 누락을 판단 | 내부 확인용이며 원문 전체를 공유 결과에 포함하는 승인이 아님 |
| 수동 후보·메모 | 모델이 놓치거나 실패한 내용을 보완 | 모든 사용자에게 추가 폼을 채우게 하지 않음. 작성한 메모도 자동 공개하지 않음 |
| 모델 연결 정보 | 실행 불가 원인을 찾기 | 운영 설정 확인을 일반 사용자의 분석 절차나 추가 동의로 만들지 않음 |

현재 진행 계산은 후보 1개 이상을 완료 표시의 근거로 쓴다. 후보가 많다는 사실은 분석의 충분성·정확성이나
자료 전체를 처리했다는 증거가 아니다. 후보가 없으면 정상적인 해당 정보 없음과 실패·예산 중단을 구분해야 한다.
설명에 필요한 맥락이 없으면 필요한 질문을 제안하되 수신처·목표 필수 입력을 되살리지 않는다.

## UF-03. 공개 결정

화면 안내: `공유할 내용과 실제로 보일 표현을 정하세요.`

공개할지와 어느 정도의 정보를 보일지는 사용자가 정한다. 이것이 내부 자료를 공유 작성용 정보로 넘기는
핵심 경계다. 선택한 자료 판본과 실제 미리보기에 결정을 연결하는 이유는 사용자 의도와 다른 값·원문이
작성기에 들어가지 않게 하기 위해서다 (`INT-04`, `INT-05`). 내부 승인 조직이나 결재 절차를 대신하지 않는다.

| 선택 | 의미 | 왜 구분하는가 |
| --- | --- | --- |
| 허용 | 확인한 특정 표현을 공유에 사용 | 원자료 전체나 주변 정보까지 허용한 것으로 확대하지 않기 위해 |
| 제외 | 이번 공유 결과에서 사용하지 않음 | 정보를 빼는 것도 유효한 사용자 선택이므로 |
| 보류 | 판단을 잠시 미룸 | 지금 제외하는 것과 나중에 검토할 것을 구분하기 위해. 모든 작업에 필요한 별도 상태인지는 검토 대상 |
| 미선택·저장된 결정 바꾸지 않음 | 이번 동작에서 새 허가를 만들지 않음 | 미선택을 허용으로 처리하거나 기존 결정을 실수로 덮지 않기 위해 |

### A~D는 왜 있고 어디까지 유효한가

현재 화면은 수치 요청량 사례의 네 가지 표현 방식을 사용한다.

| 현재 선택지 | 사용자가 비교할 것 | 한계 |
| --- | --- | --- |
| A 사실 요약 | 숫자·원문 대신 전달할 의미 | 요약 문장도 원인 단정이나 상세 정보가 들어갈 수 있어 실제 문장을 확인해야 함 |
| B 추이 | 절대값 대신 증가·감소와 관측 순서 | 순서·관측 개수도 공개된다. 단일 CSV 숫자 근거의 현재 지원 범위는 일반 자료 전체와 다름 |
| C 필드 선택 | 남기는 실제 필드·값·단위 | 마스킹이라는 이름만으로 값이 숨겨졌다고 볼 수 없음. 새 자료의 값에 자동 허가를 이전하지 않음 |
| D 직접 조건 | 사용자가 원하는 다른 표현의 실제 결과 | 임의 변환을 모두 구현하는 기능이 아님. 모호·미지원이면 이유를 알리고 입력을 보존 |

표현 수준을 고르고 조건을 직접 쓸 수 있어야 한다는 근거는 `INT-04`에 있다.
정확히 A~D 네 종류여야 하거나 모든 자료에 같은 네 개를 보여야 한다는 근거는 확인되지 않았다.
B와 C를 모두 마스킹이라고 부르면 원자료를 가리는 도구로 오해하게 하므로 새 공유 표현이라는 점을 설명한다.

## UF-04. 초안 작성

화면 안내: `공개하기로 정한 정보로 공유 초안을 만듭니다.`

사용자가 정한 정보로 본문·표·첨부를 새로 구성해 수작업으로 맞추는 부담을 줄인다.
원문 전체를 주고 일부를 가리게 하는 방식이 기본은 아니다. 입력 설명도 내부 맥락이므로
설명 전체나 내부 근거를 그대로 작성기에 전달하지 않는다 (`INT-02`, `INT-05`).

작성·취소·재시도는 실제 실행을 제어한다. 작성 중 필요한 공개 정보가 더 생기면 공개 결정으로 돌아간다.
내용을 바꾸려는 이유가 표현 문제인지 새 정보 공개인지 구분한다. 새 사실·값을 초안 수정으로 우회 허용하지 않는다.
자동 검토가 작성 과정에 포함되는 현재 구조와 별도 검토 화면의 필요성은 다른 문제다.

원시 JSON 편집은 제거됐다. 일반 문장 편집은 [DF-005](../product/deferred-features.md)의 추가 후보이며
현재 가능한 동작으로 안내하지 않는다. 현재는 공개 선택을 바꾸고 초안을 다시 작성한다.

## UF-05. 검토

화면 안내: `공개 선택을 지켰는지, 도움을 받기에 충분한지 결과를 검토하세요.`

현재 초안·실제 파일, 공개하기로 정한 표현, 필요한 경우 내부 근거를 대조한다.
원인 추정의 단정, 미확인 표시 누락, 필요한 맥락 부족, 허용하지 않은 값·원문을 확인하고 수정 경로를 안내한다.
자동 검토 통과는 정보 유출 방지의 보장이나 사람의 최종 판단을 대신하지 않는다 (`INT-06`, `INT-07`).

| 결과·동작 | 사용자가 할 일 | 의미 |
| --- | --- | --- |
| 통과 | 현재 결과를 살펴보고 파일 확인으로 진행 | 그 검토 대상에 대한 결과이며 이후 변경된 파일까지 보증하지 않음 |
| 수정 필요 | 지적 내용을 보고 다시 작성하거나 공개 선택 수정 | 모델 의견과 실제 위반 사실을 구분. 단순 통과 체크로 덮지 않음 |
| 공개 판단 필요 | 부족한 정보·표현을 공개할지 결정 | 검토자가 임의로 공개 범위를 늘리지 않음 |
| 실행 실패 | 실패 이유를 보고 재시도 또는 가능한 수동 검토 | 성공 판정과 구별. 품질이 나쁘다는 판정과 통신 실패도 구별 |

현재 수동 검토는 모델 시간 초과·연결 실패에 한정되고 파일 확인·승인 정보·불확실성 보존 체크와 사유를 받는다.
사람이 검토할 수 있어야 한다는 취지는 의도에 있지만, 세 체크와 필수 사유 또는 두 오류 코드로 제한해야 한다는
제품 판단 근거는 확인되지 않았다. 사람에게 실제 판단을 맡기는 일과 같은 내용을 확인했다고 서명시키는 일을 구분한다.
기존 구현의 허용 조건을 문서만으로 완화하거나 이미 제거한 중복 동의를 복구하지 않는다.

## UF-06. 파일 확인

화면 안내: `가져갈 파일의 내용을 확인하고 내려받으세요.`

본문만 아니라 실제 첨부도 확인하고 같은 결과를 가져가는 단계다. 공개 결정과 결과가 연결됐는지 검증하는 것은
앱의 책임이며 사용자에게 해시·판본 값을 읽고 대조하도록 떠넘기지 않는다 (`INT-02`, `INT-07`).

파일명·형식·내용을 기본으로 보여주고 크기와 변경 상태를 필요한 곳에서 알린다. 내부 경로·원래 파일명·내부 설명은
자동 첨부하지 않는다. 현재 `확정`은 현재 파일 집합을 고정해 복사·다운로드에 연결하는 동작이며
조직의 반출 승인이나 실제 외부 발송이 아니다. 형식적 확인 문자열·체크·API 확인 불리언은 이미 제거했다.

| 선택·정보 | 왜 있는가 | 검토할 부분 |
| --- | --- | --- |
| 본문 복사 | 문의 폼 등에 내용을 옮기기 위해 | 실제 제공되는 동작인지 구분. 실패를 성공으로 표시하지 않음 |
| 개별 다운로드 | 필요한 파일만 가져가기 위해 | 불필요한 내부 파일이 섞이지 않게 전체 목록을 앱이 관리 |
| ZIP | 파일 여러 개를 한 번에 가져가기 위해 | 모든 작업에서 필수 형식일 이유는 없음 |
| manifest·해시 | 무결성과 동일 파일 검증을 위해 | 사용자에게 기본 노출할 필요와 의미는 별도. 내부 경로와 원문을 포함하지 않음 |
