# SafeHandoff UI 구현 기준

## 상태와 범위

이 문서는 사용자가 지정한 발표자료와 합의한 화면 설계를 UI 구현으로 옮길 때 사용할 기준이다. 화면·API·모델 연결의 구현 완료나 실행 성공을 뜻하지 않는다.

- 적용 대상: `feat/hackathon-ui`의 `packages/client` 작업 화면.
- 목표: 사내 원자료에서 사용자가 공개를 허용한 정보로 문의 본문·표·첨부를 함께 작성하고, 검토·확정 후 직접 복사·다운로드하게 한다.
- 포함: 목적·수신처·자료 입력, A~D 공개 선택과 미리보기·적용, D 조건 확인, 본문·표·설명·첨부 동시 갱신, 내부 근거·검토, 최종 파일 확인, 스킬 등록·재사용 흐름.
- 제외: 원본의 외부 AI 전송, 외부 자동 제출, 기술 스택 교체, 모델·인증·실행 환경의 자동 설치나 변경. 커밋·푸시는 별도 승인 전 수행하지 않는다.
- 기존 문서 저장·조회 기능은 유지한다. 새 작업 화면을 만든다는 이유로 현재 기능이나 API 계약을 제거하지 않는다.

## 출처와 문서 관계

사용자가 제공한 `SafeHandoff_발표자료_통합 (1).pdf`를 발표 시연의 화면 요구 기준으로 삼는다. 원본 PDF는 저장소에 복사하지 않는다.

- 기준 파일 SHA-256: `d6f2a56a7a1ab6cb7f18c1de0ed734b2135ab256c93f1d58d06104ecc478e9cf`.
- 5쪽: 자료 입력, A~D 공개 수준, 직접 입력 조건 확인, 사람의 최종 확인, 저장·복사·다운로드·스킬 등록.
- 6~9쪽: 본문·표·설명 동시 갱신, 원문 격리, 작성·검토, 문장별 내부 근거, 스킬 재사용.

이 문서는 이번 UI의 적용 결정을 모은 문서다. 전체 제품·보안·API 계약을 다시 정의하지 않는다.

| 기준 | 참조 |
| --- | --- |
| 목적·사람의 결정·원자료 실행 경계 | [제품 의도](../intent.md) |
| 화면 구성·선택·최종 확인·오류·접근성 | [화면 구조와 공통 표시 규칙](IA.md)의 UI-03~UI-08 및 접근성 절 |
| 결정·판본·허용 정보의 불변 조건 | [동작 명세](spec.md) |
| 현재 노출된 HTTP API와 연결 한계 | [실제 API](api.md) |
| 내부 저장과 현재 구현 범위 | [3라운드 범위](round3-scope.md) |

### 발표자료의 불일치에 대한 적용 결정

- D는 5쪽 사용자 흐름을 따라 **기타 직접 입력**으로 표시한다. 다른 페이지의 비율 표현은 D의 입력 예시이지 D 전체의 정의로 사용하지 않는다.
- 수정 로그라는 표현을 원본 파일을 직접 고친다는 의미로 쓰지 않는다. 원본은 보존하고 **새 공유본과 검토 기록**을 구분한다.
- PDF의 기술 스택·구현 완료 서술을 현재 저장소의 구현 사실로 옮기지 않는다. 팀 실행 설정과 기존 구조를 유지하고 실제 연결 여부는 코드·API·관찰 결과로 구분한다.
- 발표자료와 기존 계약 사이에 추가 충돌이 발견되면 임의로 계약을 바꾸지 않는다. 충돌을 명시하고 필요한 변경을 합의한다.

## 작업 화면 구성

[IA의 UI-03](IA.md#ui-03--작업-공간)을 따라 작업 중심 화면을 구성한다. 채팅 기록만을 주 화면으로 사용하지 않는다.

| 영역 | 내용 |
| --- | --- |
| 상단 | 목적·이번 조사 목표·수신처·공개 범위, 원자료 목록, 현재 단계와 현재 선택 판본 |
| 왼쪽 | 공개 질문, 필요한 정보와 이유, A~D 선택, 실제 공개 미리보기, 보류·제외·적용 동작, 저장 기준 적용 내역 |
| 가운데 | 현재 공유용 초안의 본문·표·설명·첨부. 각 부분을 만든 공개 선택과 연결 |
| 오른쪽 접이식 패널 | 문장별 사내 근거, 내부 검토 설명, 도구 실행 요약, 판본 이력. 외부 반출 자료와 명확히 분리 |
| 하단 | 현재 서버 상태가 허용하는 주 동작 하나. 새 문서 작성·추가 질문 확인·재검토·최종 파일 확인 등 |

좁은 화면에서는 상단 정보 → 공개 질문 → 초안 → 근거·검토 → 현재 주 동작 순으로 읽을 수 있게 배치한다. 원본의 넓은 표는 해당 영역 안에서만 스크롤한다. 키보드 접근, 상태 안내, 초점 보존은 IA의 접근성 기준을 따른다.

## A~D 선택과 결정 저장

| 선택 | 사용자에게 보여줄 내용 | 주의점 |
| --- | --- | --- |
| A. 구체적인 데이터 없이 사실만 | 공개할 사실을 문장으로 미리보기 | 승인하지 않은 관측 개수·단위·증가 배율을 덧붙이지 않음 |
| B. 추이만 보이게 나머지 마스킹 | 관측 순서와 증가·감소 방향을 표현한 새 표 | 순서와 관측 개수도 공개 정보임을 안내. 정확한 값·비율·시각은 남기지 않음 |
| C. 요청 정보 마스킹 | 남길 열·단위·기간을 선택하고 실제 공개될 셀을 확인 | 정확한 값의 허용과 재사용 제한은 IA의 계약을 따름 |
| D. 기타 직접 입력 | 원하는 조건 입력, 해석된 조건·사용할 변환·실제 계산 결과 확인 | 비율은 예시. 자유 입력 자체를 공개 승인으로 취급하지 않음 |

- 첫 진입에서 허용 선택을 미리 체크하지 않는다. 권장 표시는 가능하지만 사람의 선택이나 승인으로 취급하지 않는다.
- 선택지 클릭은 **미리보기 요청**, `이 방식으로 적용`은 **결정 저장**이다. 화면의 선택 표시와 서버에 저장된 결정을 구분한다.
- 질문에는 필요한 이유, 내부 근거, 공개할 내용·공개하지 않을 내용, 이번만 적용할지 재사용할지를 보여준다. `나중에 결정`, `이번 결과에서 제외`, `근거 확인` 경로를 둔다.
- 모델은 표현 수준을 제안할 뿐 공개 결정을 대신 저장하지 않는다. 추가 정보가 필요하면 해당 질문으로 돌아간다.
- 원문 그대로를 A~D의 일반 선택지로 추가하지 않는다. 원문 사용이 필요하면 IA의 별도 원문 승인 영역에서 실제 포함할 구간을 확인한다.

### D의 조건 확인

입력 → `적용할 내용 확인` → 해석된 조건·등록된 변환·실제 공개 결과 확인 → `이 조건으로 적용` 순서다.

지원 여부가 불명확하면 조건을 다시 묻고, 지원하지 않으면 이유와 가능한 선택지를 안내한다. 입력은 보존하며 임의 코드나 정규식을 실행하지 않는다. 계산 불가나 모델 오류를 다른 계산·예시 결과로 대신하지 않는다. 조건·자료·미리보기가 바뀌면 이전 적용 상태를 해제한다.

## 작성·동시 갱신·검토

- 원본은 사내 경계에서 처리한다. 작성기에는 승인된 정보만 전달하고 원문 분석 대화나 내부 근거를 공유 초안으로 복사하지 않는다. 원본의 외부 AI 전송 동의 화면은 만들지 않는다.
- 공개 선택이 바뀌면 이전 결과를 즉시 `이전 선택의 결과 — 새 선택으로 다시 작성해야 합니다.`로 표시한다. 기록 열람은 가능하지만 복사·다운로드·최종 확정은 막는다.
- 새 선택을 적용한 본문·표·설명·첨부는 같은 판본의 결과로 함께 갱신한다. 새 표 옆에 이전 본문의 값이나 비율이 남지 않게 한다.
- 작성과 검토는 구분한다. 검토에는 원문·선택 기준·초안의 대조, 과다 공개, 근거 없는 원인 단정, 필수 업무 조건 누락을 표시한다.
- 근거가 있는 필수 조건이 빠졌으면 보완하거나 공개 선택으로 돌아간다. 원자료에 없는 업무 조건을 새로 만들어 복원했다고 표시하지 않는다.
- 모델 실패·미지원·검토 미완료·사람 확인 필요 상태를 숨기지 않는다. 실제 모델 실패를 연출용 결과로 자동 대체하지 않는다.
- 진행 상태와 가능한 동작은 서버 상태를 따른다. 화면 이벤트만으로 완료·확정 가능 상태를 만들거나 가짜 진행률을 표시하지 않는다.

## 최종 확인·내보내기·스킬

1. 최종 확인에서는 실제 공유 파일의 이름·형식·크기·내용, 현재 판본, 원문·정확한 값 사용, 미해결 결정, 검사·필요한 재현 상태를 확인한다. 내부 근거·진단·규칙 기록은 반출 파일 목록에 섞지 않는다.
2. `이 파일들로 확정` 요청에서 서버가 현재 선택·판본·파일 해시·승인 유효성을 다시 확인한다. 파일 목록만 표시됐다고 확정으로 취급하지 않는다.
3. 확정 성공 후 본문 복사·패키지 다운로드·개별 파일 다운로드를 제공한다. 자동 보내기·제출 버튼은 없다. 무효화·승인 만료·복사 권한 거부는 성공으로 표시하지 않는다.
4. 확인한 처리 기준은 스킬로 등록할 수 있다. 저장 대상은 변환 기준과 적용 범위이며, 지난 원문·정확한 값·생성 문장을 새 자료의 사실로 재사용하지 않는다.
5. 목적·수신처·조건 등 기존 명세의 적용 범위가 일치할 때만 자동 재사용한다. 달라지면 다시 질문한다. 단순히 비슷한 문제라는 이유로 자동 공개하지 않는다.

## 서버 장애 CSV 시연에 적용

목적은 외부 솔루션 개발자가 장애의 다음 조사 행동을 정할 수 있게 하는 것이다. 다음 CSV만으로 요청 증가가 장애의 원인이라고 단정하지 않는다.

```csv
observed_at,request_count
2026-10-28T09:00:01Z,820
2026-10-28T09:01:02Z,160
2026-10-28T09:02:01Z,21740
```

- 질문은 마지막 관측의 요청 증가를 관찰로 설명하고, 공개 수준 A~D를 묻는다.
- B를 선택·적용한 예시는 `기준 → 감소 → 증가`의 새 표와 그에 일치하는 문의 본문이다. 정확한 건수·비율·발생 시각은 포함하지 않는다.
- D에서 첫 관측을 기준으로 한 비율을 요청했다면 이 CSV로 실제 계산한 결과를 확인한다. 다른 시연 자료의 계산 결과를 복사하지 않는다.
- 앞선 대화의 시간 분 단위 내림, 천 단위 요청량 구간화는 확정 규칙이 아니다. 사용자 예시의 `1000 미만`·`20000 이상`도 B의 기본 변환으로 고정하지 않는다. 별도 규칙이 필요하면 기존 등록 변환의 지원 여부와 공개 의미를 확인하고 합의한다.
- 완전 익명이나 유출 위험 제거를 보장하지 않는다. 선택한 표현이 남기는 관측 순서·패턴·규모 단서를 미리보기에서 설명한다.

## 구현·연결 상태와 수용 기준

기준 문서 작성 시점의 [실제 API](api.md)에는 작성·검토 모델 주입과 내부 결정 저장이 설명돼 있지만, 분석·공개 제안·미리보기 계산 및 task/decision HTTP API는 전체 작업 화면과 연결되지 않았다. 현재 문서 저장·조회 화면이 위 흐름을 구현했다는 뜻은 아니다.

아래는 앞으로 실제 화면과 결과로 확인할 수용 기준이다. 문서에 적혀 있다는 이유로 통과나 구현 완료로 표시하지 않는다.

| 확인 대상 | 수용 기준 |
| --- | --- |
| 자료 입력 | 목적·수신처·파일과 파싱 상태를 확인할 수 있음. 업로드 성공을 분석 완료로 표시하지 않음 |
| 공개 결정 | A~D가 일관되고 기본 허용 미선택. 미리보기와 적용이 분리되며 저장 실패를 성공으로 표시하지 않음 |
| D와 추가 질문 | 조건 해석·실제 결과 확인 후 적용. 불명확·미지원·계산 오류·모델 실패에서 입력을 보존하고 복구 경로를 제공 |
| 선택 변경 | 본문·표·설명·첨부가 같은 판본으로 갱신되고 이전 결과의 반출·확정이 차단됨 |
| 내부 근거·검토 | 문장별 근거와 작성·검토 결과를 확인 가능. 내부 기록이 반출 파일에 섞이지 않음 |
| 최종 파일 | 확인한 파일·선택·판본·해시에 대해 서버가 확정하며 실제 다운로드 내용이 확인한 결과와 같음 |
| 재사용 | 스킬에 변환 기준만 저장. 적용 범위 불일치 시 재질문하며 과거 수치를 새 사실로 사용하지 않음 |
| 미연결 기능 | 실제 API가 없는 동작을 성공·승인·검토 완료로 가장하지 않음. 연출 모드는 실제 실행과 명확히 구분 |
| 기존 기능·접근성 | 기존 문서 저장·조회가 유지되고 좁은 화면·키보드·상태 안내에서 핵심 동작에 접근 가능 |

## 실행 기준과 작성 방식

실행은 팀의 `mise.toml`과 `justfile`을 따른다. Node `24.21.0`, pnpm `10.13.1`, just `1.58.0` 선언을 유지하고 Node 22 우회 도구를 다시 추가하지 않는다. 설치 성공은 사용자가 확인했으며 이 문서 작성으로 앱 실행까지 검증한 것은 아니다. 원본과 UI 작업 폴더에서 같은 포트의 서버를 중복 실행하지 않는다.

사용자가 지정한 PDF, 기존 제품·화면·API 문서, 대화에서 승인한 설계를 대조해 작성했다. 문서 대조에 읽기 전용 보조 검토를 사용했으며 문서 작성 과정에서 앱을 실행하지 않았다.
