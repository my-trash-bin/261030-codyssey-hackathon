# SafeHandoff UI 구현 기준

## 상태와 범위

이 문서는 [README](../README.md)와 `docs/`의 제품/화면/API 문서를 바탕으로 UI 구현에 적용할 기준이다. 화면/API/모델 연결의 구현 완료나 실행 성공을 뜻하지 않는다.

- 적용 대상: `feat/hackathon-ui`의 `packages/client` 작업 화면.
- 목표: 사내 원자료에서 사용자가 공개를 허용한 정보로 문의 본문/표/첨부를 함께 작성하고, 검토/확정 후 직접 복사/다운로드하게 한다.
- 포함: 목적/수신처/자료 입력, A~D 공개 선택과 미리보기/적용, D 조건 확인, 본문/표/설명/첨부 동시 갱신, 내부 근거/검토, 최종 파일 확인, 스킬 등록/재사용 흐름.
- 제외: 원본의 외부 AI 전송, 외부 자동 제출, 기술 스택 교체, 모델/인증/실행 환경의 자동 설치나 변경. 커밋/푸시는 별도 승인 전 수행하지 않는다.
- 기존 문서 저장/조회 기능은 유지한다. 새 작업 화면을 만든다는 이유로 현재 기능이나 API 계약을 제거하지 않는다.

## 기준 문서와 관계

UI 구현 기준은 [README](../README.md)와 아래의 `docs/` 문서다.

이 문서는 이번 UI의 적용 결정을 모은 문서다. 전체 제품/보안/API 계약을 다시 정의하지 않는다.

| 기준 | 참조 |

| 결정/판본/허용 정보의 불변 조건 | [동작 명세](design/spec.md) |
| 현재 노출된 HTTP API와 연결 한계 | [실제 API](design/api.md) |
| 분석 연결 뒤 남은 서버 요청과 수용 기준 | [분석 UI 이후 서버 요청](ops/ui-api-requests.md) |

### 적용 원칙

- D는 **기타 직접 입력**으로 표시한다. 비율은 입력 예시일 뿐 D 전체의 정의로 사용하지 않는다.
- 수정 로그라는 표현을 원본 파일을 직접 고친다는 의미로 쓰지 않는다. 원본은 보존하고 **새 공유본과 검토 기록**을 구분한다.
- 팀 실행 설정과 기존 구조를 유지하고 실제 연결 여부는 코드/API/관찰 결과로 구분한다.

## 작업 화면 구성

[IA의 UI-03](design/ia.md#ui-03--작업-공간)을 따라 작업 중심 화면을 구성한다. 채팅 기록만을 주 화면으로 사용하지 않는다.

작업 공간은 여섯 단계 흐름으로 한 화면에 한 단계만 펼친다. 모든 구역을 동시에 펼치면 세로로 5,000px가
넘는 한 줄 덤프가 되어 지금 할 일을 찾을 수 없었다.

| 단계 | 내용 | 완료 판단 근거 |
| --- | --- | --- |
| 01 목적과 자료 | 작업 만들기 폼, 작업 목록, 원자료 목록 | 작업이 있고 원자료가 1개 이상 |
| 02 자료 분석 | 분석 동의, 분석 실행/상태, 수동 후보 | 후보가 1개 이상 |
| 03 공개 결정 | 후보별 허용/제외/보류, 표현 미리보기, 결정 배치 저장 | 모든 후보의 결정이 저장됨 |
| 04 초안 작성 | 공유 초안 생성 job, 파일 목록, 판본 표시 | 공개 파일이 1개 이상 |
| 05 검토 | 자동 검토 결과, DocAST 편집, 사람 의미 검토 | 자동 검토 통과 또는 사람 검토 기록 |
| 06 파일 확인 | 최종 확인 체크, 확정, ZIP/개별 다운로드 | 확정 export 존재 |

| 영역 | 내용 |
| --- | --- |
| 머리말 | 작업 이름, 모드/세션/작업 요약, 여섯 칸 진행 막대와 완료 개수 |
| 왼쪽 단계 목록 | 01~06 버튼(번호, 제목, 상태 요약)과 보조 화면(규칙/이력/보관소/실행 정보) |
| 가운데 | 지금 단계의 제목, 목적, 본문과 이전/다음 이동. 보조 화면은 같은 자리를 대체 |
| 오른쪽 정보 열 | 다음에 할 일, 작업 집계(원자료/후보/결정/파일), 최근 실행 상태, 세션 정보 |
| 단계 본문 | 해당 단계 컴포넌트만 렌더한다. 다른 단계의 폼, 표, 상태는 DOM에 두지 않는다 |

작업 id가 바뀔 때만 권장 단계로 이동하고, 같은 작업의 판본이 오를 때는 사용자가 고른 단계를 유지한다.
단계나 화면을 고르면 그 제목으로 초점을 옮긴다.

배치는 화면 폭에 따라 3열(1280px 이상: 208px/가변/288px), 2열(900~1279px: 208px/가변), 1열(900px 미만)로
바뀐다. 1열에서는 단계 목록이 가로 스크롤 한 줄이 되고 진행 막대의 단계 이름은 숨긴다.

## 시각 기준

민감한 자료를 공개하기 전에 검토하는 화면이라는 주제에 맞춰 **검토용 문서** 분위기를 낸다. 장식으로 채우지 않고 바탕색/서체/괘선만 바꾼다.

| 요소 | 토큰 | 값 | 쓰임 |
| --- | --- | --- | --- |
| 바탕 | `--color-surface-page` | `#f6f2e9` | 흰 화면 대신 따뜻한 종이색 |
| 용지/카드 | `--color-surface-raised` | `#fffcf4` | 초안 용지, 분석 카드, 입력/버튼 |
| 본문 | `--color-text-primary` | `#1a1917` | 본문/제목 |
| 보조 글자 | `--color-text-secondary` | `#423e36` | 카드 본문, 설명 |
| 힌트/메타 | `--color-text-muted` | `#655f53` | 힌트, 라벨, 표 머리 |
| 헤어라인 | `--color-border-subtle` | `#d9d1c0` | 항목 구분선 |
| 구조 경계 | `--color-border-strong` | `#8f8472` | 입력/버튼 테두리, 구역 상단 경계 |
| 강조 | `--color-text-accent` | `#9c2b21` | 선택 표시, 후보 왼쪽 괘선, 선택 영역 |

- 제목만 명조 계열(`--font-title`), 본문은 산세리프를 유지한다. 제목 아래 메타 라벨은 작은 크기/자간으로 구분한다.
- 근거/후보/충돌 카드는 용지색 바탕과 왼쪽 괘선으로 구분한다. 공개 결정 대상인 후보에만 인주색 괘선을 쓴다.
- 내부 참고 영역(`내부 근거와 검토`)은 상자를 감싸지 않고 머리줄 왼쪽에 3px 인주색 괘선과 `내부용` 칩만 둔다.
  제목과 본문은 본문 계열 14px로 맞춰 다른 글자와 크기를 섞지 않는다.
- 그림자/그라디언트/배지/장식 아이콘은 쓰지 않고, 강조색은 한 색만 쓴다.
- 계산된 대비: 본문 15.7:1, 보조 글자 9.5:1, 힌트 5.7:1, 인주색 6.8:1, 입력 테두리 3.3:1. 상태 표시를 색만으로 구분하지 않는다.
- 색, 글자, 간격, 버튼과 입력 크기는 `tokens.css`의 토큰으로만 정한다. 값의 단계와 변경 절차는 [디자인 토큰](design-tokens.md)에 있다.
- 토큰과 컴포넌트 상태는 같은 번들의 `/#design-system` 화면에서 확인한다.
- 입력, 셀렉트, 버튼은 높이 40px로 같고 글자는 16px다. 셀렉트 목록, 체크박스, 라디오, 파일 선택 버튼도 토큰으로 그리며,
  네이티브 컨트롤의 키보드 동작과 라벨 연결은 그대로 둔다. 라벨과 컨트롤 사이는 8px, 필드 사이는 16px로 고정한다.
- 화면 폭 320/768/1280에서 가로 넘침이 없음을 확인했다. 이 확인은 색/서체/폭의 계산값이며, 사람이 화면을 보고 판단한 결과가 아니다.

## A~D 선택과 결정 저장

| 선택 | 사용자에게 보여줄 내용 | 주의점 |
| --- | --- | --- |
| A. 구체적인 데이터 없이 사실만 | 공개할 사실을 문장으로 미리보기 | 승인하지 않은 관측 개수/단위/증가 배율을 덧붙이지 않음 |
| B. 추이만 보이게 나머지 마스킹 | 관측 순서와 증가/감소 방향을 표현한 새 표 | 순서와 관측 개수도 공개 정보임을 안내. 정확한 값/비율/시각은 남기지 않음 |
| C. 요청 정보 마스킹 | 남길 열/단위/기간을 선택하고 실제 공개될 셀을 확인 | 정확한 값의 허용과 재사용 제한은 IA의 계약을 따름 |
| D. 기타 직접 입력 | 원하는 조건 입력, 해석된 조건/사용할 변환/실제 계산 결과 확인 | 비율은 예시. 자유 입력 자체를 공개 승인으로 취급하지 않음 |

- 첫 진입에서 허용 선택을 미리 체크하지 않는다. 권장 표시는 가능하지만 사람의 선택이나 승인으로 취급하지 않는다.
- 선택지 클릭은 **미리보기 요청**, `이 방식으로 적용`은 **결정 저장**이다. 화면의 선택 표시와 서버에 저장된 결정을 구분한다.
- 질문에는 필요한 이유, 내부 근거, 공개할 내용/공개하지 않을 내용, 이번만 적용할지 재사용할지를 보여준다. `나중에 결정`, `이번 결과에서 제외`, `근거 확인` 경로를 둔다.
- 모델은 표현 수준을 제안할 뿐 공개 결정을 대신 저장하지 않는다. 추가 정보가 필요하면 해당 질문으로 돌아간다.
- 원문 그대로를 A~D의 일반 선택지로 추가하지 않는다. 원문 사용이 필요하면 IA의 별도 원문 승인 영역에서 실제 포함할 구간을 확인한다.

### D의 조건 확인

입력 -> `적용할 내용 확인` -> 해석된 조건/등록된 변환/실제 공개 결과 확인 -> `이 조건으로 적용` 순서다.

지원 여부가 불명확하면 조건을 다시 묻고, 지원하지 않으면 이유와 가능한 선택지를 안내한다. 입력은 보존하며 임의 코드나 정규식을 실행하지 않는다. 계산 불가나 모델 오류를 다른 계산/예시 결과로 대신하지 않는다. 조건/자료/미리보기가 바뀌면 이전 적용 상태를 해제한다.

## 작성/동시 갱신/검토

- 원본은 사내 경계에서 처리한다. 작성기에는 승인된 정보만 전달하고 원문 분석 대화나 내부 근거를
  공유 초안으로 복사하지 않는다. 원본의 외부 AI 전송 동의 화면은 만들지 않는다. 분석 화면의 동의
  체크는 운영 설정으로 지정된 모델이 승인된 사내/로컬 분석 환경임을 확인했다는 표시이며 외부 AI
  전송 승인이 아니다. `GET /api/core`로 모델 주소를 확인할 수 없으므로 화면이 사내 여부를 자동
  검증한다고 표시하지 않는다.
- 공개 선택이 바뀌면 이전 결과를 즉시 `이전 선택의 결과 - 새 선택으로 다시 작성해야 합니다.`로 표시한다. 기록 열람은 가능하지만 복사/다운로드/최종 확정은 막는다.
- 새 선택을 적용한 본문/표/설명/첨부는 같은 판본의 결과로 함께 갱신한다. 새 표 옆에 이전 본문의 값이나 비율이 남지 않게 한다.
- 작성과 검토는 구분한다. 검토에는 원문/선택 기준/초안의 대조, 과다 공개, 근거 없는 원인 단정, 필수 업무 조건 누락을 표시한다.
- 근거가 있는 필수 조건이 빠졌으면 보완하거나 공개 선택으로 돌아간다. 원자료에 없는 업무 조건을 새로 만들어 복원했다고 표시하지 않는다.
- 모델 실패/미지원/검토 미완료/사람 확인 필요 상태를 숨기지 않는다. 실제 모델 실패를 연출용 결과로 자동 대체하지 않는다.
- 진행 상태와 가능한 동작은 서버 상태를 따른다. 화면 이벤트만으로 완료/확정 가능 상태를 만들거나 가짜 진행률을 표시하지 않는다.

## 최종 확인/내보내기/스킬

1. 최종 확인에서는 실제 공유 파일의 이름/형식/크기/내용, 현재 판본, 원문/정확한 값 사용, 미해결 결정, 검사/필요한 재현 상태를 확인한다. 내부 근거/진단/규칙 기록은 반출 파일 목록에 섞지 않는다.
2. `이 파일들로 확정` 요청에서 서버가 현재 선택/판본/파일 해시/승인 유효성을 다시 확인한다. 파일 목록만 표시됐다고 확정으로 취급하지 않는다.
3. 확정 성공 후 본문 복사/패키지 다운로드/개별 파일 다운로드를 제공한다. 자동 보내기/제출 버튼은 없다. 무효화/승인 만료/복사 권한 거부는 성공으로 표시하지 않는다.
4. 확인한 처리 기준은 스킬로 등록할 수 있다. 저장 대상은 변환 기준과 적용 범위이며, 지난 원문/정확한 값/생성 문장을 새 자료의 사실로 재사용하지 않는다.
5. 목적/수신처/조건 등 기존 명세의 적용 범위가 일치할 때만 자동 재사용한다. 달라지면 다시 질문한다. 단순히 비슷한 문제라는 이유로 자동 공개하지 않는다.

## 서버 장애 CSV 시연에 적용

목적은 외부 솔루션 개발자가 장애의 다음 조사 행동을 정할 수 있게 하는 것이다. 다음 CSV만으로 요청 증가가 장애의 원인이라고 단정하지 않는다.

```csv
observed_at,request_count
2026-10-28T09:00:01Z,820
2026-10-28T09:01:02Z,160
2026-10-28T09:02:01Z,21740
```

- 질문은 마지막 관측의 요청 증가를 관찰로 설명하고, 공개 수준 A~D를 묻는다.
- B를 선택/적용한 예시는 `기준 -> 감소 -> 증가`의 새 표와 그에 일치하는 문의 본문이다. 정확한 건수/비율/발생 시각은 포함하지 않는다.
- D에서 첫 관측을 기준으로 한 비율을 요청했다면 이 CSV로 실제 계산한 결과를 확인한다. 다른 시연 자료의 계산 결과를 복사하지 않는다.
- 앞선 대화의 시간 분 단위 내림, 천 단위 요청량 구간화는 확정 규칙이 아니다. 사용자 예시의 `1000 미만`/`20000 이상`도 B의 기본 변환으로 고정하지 않는다. 별도 규칙이 필요하면 기존 등록 변환의 지원 여부와 공개 의미를 확인하고 합의한다.
- 완전 익명이나 유출 위험 제거를 보장하지 않는다. 선택한 표현이 남기는 관측 순서/패턴/규모 단서를 미리보기에서 설명한다.

## 상태 계층과 훅 계약

작업 화면은 React 함수 컴포넌트다. 상태 소유자는 클래스나 어댑터 객체가 아니라 `packages/client/src`의 순수 reducer와, 그 reducer를 `useReducer`로 붙인 훅이다.

- 상태 소유: `disclosuresReducer`(`disclosure-state.ts`)와 작업 흐름 훅(`ui/hooks/useTaskFlow.ts`, 공유 타입과 상수는 `task-flow-model.ts`)이 화면 상태의 단일 원천이다. 파생 값과 명령 계획은 `disclosure-selectors.ts`가 현재 상태와 입력만으로 계산하고 상태를 바꾸지 않는다. 컴포넌트는 reducer가 만든 상태와 selector 결과만 읽는다.
- 불변 갱신: 모든 전이는 기존 상태를 고치지 않고 새 객체/새 `Map`으로 만든다. 같은 상태를 여러 곳에서 고치는 공유 가변 컨테이너를 두지 않는다.
- 훅의 책임: `useSession`/`useTaskFlow`/`useDisclosures`/`useArtifacts`/`useRules`/`useTaskBrowser`/`useTaskHistory`/`useDocuments`/`useRuntimeInfo`는 요청 수명(요청 세대 번호, `AbortController`, 진행 중 점유)만 `useRef`로 다루고 화면 상태를 복제하지 않는다. `useSession`이 받은 CSRF 토큰은 `App`의 상태로 올려 `useDisclosures({ csrfToken })`/`useTaskFlow({ csrfToken })`가 같은 값으로 쓰기 헤더를 만든다.
- 늦은 응답: 요청을 시작할 때 세대 번호를 올려 소유자를 잡고, 응답을 처리하기 전에 세대가 같은지 확인한다. 다른 요청이 시작됐거나 언마운트됐으면 응답을 버리고 상태를 바꾸지 않는다. 공개 결정 배치가 409를 받으면 reducer가 재조회 요청을 만들고 훅의 효과가 그것을 한 번만 소비한다.
- 검사 도구: 요청 계약(메서드/경로/헤더/멱등 키)은 `session-client`/`task-client`/`artifacts-client`/`rules-client`/`task-browser-client`의 `*.test.ts`가 스텁 fetch로 확인한다. 훅 동작은 `disclosure-state.test.ts`/`analysis-state.test.ts`가 `test-helpers/react-hook.ts`의 `renderHook`으로 실제 React root에 훅을 mount하고, 명령 호출을 `React act` 안에서 수행해 확인한다. 상태는 렌더마다 snapshot이므로 매번 `result.current`에서 읽는다.

## 구현/연결 상태와 수용 기준

작업 화면은 이번에 목적/수신처/지원 형식 파일을 읽어 `POST /api/analysis`를 호출하고, 응답의 로컬
바이트 범위 근거와 후보 제안/충돌을 내부 검토용 영역에 표시하는 데까지 연결했다. 응답의
evidence/후보 참조는 임시 값이며 task/candidate 저장, 공개 허가, 공유 초안, 결정 저장이 아니다.
이 stateless 경로는 `TaskStore.analysis`와 연결되지 않으며, 화면은 영속 채택을 인증된 `/api/v1`
분석 job으로만 시작한다. 파일을 고르는 것만으로 전송하지 않고 승인된 사내/로컬 분석 환경 확인에
동의해야 호출하며, 입력이 바뀌면 동의를 해제한다. `GET /api/core`는 모델 주소를 제공하지 않으므로
화면이 실제 호스트의 사내 여부를 검증하거나 자동 차단한다고 표시하지 않는다. 사내 LAN의 HTTP처럼
`crypto.subtle`을 쓸 수 없는 보안 문맥에서는 요청 전에 오류를 안내하고 해시를 생략하지 않는다.

파일 크기 검사를 통과해도 근거 최대 100개를 넘기면 분석할 수 없다. 화면은 이 한도와 `INVALID_CORE_INPUT`의 원인을 추측하지 않는 표시, 파일 크기와 무관한 `MODEL_BUDGET_EXCEEDED`를 구분해 안내한다. 전체 조건은 [분석 UI 이후 서버 요청](ops/ui-api-requests.md)에 적었다.

공개 결정 영역은 `useDisclosures`가 `GET /api/v1/tasks/{id}` 조회와 C 필드 목록/미리보기/해석
요청/결정 배치/철회를 HTTP로 호출하고, 작업 등록은 `useTaskFlow`가 `readCatalog` ->
`createTask({ intake })` -> `startAnalysis` -> `readAnalysisJob` 순서로 호출한다
(`packages/client/src/ui/hooks/`, `packages/client/src/task-client.ts`). 초안과 파일은
`useArtifacts`가, 규칙은 `useRules`가, 작업 목록/삭제와 이력은 `useTaskBrowser`/`useTaskHistory`가
호출한다. 세션 CSRF 토큰이 없으면 쓰기는 사유만 표시하고 전송하지 않는다.

이 연결은 코드 배선에 더해 실제 브라우저에서 확인했다. 아래 실행 확인 절의 항목은 실행해서 관찰한
결과이고, 확인하지 않은 항목은 미확인으로 남긴다.

### 실행 확인 (합성 모델 client + 메모리 저장소)

실제 모델이나 실제 고객 자료를 쓰지 않았다. 합성 `ModelClient`와 `TaskStore(':memory:')`로 띄운
서버에 Chromium을 붙여 아래를 실행하고 화면 문구, 서버 응답, 내려받은 파일을 함께 확인했다.
아래 세션 로그인/로그아웃 행은 시작 토큰 제거 전의 과거 검증이다. 2026-11-01부터는 로그인 없이
자동 연결하고, 만료·서버 재시작 뒤에도 자동 재연결한다. 과거 토큰 절차는 현재 실행 방법이 아니다.

| 흐름 | 관찰 결과 |
| --- | --- |
| 세션 열기/복원/로그아웃 | 열기/복원 성공. 로그아웃 확인 단계에서 초점이 확인 버튼으로 이동하고, 닫은 뒤 `/api/v1/tasks`는 401 `AUTH_REQUIRED` |
| 세션 만료 | 서버 시계를 9시간 앞으로 옮긴 뒤 재확인하면 세션을 닫고 새 시작 토큰이 필요하다고 안내 |
| 작업 등록 | catalog intake(프로젝트/목적/수신처/공개 범위) + CSV 등록 -> 판본 2, 원자료 1개 |
| 분석 | 동의 체크 뒤 시작 -> 후보 생성. 취소 요청 -> `cancel_requested` -> `cancelled` |
| 원자료 해제 | 해제 뒤 판본 상승, 분석 동의 자동 해제 |
| 수동 후보 | 직접 메모 방식으로 추가 -> 판본 상승, 후보 2개 |
| C 필드 | 필드 목록(`count`) -> 미리보기(서버 반환 표 20/30/40, `projection_sha256`) -> 전체 적용 -> 결정 저장 |
| B 추이 | 한 CSV 한 열, 서로 다른 행 근거에서 미리보기(1 기준, 2 증가, 3 증가) |
| 결정 철회 | `철회됨` 표시, 이후 같은 export는 409 `EXPORT_INVALIDATED` |
| 초안/검토 | 작성 job 성공, 파일 3개, 자동 검토 통과, 이슈 0개 |
| 사람 의미 검토 | 검토를 `MODEL_UNAVAILABLE`로 실패시킨 뒤 체크 3개+사유로 기록 -> 확정 성공 |
| 확정/다운로드 | 확정 뒤 ZIP 655 B 저장, `sha256`이 화면 표시 ZIP SHA-256과 일치. `unzip -l` 3개 파일, CSV CRLF와 표 참조 문장 유지. 개별 파일도 표시 해시와 일치 |
| 규칙 저장/판본 | 결정에서 규칙 저장 -> 목록 표시. 새 판본(기준 100 지수) -> 판본 2가 최신 |
| 규칙 적용 | 다른 작업에 명시 적용 -> 결정 자동 생성, 적용된 표현이 최신 판본(지수) |
| 규칙 철회 | 철회된 규칙을 쓰던 결정도 함께 철회되고 초안 생성 조건이 미충족으로 바뀜 |
| 작업 삭제 | 삭제 뒤 목록/작업/이력/공개 결정이 모두 비고, 재조회는 404 |

미확인으로 남긴 것: 실제 모델 provider로 같은 흐름을 돌린 기록, 8시간 세션 만료의 실시간 경과,
확정 뒤 새로고침한 화면에서 export 패널 복원(아래 간격 참조).

### 작업 흐름 셸 실행 확인

6단계 셸은 로컬 앱 서버(:8090)와 Vite 클라이언트(:5174), 모델 응답은 루프백 스텁(:8299)으로 확인했다.
실제 모델이 아니므로 문안 품질은 확인 대상이 아니다.

| 흐름 | 관찰 결과 |
| --- | --- |
| 빈 상태 | 작업 없음에서 페이지 높이 1,441px, 가로 넘침 0. 예전 같은 화면은 5,111px였다 |
| 작업 등록 | 폼 입력 + CSV 등록 -> 자동으로 02단계 이동, 진행 1/6, 왼쪽 목록 `01 완료` |
| 분석 | 동의 체크 뒤 실행 -> 후보 1개, `02 완료` 표시. 동의 문장은 폭 62ch에서 어절 단위로 줄이 바뀜 |
| 공개 결정 | 후보 1개의 A(사실 요약) 미리보기 -> 전체 적용 -> `결정 1 / 1`. 작업 ID 입력은 접힌 `직접 조회`로 옮겼다 |
| 초안/검토/확정 | 작성 job 성공(파일 2개) -> 자동 검토 통과 -> 최종 확인 체크 -> 확정 -> ZIP SHA-256과 개별 파일 표시 |
| 폭 | 1680/1280/1024/900/768/640px에서 가로 넘침 0. 3열에서 2열, 다시 1열로 전환이 위 기준대로 동작 |
| 글자 크기 | 작업 공간에서 쓰는 크기는 토큰 여섯 값(12/14/16/20/24/40px) 중 12/14/16/20/40px 다섯 가지로 모였다(40px은 머리말 제목) |
| 버튼 높이 | 기본 40px, 목록 선택 36px, 행 안 동작 32px. 행 안 `해제` 버튼은 32px로 줄여 행 높이를 밀지 않는다 |

미확인: 실제 모델 provider로 같은 흐름을 돌린 결과, 사람 의미 검토가 필요한 실패 경로의 새 배치
(`MODEL_INVALID_RESPONSE`를 내는 모델로 검토를 실패시키는 경우)는 이번에 다시 확인하지 않았다.

### 남은 UI 접속점과 연결 간격

서버 경로 존재와 화면 연결을 구분해 적는다. 아래는 화면이 아직 호출하지 않거나 일부만 쓰는 지점이다.

- 세션: 복원/열기/로그아웃/만료 재확인까지 연결했다. 서버가 세션을 열지 못하는 환경(503
  `WORKFLOW_API_DISABLED` 등)에서는 토큰이 비어 쓰기가 계속 차단되므로 안내 문구만 확인했다.
- 초안 작성/검토: `compose`/`review` job, DocAST 편집 저장, 사람 의미 검토, 확정, ZIP/개별 파일
  다운로드까지 연결했다. 확정 정보는 메모리에만 있어 새로고침하면 내보내기 패널이 사라진다. 같은
  파일 집합을 다시 확정하면 서버가 같은 bytes로 새 export를 만들므로 다운로드는 복구되지만, 버튼
  문구는 여전히 `이 파일들로 확정`이다.
- 재사용 규칙: 저장/목록/새 판본/철회/명시 적용까지 연결했다. 규칙 저장은 결정 배치의
  `save_reusable_rule`과 규칙 화면의 `선택한 결정에서 규칙 저장` 두 경로 모두 서버가 검증한다.
  B(추이)의 선택 조건은 후보 종류가 아니라 근거 모양(한 CSV, 같은 열, 서로 다른 행)으로 서버 계열
  변환과 맞췄다.
- 실행 환경: `ExecutionSection.tsx`의 `#execution-environment`가 `/api/core`의 세 값과 세션 응답의
  `analysis_environment` 안내로 라벨을 만든다. `useRuntimeInfo`는 `/api/core`만 보고
  `/api/v1/runtime`과 `/api/sharing`은 화면이 호출하지 않는다.
- 작업 상태 문구: `#task-status`는 고른 작업이 없을 때와 아직 명령을 실행하지 않은 작업에서 각각 다른
  안내를 보여 준다. 다만 마지막 실행 결과 문구는 작업을 바꿔도 남으므로, 다른 작업을 고른 직후에는
  이전 작업의 결과 문구가 한 번 더 보일 수 있다.

아래는 실제 화면과 결과로 확인할 수용 기준이다. 문서에 적혀 있다는 이유로 통과나 구현 완료로 표시하지 않는다.

| 확인 대상 | 수용 기준 |
| --- | --- |
| 자료 입력 | 목적/수신처/파일과 형식/한도를 확인할 수 있음. 파일 선택만으로 전송하지 않고 동의 없이는 분석을 호출하지 않음 |
| 분석 결과 | 서버가 반환한 근거 위치/후보 종류/확실성/목적 관련성/충돌을 표시하고, 임시 결과를 저장/공개 허가/초안으로 표시하지 않음 |
| 공개 결정 | A~D가 일관되고 기본 허용 미선택. 미리보기와 적용이 분리되며 저장 실패를 성공으로 표시하지 않음 |
| D와 추가 질문 | 조건 해석/실제 결과 확인 후 적용. 불명확/미지원/계산 오류/모델 실패에서 입력을 보존하고 복구 경로를 제공 |
| 선택 변경 | 본문/표/설명/첨부가 같은 판본으로 갱신되고 이전 결과의 반출/확정이 차단됨 |
| 내부 근거/검토 | 문장별 근거와 작성/검토 결과를 확인 가능. 내부 기록이 반출 파일에 섞이지 않음 |
| 최종 파일 | 확인한 파일/선택/판본/해시에 대해 서버가 확정하며 실제 다운로드 내용이 확인한 결과와 같음 |
| 재사용 | 스킬에 변환 기준만 저장. 적용 범위 불일치 시 재질문하며 과거 수치를 새 사실로 사용하지 않음 |
| 미연결 기능 | 실제 API가 없는 동작을 성공/승인/검토 완료로 가장하지 않음. 연출 모드는 실제 실행과 명확히 구분 |
| 기존 기능/접근성 | 기존 문서 저장/조회가 유지되고 좁은 화면/키보드/상태 안내에서 핵심 동작에 접근 가능 |

## 실행 기준

실행은 팀의 `mise.toml`과 `justfile`을 따른다. Node `24.21.0`, pnpm `10.13.1`, just `1.58.0` 선언을 유지하고 Node 22 우회 도구를 다시 추가하지 않는다. 설치 성공은 사용자가 확인했으며, 분석 연결 확인은 저장소 밖 임시 사본에서 실제 앱/UI를 실행해 수행했다. 원본과 UI 작업 폴더에서 같은 포트의 서버를 중복 실행하지 않는다.

## 분석 연결 실행 확인

현재 UI 작업 사본을 저장소 밖 임시 폴더로 복사하고 기존 의존성을 재사용해 검사했다. 실제 앱 서버/클라이언트를 실행하되, 모델 연결은 합성 파일만 받는 루프백 HTTP 응답기로 한정했다. 원본 실행 설정/인증/데이터베이스는 바꾸지 않았다.

```sh
mise exec -- pnpm --filter @safehandoff/client typecheck
mise exec -- node --conditions=development --test packages/client/src/*.test.ts packages/core/src/analyze.test.ts packages/core/src/evidence-parser.test.ts packages/server/src/*.test.ts packages/app/src/app.test.ts packages/app/src/config.test.ts packages/core-interface/src/workflow.test.ts
```

클라이언트 타입 검사와 위 회귀 검사 77개가 통과했다. 전체 테스트 묶음을 실행한 결과로 확대하지 않는다.

브라우저에서 관찰한 결과:
- 한글/CRLF 로그, CSV, JSON 파일 3개가 실제 분석 API를 거쳐 근거 9개/후보 제안 3개/충돌 1개로 표시됐다. 모델 입력의 원문도 원본 줄바꿈을 유지했다.
- UTF-8 바이트 범위 발췌, 머리글을 포함한 CSV 행/열, 이스케이프된 JSON 포인터가 표시됐다. 모델 문장의 HTML 모양 문자열은 텍스트로만 표시됐고 이미지 요소를 만들지 않았다.
- 파일 선택만으로는 모델을 호출하지 않았다. 목적 변경은 동의를 해제하고 이전 결과를 구분했으며 공유 초안 생성은 계속 비활성이었다.
- 로컬 모델 응답을 11초 지연해도 분석이 완료됐다. 분석 취소는 프록시/앱을 거쳐 모델 HTTP 연결 중단까지 전달됐다.
- 빈 후보는 후보 0개로 표시됐다. 모델의 503 오류에서는 기존 엔진의 두 번 시도 후 안전한 오류를 표시하고 입력/직전 결과를 보존했다. 화면은 분석 API를 자동 재전송하지 않았다.
- 파일당 256KiB 초과 파일이 섞인 선택과 합계 1MiB 초과 선택은 전체가 전송 전에 거부됐다. 근거 101개 입력은 서버의 400 오류로 표시됐고 모델 호출은 없었다. 용량 오류 뒤 주요 동작 안내도 같은 오류를 표시했다.
- 화면 폭 320px에서 문서 폭도 320px였고 스크립트 예외는 관찰되지 않았다. 사용자가 취소한 요청의 네트워크 중단은 의도된 동작이다.

실제 LLM의 후보 의미 정확성, 모델 호스트의 사내 여부, 영속 task 채택, 실제 세션/CSRF와 공개 결정 저장, 공유 초안/최종 파일의 종단간 동작은 이 확인에 포함하지 않았다.

### 최신 main 병합 뒤 재확인

분석 결과의 내부 저장/채택을 추가한 `main`을 병합한 트리에서 다시 검사했다.

- `mise exec -- pnpm typecheck`가 워크스페이스 전체에서 통과했다.
- `mise exec -- pnpm test`가 패키지 검사와 `tools` 검사에서 실패 0으로 끝났다. 첫 실행에서는 로컬 설치에 `playwright`가 없어 `tools/demo-browser.test.mjs`가 모듈 없음으로 실패했고, 잠금 파일대로 설치한 뒤 통과했다. 설치 누락이었으며 분석 변경과 무관하다.
- 병합 트리에서도 루프백 모델로 실제 앱/UI를 실행해 근거 3개/후보 1개가 표시되고 공유 초안 생성이 비활성인 것을 확인했다. 기존 문서 저장/조회는 201/200으로 유지됐다.
- 같은 실행은 `SAFEHANDOFF_WORKFLOW_TOKEN` 없이 띄운 앱이라 `GET /api/v1/tasks`가 404였고
  데이터베이스에 workflow 테이블이 생기지 않았다. 앱은 token이 있을 때만 `TaskStore`를
  조립하므로(`packages/app/src/main.ts`) `/api/analysis`가 내부 채택 경로를 호출하지 않는다는
  서술과 일치한다. 내부 채택 자체의 동작은 `packages/server/src/analysis-store.test.ts`와
  `packages/app/src/config.test.ts`로 확인했으며, 이 화면 실행이 영속 채택을 검증한 것은 아니다.
