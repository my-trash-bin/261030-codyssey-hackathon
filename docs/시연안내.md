# 시연 안내

## 공급사 문의 · 실행 환경 없음

1. `make run-fixture`로 시작하고 새 작업에서 공급사 문의·VendorStore 수신자를 선택합니다.
2. `fixtures/author/b2b-timeout` 세 파일을 업로드하고 분석합니다. 파일과 파싱 오류가 있으면 먼저 수정합니다.
3. timeout 관찰·재시도 성공 응답·미확인 사항을 각각 미리보기 후 허용합니다. 두 추적 ID는 이번 자료의 정확한 값으로 허용합니다.
4. 요청량은 처음에 비율을 허용하고 문서를 작성합니다. 본문과 CSV를 확인합니다.
5. 같은 카드에서 방향만 공개로 바꿉니다. 기존 확정 파일을 받으려고 하면 409로 차단됩니다. 새 문서와 CSV를 다시 생성합니다.
6. 최종 화면에서 원래 시각·건수·비율·payload·접속 주소가 없는 실제 파일을 확인한 뒤 확정합니다. `not_run/no_environment`는 서버 처리를 재현했다는 의미가 아닙니다.
7. 선택적 새 설정 예시를 허용하면 문서용 IP를 사용하는 새 JSON이 추가됩니다. 원본 접속 로그를 공개하도록 허용한 것이 아닙니다.
8. ID 미공개 분기에서는 ID 후보를 제외합니다. 공급사 조회를 완료한 것처럼 쓰지 않고 최소 진단 항목·안전한 재시도 조건을 문의해야 합니다.

## 새 합성 입력으로 OSS 재현

1. `make prepare-runners`, `make test-extensions`를 실행합니다. 등록 digest와 실제 Docker 시험 보고서를 확인합니다.
2. 새 OSS 작업에 `fixtures/author/oss-encoding` 자료를 넣습니다.
3. 기술 관찰을 허용하고 고객 정보는 공개하지 않습니다. 합성 입력 생성·고정 대상 실행 후보는 별도로 허용합니다.
4. 작성할 때 고정 runner가 ASCII/다중 바이트를 buggy/fixed에 각각 실행합니다. encode의 지정 오류와 실제 출력 파일 내용으로 판정합니다.
5. 최종 ZIP에는 고객 입력 대신 새 합성 입력, 고정 공개 repro 소스, 실행 결과가 포함됩니다.
6. ZIP만 받은 사람이 별도 폴더에서 `cd repro; GOTOOLCHAIN=local GOPROXY=off go run ./cmd/repro --inputs ./inputs`를 실행합니다. 그 사람의 확인은 아직 수행하지 않았으며 자동 runner 시험과 별도입니다.

## 재사용과 일반 내부 자료

1. 운영 자문 작업에 `fixtures/author/internal-operations` 자료를 넣습니다.
2. 중복 입력·사람 대조·기존 메일/메신저 채널 유지 제약을 허용합니다.
3. 요청량 방향 변환을 같은 범위에 재사용하도록 저장합니다.
4. 생성기로 `middle-decrease` 자료를 만들고 같은 프로젝트·목적·수신자에서 새 작업을 만듭니다. 방향을 감소·증가로 다시 계산해야 하며 이전 문장·비율을 복사하면 안 됩니다.
5. 수신자를 바꾸면 과거 정확한 값 승인과 저장 기준은 새 범위에서 유효하지 않습니다. 다시 미리보기와 공개 결정을 받아야 합니다.
6. 작업 기록에서 기준을 철회하면 의존하는 현재 결과가 무효화됩니다.

## 브라우저 시험 재실행

Node와 Playwright는 선택적인 개발 시험 도구이며 앱 런타임에 필요하지 않습니다.

```bash
mise exec node@24.21.0 -- npm install --prefix /tmp/safehandoff-browser playwright
mise exec node@24.21.0 -- /tmp/safehandoff-browser/node_modules/.bin/playwright install chromium
# fixture 서버를 8080에서 실행해 둔 별도 터미널에서:
NODE_PATH=/tmp/safehandoff-browser/node_modules \
  mise exec node@24.21.0 -- node scripts/browser-smoke.cjs
```

이 스크립트는 전용 시험 DB의 서버를 대상으로 실행합니다. 실제 작업 DB에는 사용하지 마세요. 공개 선택을 수행하는 테스트이고 사용자 선택을 대신하는 제품 기능이 아닙니다. 결과 JSON과 화면 이미지는 `evaluation/results`에 저장됩니다.
