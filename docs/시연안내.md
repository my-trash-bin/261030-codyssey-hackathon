# 시연 안내

> 보존한 제품 설계·이전 기록이다. 현재 구현은 TypeScript 서버·클라이언트의 문서 저장·조회만 제공한다. 현재 실행과 API는 [README](../README.md) 및 [api](api.md)를 따른다.

시연 기준은 [demo.md](demo.md)와 [test-data.md](test-data.md)입니다. 아래 순서는 그 기준에 맞춘 실행 체크리스트이며 목표 기능의 구현 완료를 뜻하지 않습니다. 실행 전 [검증보고서](검증보고서.md)로 가능한 단계를 확인하고, 미구현 단계는 실제 성공 장면으로 제시하지 않습니다.

## 준비

1. 가상 자료와 전용 demo DB를 사용하고 fixture/live·등록 runner 상태를 표시합니다.
2. 실행 자료는 `fixtures/reference-pack/author/`를 기준으로 준비합니다. `fixtures/reference-pack/recipient/`와 `evaluation/expected/`는 앱·모델에 주지 않습니다.
3. 새 접속 계약은 5분 일회용 토큰과 로컬 세션입니다. 현재 코드의 접속 방식과 목표 선택·삭제 기능이 미구현이면 그 사실을 표시합니다.
4. runner는 준비 단계에서 이미지·바이너리를 고정하고 runtime pull·외부 인터넷으로 보완하지 않습니다.

## 공급사 문의

1. vendor_support의 default 목표와 등록 수신자를 선택하고 B 자료를 분석합니다.
2. timeout·재시도 성공 응답·최초 완료/중복/원인 미확인을 구분합니다. 추적 ID는 이번 자료의 정확값으로 허용하거나 제외합니다.
3. 요청량 `820/1160/1740`에 직접 입력 D의 지수 변환을 적용합니다. 기본 정수 HALF_UP 결과 `100/141/212`를 실제 미리보기에서 확인합니다.
4. B 방향 표로 바꾸고 기존 본문·표·ZIP이 stale이 되는지 확인합니다. 새 결과에 실제 건수·비율·시각이 따라오지 않아야 합니다.
5. ID를 제외해 추가 진단 질문이 필요하면 ask_for_diagnostics 목표로 명시적으로 변경하고 재분석·공개 선택을 다시 합니다. 공급사 조회를 끝낸 것처럼 표현하지 않습니다.
6. 실제 파일을 확인하고 확정·다운로드합니다. 관찰 문의의 `not_run/no_environment`는 서버 재현 성공을 뜻하지 않습니다.

## OSS 합성 재현과 맥락 검사

1. OSS default/observations_only와 reproduction_evidence 중 목표를 선택합니다. 재현 목표에는 호환 등록 팩이 필요합니다.
2. 공개 기술 조건과 새 입력의 실제 미리보기를 승인합니다. 고객 문자열·내부 경로·사업 정보는 제외합니다.
3. 같은 길이의 새 ASCII/한글 입력을 buggy/fixed에 각각 실행하고 지정 오류·파일 부재·성공 파일 바이트를 확인합니다.
4. 재현 목표의 실패·환경 없음은 확정 성공으로 바꾸지 않습니다. 계속하려면 사용자가 observations_only로 바꾸고 다시 판단합니다.
5. 공개 ZIP만 받은 수신자가 독립 repro를 실행하고 다음 행동을 기록합니다. 자동 runner 결과와 수신자 확인을 구분합니다.
6. 승인한 새 설정의 문서용 IP와 원래 접속 로그의 같은 IP에 다른 문맥 판정이 적용되는지 확인합니다. 예외는 특정 finding만 해소합니다.

## 재사용·복구·삭제

1. 같은 scope·schema/version·selector에 방향 기준을 저장하고 새 `820/780/1740` 자료에서 감소·증가를 다시 계산합니다.
2. 수신자·goal·자료 판본을 바꾸면 정확값·원문 승인을 재확인합니다. 기준 철회·만료 후 과거 허용이 부활하지 않아야 합니다.
3. 늦은 응답·모델 오류·재시작을 실행해 선택 보존과 명시적 재시도를 확인합니다.
4. 작업 삭제의 DELETE 확인과 저장 기준 보존 설명을 확인합니다. 삭제 후 늦은 결과가 원문·작업을 되살리지 않아야 합니다.
5. raw trace 기본 미저장, debug opt-in의 24시간 정리와 작업 삭제 시 제거를 별도로 확인합니다.

## 결과 기록

fixture/live·사람 개입·실제 runner·수신자 행동을 [보고 틀](../evaluation/results/report-template.json)에 구분합니다. 새 [QA](qa.md)의 해당 시험을 실행한 경우만 pass/fail로 기록하고 나머지는 not_run으로 둡니다. 기존 T01–T28의 pass를 새 시험 번호에 복사하지 않습니다.

현재 코드의 기본 브라우저 회귀는 `scripts/browser-smoke.cjs`와 `scripts/browser-advanced.cjs`입니다. 전용 fixture 서버와 기존 `fixtures/author/`를 사용하는 회귀시험이며 위 전체 시연·새 보안/삭제/목표 계약의 수용시험을 대신하지 않습니다. 앱 런타임에는 Node·Playwright가 필요하지 않습니다.
