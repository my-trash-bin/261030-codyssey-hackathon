# 구현 및 검증 보고서

## 판정 범위

실행 가능한 로컬 핵심 PoC를 구현했습니다. fixture 자동 흐름, 승인·판본·확정 경계, 고정 Docker 재현과 외부 checker를 검증했습니다. **실제 사내 모델 PoC 완료는 아직 아닙니다.** 아래 미구현·부분 구현과 미수행 검증을 함께 보아야 합니다.

사내 endpoint·모델 ID·인증이 제공되지 않아 live 수용시험은 `not_run`입니다. fixture 응답을 live 결과로 대체하지 않았습니다. 독립 수신자의 실제 작업·사람 의미 평가·일반 채팅 대비 비교 실험도 수행하지 않았으며 기록은 null입니다.

## 실제 검증 증거

| 검증 | 결과 | 증거 |
| --- | --- | --- |
| Go 모듈 다운로드·무결성 | 통과 | `make setup`, 고정 go.mod/go.sum |
| 단위·API 통합·고정 target | 통과 | `make test`, `evaluation/results/unit-tests.jsonl` |
| 정적 검사 | 통과 | `go vet ./...` |
| fixture A/B/B ID 제외/일반 내부 자료 | 자동 검사 통과 | `evaluation/results/fixture-run.json` |
| Docker 합성 입력 네 실행·출력 파일 바이트 | 재시험 통과 | `evaluation/results/extensions-run.json` |
| 외부 process checker 허용/접속 로그/깨진 참조 | 통과 | 같은 확장 보고서 |
| 잘못된 target digest | 실행 전 차단 | 같은 확장 보고서 |
| Chromium 생성~확정·다운로드·새로고침·이력 | 통과 | `browser-run.json`, `workspace.png` |
| 1280×720, 1366×768 가로 넘침 | 없음 | 브라우저 실제 scrollWidth 측정 |
| 고급 브라우저 원문·조건 해석·타임라인·설정 | 재시험 결과 참조 | `browser-advanced-run.json` |
| 앱·DB 없는 독립 repro 실행 | 통과 | `standalone-repro.json` |
| 실제 사내 모델 | 미수행 | `live-run.json`, 종료 코드 2 |
| 독립 수신자·사람 의미 검토 | 미수행 | fixture 보고서의 null 및 not_run |
| Go race detector | 미수행 | 이 환경에는 C compiler가 없어 `-race` 사용 불가 |

첫 Docker 시험에서는 대상의 persist 성공 응답만 있고 호스트에서 파일을 확인하지 못했습니다. oracle은 이를 `inconclusive/CONTROL_FAILED`로 판정했습니다. 컨테이너 내부 고정 probe가 실제 파일을 읽도록 보완한 뒤 재시험했습니다. 중간에는 코드 변경 후 checker digest 불일치도 차단되었습니다. 두 실패를 `extensions-first-failure.json`, 해당 실행 ID 보고서에 보존했습니다. 성공한 실행만 골라 기록하지 않았습니다.

브라우저 첫 자동 실행은 공개 선택 응답 대기 timeout이 있었습니다. 고급 자동 시험에서도 닫힌 직접 입력 패널에 접근하다 timeout이 났으며, 선택한 공개 방법의 패널을 자동으로 여는 UI로 보완했습니다. SSE 중복 갱신이 미리보기 상태를 초기화할 수 있는 경로를 보완하고 재시험했습니다. 한국어 폰트가 없는 시스템에서도 정상 표시되도록 OFL 글꼴을 앱에 포함했습니다.

## 명세 대비 남은 구현

- 저장은 정규화된 25개 테이블 대신 SQLite 작업 집계와 불변 revision 스냅샷입니다. 결정·파일·이벤트의 원자적 변경과 CAS는 구현했으나 명세의 테이블별 조회 모델은 미구현입니다.
- 텍스트 byte range·CSV 셀·JSON Pointer와 원문 승인 UI를 구현했습니다. 원문 선택은 바이트 단위의 고급 UI이며 텍스트 드래그·민감 필드 자동 강조는 후속 개선입니다.
- 직접 입력은 별도 disclosure 모델 job으로 supported/ambiguous/unsupported를 제안하며 실제 승인과 분리합니다. fixture는 두 개의 고정 문장만 지원합니다. live 조건 해석 품질은 실제 모델 설정 후 평가해야 합니다.
- 요청량의 열·단위·관찰 범위와 네 타임라인 변환을 구현했습니다. 임의 JSON 필드의 범용 변환과 일반 설정 편집기는 포함하지 않았습니다.
- 제품 팩은 빌드에 포함한 고정 두 개입니다. 임의 팩 등록·동적 판본 적용 UI는 없고 임의 스크립트 업로드도 없습니다. 고정 context checker·target runner는 실제 실행됩니다.
- 규칙 새 판본 API는 만료 시각 변경을 지원합니다. 다른 변환은 새 미리보기·공개 결정을 통해 저장합니다. 저장 기준 판본 선택 → 새 자료 미리보기 → 적용을 통해 현재 결정에 명시 적용할 수 있습니다.
- 최종 모델 검토에서 문제가 남으면 blocked 파일과 내부 trace를 남기고 재검토·사람 의미 검토를 제공합니다. 모델 지적 위치를 시각적으로 강조하는 UI와 모든 오류의 상세 필드 표시는 추가 구현이 필요합니다.
- SSE는 재생·15초 heartbeat·resync_required·polling을 제공합니다. 이력은 현재 압축하지 않습니다. 큐는 단일 프로세스·전역 동시성 1에 한정됩니다.
- 계약은 strict Go 검증과 schema를 함께 제공하지만 모든 계약의 동일 corpus를 독립 JSON Schema 엔진으로 전수 검증하지는 않았습니다.
- 평가 CLI는 네 기본 자동 사례와 별도 확장을 실행합니다. 모든 heldout 변형·공개 수준 변경·수신자 변경을 live에서 수행하는 전체 묶음은 아직 없습니다.

다음 개선 우선순위는 전체 계약/수용 corpus 전수 검사, 일반 필드 변환 확대, 근거·검토 시각화, 저장 정규화입니다. 실제 사내 LLM 설정이 제공되면 그다음 live 수용 결과와 실패·사람 개입을 별도로 기록해야 합니다.

## 실행 기록 보존 방식

최종 evaluator는 `evaluation/results/runs/{run_id}`에 보고서·trace·공개 파일을 보관합니다. 최신 예시는 `examples`로 제공하되 기존 예시 디렉터리는 `previous-examples`로 이동해 보존합니다. 초기 개발 실행의 일부 성공 trace·예시는 최신 경로를 공유했으므로 당시 파일 전체를 복원할 수 없습니다. 기록을 보완한 최종 실행부터는 실행별 파일·정답표 해시를 확인할 수 있습니다. 자동 공개 계획은 필수 후보와 명시한 series/추적 ID/합성 입력을 사용하고 다른 optional 후보는 제외합니다. 의미 정답표는 제품 입력에 넣지 않으며, 의미 평가가 자동 통과했다는 주장도 하지 않습니다.

CSV 자료의 역할은 생성·추가 화면에서 지정합니다. 프로젝트·수신자는 등록 UI에서 앱이 ID를 발급하며, 알려지지 않은 ID는 API에서 거부합니다. 직접 편집은 문단·제목·목록 텍스트로 제공하고, 첨부 데이터의 변경은 공개 선택으로 안내합니다. 정형 표·타임라인의 기본 레이블은 현재 한국어입니다. English 선택의 live 본문 품질 및 정형 레이블의 다국어 확대는 후속 검증 항목입니다.
