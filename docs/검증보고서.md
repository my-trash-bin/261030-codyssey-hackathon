# 구현 및 검증 보고서

## 판정 범위

실행 가능한 로컬 핵심 PoC를 구현했습니다. fixture 자동 흐름, 승인·판본·확정 경계, 고정 Docker 재현과 외부 checker를 검증했습니다. **전체 명세의 코드 구현 완료와 실제 사내 모델 PoC 완료를 선언하지 않습니다.** 아래 미구현·부분 구현과 미수행 검증을 함께 보아야 합니다.

사내 endpoint·모델 ID·인증이 제공되지 않아 live 수용시험은 `not_run`입니다. fixture 응답을 live 결과로 대체하지 않았습니다. 독립 수신자의 실제 작업·사람 의미 평가·일반 채팅 대비 비교 실험도 수행하지 않았으며 기록은 null입니다.

## 실제 검증 증거

| 검증 | 결과 | 증거 |
| --- | --- | --- |
| Go 모듈 다운로드·무결성 | 통과 | `make setup`, 고정 go.mod/go.sum |
| 단위·API 통합·고정 target | 통과 | `make test`, `evaluation/results/unit-tests.jsonl` |
| 정적 검사 | 통과 | `go vet ./...` |
| fixture A/B/B ID 제외/일반 내부 자료 | 자동 검사 통과 | `evaluation/results/fixture-run.json` |
| Docker 합성 입력 네 실행·출력 파일 바이트 | 재시험 통과 | `evaluation/results/extensions-run.json` |
| 외부 process checker 허용/접속 로그/깨진 참조 | 통과 | 같은 확장 보고서 |
| 잘못된 target digest | 실행 전 차단 | 같은 확장 보고서 |
| Chromium 생성~확정·다운로드·새로고침·이력 | 통과 | `browser-run.json`, `workspace.png` |
| 1280×720, 1366×768 가로 넘침 | 없음 | 브라우저 실제 scrollWidth 측정 |
| 실제 사내 모델 | 미수행 | `live-run.json`, 종료 코드 2 |
| 독립 수신자·사람 의미 검토 | 미수행 | fixture 보고서의 null 및 not_run |
| Go race detector | 미수행 | 이 환경에는 C compiler가 없어 `-race` 사용 불가 |

첫 Docker 시험에서는 대상의 persist 성공 응답만 있고 호스트에서 파일을 확인하지 못했습니다. oracle은 이를 `inconclusive/CONTROL_FAILED`로 판정했습니다. 컨테이너 내부 고정 probe가 실제 파일을 읽도록 보완한 뒤 재시험했습니다. 중간에는 코드 변경 후 checker digest 불일치도 차단되었습니다. 두 실패를 `extensions-first-failure.json`, 해당 실행 ID 보고서에 보존했습니다. 성공한 실행만 골라 기록하지 않았습니다.

브라우저 첫 자동 실행은 공개 선택 응답 대기 timeout이 있었습니다. SSE 중복 갱신이 미리보기 상태를 초기화할 수 있는 경로를 보완하고 재시험했습니다. 한국어 폰트가 없는 시스템에서도 정상 표시되도록 OFL 글꼴을 앱에 포함했습니다.

| 항목 | 현재 확인 |

| T02 공개 수준 변경 | 비율→방향 후 이전 ZIP 차단, 새 실제 파일·ZIP 검사 |
| T03 늦은 응답 | 지연 provider와 동시 revision 변경으로 stale 결과 차단 |
| T04 범위 재사용 | 정확한 selector/scope 일치 재사용·철회 시험; 방향 계산의 감소 변형 단위시험. 전체 UI 변형 수용은 추가 필요 |
| T05 수신자 변경 | 기존 승인으로 compose 불가·파일 pointer 해제 확인 |
| T06 만료·철회 | 정책의 scope/expiry/revoke와 다운로드 재검사 경로 확인. 모든 동시 만료 경계 전수 시험은 추가 필요 |
| T07 원문 정상 양성 | byte range·UTF-8·source hash·정확한 저장 바이트·writer 슬롯 격리 시험 |
| T08 원문 충돌 | 모델 conflict 참조 검사 후 SOURCE_CONFLICT로 중단. 충돌 후보를 나란히 유지하는 완전한 UI는 미구현 |
| T09 의미 검토 효과 | 실제 모델 비교 시험 미수행. fixture pass를 효과 근거로 사용하지 않음 |
| T10 자료 속 지시 | 원자료가 결정 API·도구 registry를 호출할 경로 없음. live prompt injection 시험은 미수행 |
| T11–T12 IP 문맥 | 생성 설정만 허용, 접속 로그·깨진 참조·다른 finding/hash 거부 |
| T13–T14 다른 오류/대조군 | oracle의 validate 오류·CONTROL_FAILED 구분 단위시험 및 실제 실패 기록 |
| T15 환경 없는 B | 실제 B 문의의 확정·ZIP 경로에서 not_run 유지 |
| T16 공개 패키지 | allowlist·실제 ZIP·금지 표식·승인 원문 양성 검사 |
| T17 JSON 엄격성 | 중복·unknown·대소문자·타입·후행 JSON·모델 필수 키 corpus 검사 |
| T18 provider 실패 | 잘림·문맥 초과·tool_calls 거부, fixture 자동 fallback 없음. 실제 장애 endpoint 시험 미수행 |
| T19 멱등 | 동일 요청 재생·다른 요청 409·처리 전 키 예약 |
| T20 바이트 변조 | 한 바이트 변경 후 확정·사람 검토 차단, 다운로드의 저장 ZIP 동일성 |
| T21 철회 후 과거 허용 부활 | current decision만 사용하며 철회·규칙 철회 시 결과 무효화 |
| T22 직접 편집 새 숫자 | 인용 fact에 없는 숫자 hard check 차단. 새 비수치 사실은 의미 검토 대상 |
| T23 사람 fallback | mode=human의 현재 문서/파일 hash 결속, hard check 우회 불가 시험 |
| T24 재시작 | running/queued를 INTERRUPTED로 복원, 확정 중간 파일 없음 |
| T25 입력 상한 | 업로드·전체 자료·모델 요청 byte 상한 검사, 조용한 절단 없음 |
| T26 원문 판본 | 새 source version·문자 경계에서 과거 grant 거부 |
| T27 도구·process | 고정 digest·network/resource 제한 실제 실행, tool_calls 비실행 |
| T28 로컬 요청·표현 | Host/CSRF/멱등 검사, HTML escaping, CSV 수식·숫자 타입 시험, 실제 브라우저 흐름 |

이 표는 28개 전체가 통과했다는 집계가 아닙니다. 부분 시험과 실제 환경 미수행은 각각 적었습니다.

## 명세 대비 남은 구현

- 저장은 정규화된 25개 테이블 대신 SQLite 작업 집계와 불변 revision 스냅샷입니다. 결정·파일·이벤트의 원자적 변경과 CAS는 구현했으나 명세의 테이블별 조회 모델은 미구현입니다.
- 근거는 모든 형식에서 정확한 원본 byte range입니다. CSV 셀 locator·JSON Pointer 전용 locator, 원문 구간을 고르는 완전한 브라우저 UI는 미구현입니다. 원문 grant API와 UTF-8·hash 검사는 동작합니다.
- 직접 입력은 두 개의 명시적인 방향/기준100 조건만 구조화합니다. 임의 자연어 조건의 live 해석 역할·명확성 제안 UI는 미구현이며 알 수 없는 조건을 권한으로 저장하지 않습니다.
- 열·단위·관찰 범위 선택은 요청량 series에 한정됩니다. 임의 JSON 필드 선택·실제 시각/간격별 timeline 변환·일반 설정 편집 UI는 미구현입니다.
- 제품 팩은 빌드에 포함한 고정 두 개입니다. 임의 팩 등록·동적 판본 적용 UI는 없고 임의 스크립트 업로드도 없습니다. 고정 context checker·target runner는 실제 실행됩니다.
- 규칙 새 판본 API는 만료 시각 변경을 지원합니다. 다른 변환은 새 미리보기·공개 결정을 통해 저장합니다. 기존 결정에 새 rule version을 명시 적용하는 전용 UI는 없습니다.
- 최종 모델 검토에서 문제가 남으면 blocked 파일과 내부 trace를 남기고 재검토·사람 의미 검토를 제공합니다. 모델 지적 위치를 시각적으로 강조하는 UI와 모든 오류의 상세 필드 표시는 추가 구현이 필요합니다.
- SSE는 재생과 polling을 제공하지만 이력 압축 이후 resync_required 처리는 아직 없습니다. 큐는 단일 프로세스·전역 동시성 1에 한정됩니다.
- 계약은 strict Go 검증과 schema를 함께 제공하지만 모든 계약의 동일 corpus를 독립 JSON Schema 엔진으로 전수 검증하지는 않았습니다.
- 평가 CLI는 네 기본 자동 사례와 별도 확장을 실행합니다. 모든 heldout 변형·공개 수준 변경·수신자 변경을 live에서 수행하는 전체 묶음은 아직 없습니다.

따라서 다음 구현 우선순위는 형식별 근거·원문 UI, 충돌/조건 해석 흐름, timeline·규칙 판본 적용, 전체 계약/수용 corpus입니다. 실제 사내 LLM 설정이 제공되면 그다음 live 수용 결과와 실패·사람 개입을 별도로 기록해야 합니다.
