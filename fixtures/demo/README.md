# 화면 시연용 가상 자료

회사·고객·ID·수치·인증 표식은 모두 가상이다. 실제 인증 정보는 없다. 이 묶음은 시연 입력이며 실행 성공이나 모델 품질의 검증 결과가 아니다. 아래 진행 안내와 기대 관찰은 발표자용이다. 앱에는 각 사례의 원자료만 업로드한다.

## 분리형 interactive 시연

`just demo-start` 후 http://127.0.0.1:8081 에서 사례를 불러오면 파일 선택 없이 분석·공개 표현 편집·승인·재생성·재검토·다운로드를 시험할 수 있다. 후보와 결과는 사전 작성·템플릿이며 실제 모델 품질 검증이 아니다. 실제 모델 화면은 `just live-start` 후 http://127.0.0.1:8082 에서 원자료를 업로드한다. 자세한 실행·API·시험 방법과 현재 한계는 [독립 실행 안내](../../docs/separated-runtime.md)를 따른다.

아래 A–D와 재사용·runner 설명은 기존 일체형 시제품을 위한 진행 계획이다. 새 임시 화면에는 해당 확장이 아직 연결되지 않았으므로 기본 공개 표현 승인·재작성 흐름과 구분한다.

## 먼저 해볼 사례: 운영 자문

1. 새 작업에서 목적은 **외부 운영 자문**, 수신자는 자문사, 공개 범위는 **지정 외부 수신자**, 결과 언어는 한국어로 선택한다. 필요하면 자문사를 새로 등록한다.
2. `operations/업무메모.md`와 `operations/요청량.csv` 두 파일만 업로드한다. CSV 역할은 **요청량 관찰**이다.
3. 분석 후 중복 입력·수동 대조·기존 채널 유지라는 사실은 공유 대상으로 선택하고, 고객·계약 배경·내부 표식은 제외한다. 실제 카드와 미리보기 내용을 확인한다.
4. 요청량은 먼저 D에서 “첫 관찰=100, 정수 지수만 공개”를 입력하고 해석·미리보기를 확인한 뒤 적용한다. 지원하지 않는 해석이면 임의로 진행하지 않는다.
5. 작성 결과에서 지수 100/141/212와 메일·메신저 유지 조건을 확인한다. 날짜·실제 건수·고객·표식이 남지 않았는지 전체 파일을 확인한다.
6. 요청량을 B 방향 표로 바꾸고 다시 작성한다. 기존 결과가 무효화되고 지수·비율이 사라지는 장면을 보여준다. 본문뿐 아니라 표·첨부도 확인한다.
7. 최종 파일 확인 후 확정하고 다운로드한다. 자문사가 현재 업무와 유지 제약을 이해하고 개선 순서를 제안할 수 있는지 확인한다.

짧게 시연할 때는 D 단계를 생략하고 B로 시작한다. A를 선택하면 관찰 수·순서·수치를 붙이지 않은 증가 사실만 남아야 한다. C는 이번 자료에서 사용자가 승인한 필드와 정확값만 포함해야 한다.

## 공급사 문의

- 목적: **공급사 문의**. 수신자: 지정 공급사. 공개 범위: **지정 외부 수신자**.
- 업로드: `vendor/문의메모.md`, `vendor/요청량.csv`. CSV 역할: **요청량 관찰**.
- 요청량은 B, 추적 ID는 이번 공급사 문의에 한해 정확값을 허용하는 흐름으로 진행한다. 고객·단가·인증 표식은 제외한다.
- 확인할 내용: 첫 응답 대기 timeout, 재시도의 200 응답, 첫 서버 처리·중복·인과관계는 미확인, 승인 ID로 조사와 안전한 재시도 조건 문의.
- “첫 저장 실패”, “중복 없음”, “재시도로 해결”, “요청 증가가 원인”이라는 단정이 나오면 통과로 설명하지 않는다. 재현은 실행 환경 없음으로 미수행이다.
- 기본 화면 시연은 ID 허용 분기로 진행한다. ID 제외 분기는 별도 목표 변경이 필요한 API 검증 항목이며 현재 화면에는 목표 변경 입력이 없다. ID를 제외한 채 공급사 기록을 조회할 수 있다고 설명하지 않는다.

## 오픈소스 제보

- 목적: **오픈소스 버그 제보**. 수신자: 공개 프로젝트. 공개 범위: **전체 공개**.
- 업로드: `oss/장애메모.md` 한 파일. CSV는 없다.
- 공개 버전·입력 계약·오류 단계·ASCII/다중바이트 차이는 허용하고 고객 문자열·내부 경로·사업 정보·인증 표식은 제외한다.
- 재현 환경이 준비됐다면 공개 toy 계약에 따른 새 예시 길이 6으로 buggy/fixed 실행을 확인한다. 원래 고객 문자열을 이름만 바꿔 내보내지 않는다.
- 재현 환경이 없으면 이 사례는 분석·공개 선택까지만 시연한다. 관찰 문의로 완료하려면 별도 목표 변경이 필요한데 현재 화면에는 해당 입력이 없다. 실행하지 않은 결과를 재현 성공이라고 설명하지 않는다.

## 추가 사례: 스트리밍 CSV 오픈소스 제보

[oss-streamcsv/조사메모.md](oss-streamcsv/조사메모.md)를 중심으로 한 가상 StreamCSV-Demo 문의다. 버퍼 경계에서만 실패하는 파서 문제를 다루며 기존 toyrecord 사례와 독립적이다.

- 목적: **오픈소스 버그 제보**. 공개 범위: **전체 공개**. 수신자는 이 가상 프로젝트용으로 등록한다.
- 업로드: `oss-streamcsv/`의 조사메모·실행기록·원본발췌·환경 네 파일만 선택한다. CSV 역할은 반드시 **일반 자료**로 고른다. 원본발췌.csv는 요청량 schema가 아니다.
- 보여줄 판단: 공개 버전·런타임·파서 설정·오류 코드·청크 경계 조건과, 비공개 고객·주문번호·경로·계약액을 구분한다.
- 새 예시를 만들 때 따옴표 안 CRLF와 CR/LF 사이의 청크 경계를 유지해야 한다. 원본 고객명만 치환한 자료를 자동 승인하지 않는다.
- 기대 관찰: 한 청크와 정상 레코드 뒤 분할은 성공으로 기록됐고, 따옴표 안 CR/LF 사이 분할은 오류로 기록됐다. 상태 초기화가 원인이라는 결론, 미실행 버전 비교, 새 최소 예시 재현 성공은 쓰지 않는다.
- 이 가상 프로젝트에는 등록 runner·제품 팩이 없다. 기존 toyrecord runner 결과를 이 사례의 증거로 사용하지 않는다. 현재 화면에서는 분석·공개 선택 시연용으로 사용한다.

## 추가 사례: 배송 웹훅 B2B 기술지원

[b2b-webhook/지원요청메모.md](b2b-webhook/지원요청메모.md)를 중심으로 한 가상 ParcelRelay-Demo 문의다. 응답 전달의 불확실성, 중복 수신, 이벤트 순서 역전을 함께 다룬다.

- 목적: **공급사 문의**. 공개 범위: **지정 외부 수신자**. 수신자는 이 가상 공급사용으로 등록한다.
- 업로드: `b2b-webhook/`의 지원요청메모·수신기록·연동설정·관찰량 네 파일. CSV 역할은 **요청량 관찰**이다.
- 공개 후보: API·수신기 버전, 큐 기록 후 응답 방식, 프록시 timeout 설정, 서명 검증 결과, 중복 제거 미적용, 도착 순서 기반 상태 갱신 방식. 카드와 근거를 확인한 뒤 개별 결정한다.
- 별도 판단: event_id·delivery_id·테넌트·리전·정확한 시각은 해당 공급사 조사에 필요한 범위만 허용한다. 고객·주문번호·계약·엔드포인트·내부 주소·인증 표식은 제외한다. 요청량은 B로 시작한다.
- 기대 관찰: 앱의 204 로그와 프록시의 504 로그를 함께 설명하고 공급사의 수신 결과는 미확인으로 둔다. 동일 event_id의 서로 다른 delivery_id, 발생 시각과 수신 순서의 차이를 유지한다.
- 문의할 내용: 최초 전달 결과·재시도 사유·백오프·중복 제거 키와 보관 기간·순서 보장 범위·상태 병합 방법. 정상 정책인지 결함인지 단정하지 않는다.
- 관찰량은 수신량이며 오류 건수·실패율이 아니다. “트래픽 증가로 공급사가 실패했다”, “서명 유효이므로 순서도 보장된다”는 결론은 근거가 없다. 공급사 환경에서 재현하지 않은 관찰 문의로 진행한다.

## 두 번째 자료에서 기준 재사용

운영 자문의 B 방향 기준을 저장했다면 같은 프로젝트·수신자·목적·범위의 새 작업을 만든다. 원래 업무메모와 `variants/middle-decrease/요청량.csv`만 올린다. 기존 CSV와 변형 CSV를 함께 올리지 않는다. 기대 방향은 감소/증가이며 “계속 증가”가 아니다. 새 작업에서 실제 적용된 기준과 미리보기를 확인한다.

`variants/zero-baseline/요청량.csv`는 실패 처리 시연용이다. 첫 관찰이 0이므로 기준100 지수를 만들 수 없다. 지수가 필요하지 않은 A/B 선택과 구분해 보여준다. 0을 다른 값으로 대체하거나 지수를 임의로 만들면 안 된다.

## 발표할 때 구분할 것

- 안내 파일인 이 README를 원자료와 함께 업로드하지 않는다. 다른 사례·변형도 한 작업에 섞지 않는다.
- 업로드는 공개 승인이 아니다. 실제 카드와 미리보기에서 공개 범위를 결정한다.
- live 모델 호출, fixture 고정 응답, 사람의 편집과 미수행을 구분한다. 현재 입력 묶음으로 live 실행은 아직 검증하지 않았다.
- `CONTEXT_BUDGET_EXCEEDED`의 코드·설정·구조는 이번 자료 준비에서 변경하지 않았다. 이 자료를 해당 문제의 해결책으로 취급하지 않는다.
