# 가상 VendorStore-Lab 지원 문의 메모

모든 이름/ID/고객/수치는 가상이다. 작성자는 공급사 서버나 재현 환경에 접근할 수 없다.

첫 요청에서 클라이언트가 응답을 기다리다가 timeout을 관찰했다. 같은 operation_id와 새 attempt_id로 재시도했고200응답을 받았다. operation_id와 attempt_id는 클라이언트가 보낸 추적 정보이며 공개 제품 계약상 멱등성을 보장하지 않는다.

첫 요청이 서버에서 처리 완료됐는지, 두 요청이 중복 레코드를 만들었는지, 요청량 증가와 timeout에 인과관계가 있는지는 아직 모른다. 재시도 응답만으로 해결됐다고 단정할 수 없다.

request-summary.csv의 count는 각 관찰 시점의 분당 요청량이다. 정확한 수치/분당 단위/시간/간격/payload/주소는 공개 수준을 따로 정해야 한다. connection_log의 문서용 대역 주소는 실제 회사 주소가 아닌 테스트용 가상 값이다. 이 파일에서는 새 설정 예시가 아니라 관찰된 접속 기록의 역할을 한다.

지정 공급사에 ID를 공개하기로 선택하면 해당 요청의 처리 결과와 안전한 재시도 방법을 문의하고 싶다. ID를 공개하지 않는다면 먼저 조사에 필요한 최소 진단 항목을 묻는 문의로 바꾸고 싶다.
