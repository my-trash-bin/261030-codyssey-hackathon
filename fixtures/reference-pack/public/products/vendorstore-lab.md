# VendorStore-Lab / 공개 가상 제품 계약

실제 제품이 아닌 PoC용 공개 자료다. 내부 공급사 처리 기록은 여기에 포함하지 않는다.

- 클라이언트는 저장 요청마다 operation_id와 attempt_id를 보낼 수 있다.
- operation_id는 한 업무의 추적용 값이며 서버의 멱등 처리 보장을 뜻하지 않는다.
- attempt_id는 각각의 전송 시도를 구분한다. 재시도에서는 새 값을 사용한다.
- 클라이언트의 응답 대기 timeout만으로 서버의 저장 실패를 확정할 수 없다.
- 성공 응답을 받은 재시도만으로 최초 처리 결과/중복 여부/원인을 알 수 없다.
- 지원팀에 직접 조회를 요청할 때는 사용자가 허용한 operation_id/attempt_id가 연결 단서가 된다.
- ID를 공개하지 않으면 현재 관찰과 미확인 사항을 설명하고 필요한 최소 추가 진단 항목/안전한 재시도 조건을 질문할 수 있다.
- 생성 설정 예시는 upstreams의 id/address와 route의 upstream_id를 가진다. route는 실제 존재하는 upstream을 참조해야 한다.

첫 PoC에는 이 제품의 서버 재현 환경이 없다. 새 예시 설정에서 문서용 주소를 사용해도 실제 운영 접속 주소의 공개를 자동 허용하지 않는다.
